# adr

## 언제
- 버전, 빌드 구조, 라이브러리 도입이나 제거를 결정했을 때
- 서비스 경계, 통신 방식, SAGA 방식처럼 여러 서비스에 걸친 설계를 정했을 때
- SA 문서와 다르게 구현하기로 했을 때 (사용자 확인 후)
- 여러 대안 중 하나를 고른 이유가 나중에 다시 궁금해질 만할 때

## 절차
1. `docs/decisions/`에서 마지막 번호를 확인하고 다음 번호로 `NNNN-<영문-kebab-slug>.md`를 만든다.
2. `docs/decisions/README.md` 목록에 한 줄을 추가한다.
3. 이전 결정을 뒤집는 경우, 이전 ADR의 상태를 `대체됨 (NNNN)`으로 바꾼다.
4. 결정이 AI 제안에 대한 판단에서 나왔으면 `docs/ai-judgments/`의 해당 기록과 서로 링크한다.
5. 답 끝에 `기록: <경로>`를 남긴다. 팀 결정이 필요한 내용이면 상태를 `제안`으로 두고 PR에서 리뷰받는다.

## 형식
```markdown
# NNNN. <결정 제목>

- 상태: 제안 | 채택 | 대체됨 (NNNN)
- 날짜: YYYY-MM-DD
- 결정자: <이름 또는 팀>
- 관련 AI 판단: <docs/ai-judgments 링크. 없으면 생략>

## 맥락
<왜 결정이 필요했나. 제약, 확인한 사실>

## 결정
<무엇을 하기로 했나>

## 검토한 대안
- <대안>: <채택하지 않은 이유>

## 결과
<얻는 것, 감수하는 것, 후속 작업>
```
