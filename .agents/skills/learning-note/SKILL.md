# learning-note

## 언제
- **질문 노트**: 사용자가 지식이나 방법을 묻는 질문을 했을 때(판단 기준: `docs/agents/learning-guide.md` 2절). 답한 뒤 사용자 동의를 기다리지 않고 저장한다.
- **하루 정리**: 사용자가 하루 작업을 마칠 때. 에이전트가 답 끝에 한 줄로 제안하고, 사용자가 원하면 쓴다.

`<이름>`은 팀원 영문 이름이다(예: junhyun). `git config user.name`이나 대화로 알 수 없으면 사용자에게 묻는다. 폴더가 없으면 `README.md`와 함께 만들고 `docs/learning/README.md` 표에 추가한다.

## 질문 노트 절차
1. 채팅에서 핵심 답을 짧게 먼저 준다.
2. `docs/learning/<이름>/qna/`에서 같은 주제의 노트를 찾는다. 있으면 그 노트를 보강하고 `updated`를 갱신한다.
3. 없으면 `docs/learning/<이름>/qna/YYYY-MM-DD-<영문-kebab-slug>.md`를 만든다. 날짜는 질문한 날이다.
4. `docs/learning/<이름>/README.md` 표에 한 줄을 추가하거나 갱신한다. 최신 노트가 위로 오게 한다.
5. 답을 들은 사용자가 AI 답을 수용·거부했다면 `ai-judgment`도 함께 쓴다.
6. 채팅 마지막 줄에 `기록: <경로>`를 남긴다.

## 노트 형식
```markdown
---
title: <질문을 한 문장 제목으로>
date: YYYY-MM-DD
updated: YYYY-MM-DD
asker: <git config user.name>
level: 기초 | 중급 | 고급
tags: [kafka, redis, ...]
---

# <title>

## 질문
<사용자 질문 원문. 필요하면 맥락을 한 줄 덧붙인다>

## 짧은 답
<3~5줄 결론>

## 자세히
<원리, 동작 방식, 대안 비교. 코드 예시>

## 이 프로젝트에서는
<실제 파일 경로와 적용 방식. 없으면 생략>

## 면접 포인트
- <예상 질문과 답변 요지>

## 참고
- <공식 문서, 확인한 실행 결과>
```

## 하루 정리
1. 자료를 모은다: 오늘 커밋(`git log --since=midnight --author="$(git config user.name)" --stat`), 이 대화에서 다룬 질문·구현, 오늘 쓴 AI 판단 기록. 이미 노트로 남긴 내용은 다시 쓰지 않고 링크한다.
2. `docs/learning/<이름>/daily/YYYY-MM-DD.md`를 만든다.
   ```markdown
   # YYYY-MM-DD
   ## 오늘 한 일
   ## 배운 것
   - **{개념}**: 한두 줄 설명 — 관련 문서
   ## 오늘 내린 AI 판단
   - <docs/ai-judgments 링크와 한 줄 요약>
   ## 헷갈렸던 것, 아직 모르는 것
   ## 다음에 할 일
   ```
3. 사용자가 실제로 다룬 내용만 쓴다. 다루지 않은 개념을 채워 넣지 않는다.
4. 답 끝에 `기록: <경로>`를 남긴다.

## 규칙
- 대화 맥락 없이 독립적으로 읽히게 쓴다. 블로그 초안으로 옮겨 쓸 수 있어야 한다.
- 한국어 평서체로 쓴다. 이모지와 AI 말투를 쓰지 않는다.
- 버전에 따라 달라지는 내용은 버전과 근거를 적는다.
