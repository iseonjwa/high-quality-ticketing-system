# troubleshooting: 문제 해결 기록

같은 문제를 팀원이 다시 겪지 않게 남긴다. 발제의 트러블슈팅 정리(11/16~18)와 발표 자료의 원천이다.

## 언제
- 에러나 예상과 다른 동작을 재현하고 원인을 찾아 해결했을 때
- 원인은 못 찾았지만 우회 방법을 찾았을 때("원인: 미확인")

## 절차
1. `docs/troubleshooting.md`에서 같은 증상의 항목이 있는지 찾는다. 있으면 그 항목에 해결 방법이나 관련 커밋을 보탠다.
2. 없으면 맨 아래에 다음 번호로 추가한다.
   ```
   ### TS-{번호} {한 줄 증상}
   - 서비스·작성: {서비스} / {이름} / YYYY-MM-DD
   - 문제: 무엇이 어떻게 실패했나(에러 메시지, 재현 조건)
   - 원인: 왜 그랬나
   - 해결: 무엇을 바꿨나(관련 파일, 커밋)
   - AI 활용: (선택) AI 제안을 어떻게 판단했나. 개별 판단 기록이 있으면 링크
   - 배운 점: (선택) 다음에 같은 실수를 피하려면
   ```
3. 답 끝에 `기록: docs/troubleshooting.md TS-{번호}`를 남긴다. 사용자 동의를 기다리지 않는다.

## 규칙
- 확인한 사실만 쓴다. 원인을 확인하지 못했으면 "원인: 미확인"으로 쓰고 추측을 사실처럼 쓰지 않는다.
- 에러 메시지는 핵심 줄만 그대로 옮긴다. 비밀값과 토큰은 지운다.
