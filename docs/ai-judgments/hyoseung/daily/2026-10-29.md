# 2026-10-29 hyoseung AI 판단 일지

- [선택] AI가 낸 엔티티 연관관계 두 안(객체 참조 `@ManyToOne` / ID만 보관) 중 객체 참조를 골랐다. AI는 같은 모듈 안에서는 객체 참조, 모듈 경계를 넘으면 ID 참조를 덧붙였다 — 근거: "N쪽에서 1은 fetch join을 하면 추가쿼리가 안나가는데 id만 있으면 무조건 조회하는 쿼리를 따로 날려야 하잖아" (Claude Code)
- [선택] 상태·등급 값을 문자열 대신 Java enum + `@Enumerated(EnumType.STRING)`으로 두기로 했다 — 근거: "enum으로 하고 @Enumerated로 하면 String으로 저장되지 않나? 그래서 enum이 나은 것 같은데" (Claude Code)
- [결정 전달] AI가 초안을 쓴 권우 님 확인 메시지 세 가지(`schedule_seats.status` 값 AVAILABLE·HELD·SOLD와 선점 UPDATE는 권우 님 쪽, Flyway 버전 날짜 기반, `Money`를 두 모듈이 쓰는 공유 위치로 이동)를 권우 님이 받아들였다. ISE-10 엔티티는 임시라 ISE-63에서 `Money`를 공유 위치에 만든다 — 근거: "임시로 엔티티 관련만 딸깍 해둔거라 그렇게 해도 괜찮을 거 같아요" (Claude Code)
- [수용] 준현 님 결제 계약(contracts.md 4절) 7개 항목에 AI가 낸 답장 초안대로 "모두 그대로"라고 ISE-22에 답했다 — 근거: 미기재 (Claude Code)
- [선택] AI가 낸 "venue_seats DDL을 직접 써 보고 리뷰받기" 대신, AI가 `V20261029_1__concert_tables.sql` 전체를 쓰고 사용자가 따라 치며 이해하는 방식으로 바꿨다. 엔티티도 같은 방식으로 진행한다 — 근거: "db를 잘 몰라서 필드들 설정해주고 싶은데 잘 못하겠네. 너가 만들어주고 내가 따라 쳐보며 이해하는 식으로 할게" (Claude Code)
- [수용] reservation-service `application.yml`에 직접 넣었던 `spring.jpa.hibernate.ddl-auto: validate`를 AI 제안대로 지웠다. 같은 설정이 `config-repo/application.yml`에 이미 있어 두 곳을 맞춰 관리할 필요가 없다 — 근거: 미기재 (Claude Code)
- [부분 수용] AI가 낸 "학습·판단 기록 커밋 + 기능 커밋" 2개 구성 중 기록 커밋은 빼고, ISE-63 PR에는 스키마·엔티티·테스트만 올리기로 했다. 기록은 로컬에 두고 나중에 따로 올린다 — 근거: "내 학습 기록은 지금 안 올리고" (Claude Code)
