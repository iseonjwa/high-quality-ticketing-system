# 2026-10-30 hyoseung AI 판단 일지

- [수용] AI가 빠뜨렸다고 짚은 soft delete 기본 필터를 공연장·공연·회차 엔티티에 `@SQLRestriction("deleted_at IS NULL")`로 걸었다. 따로 막는 계약이 없으니 SA 12-1대로 추가한다 — 근거: "따로 걸지말라는 계약 없으면 추가하면 되지않나?" (Claude Code)
- [선택] AI가 알린 SA 안의 불일치(12-1 "상태 VARCHAR(20)" / 12-3 표 `status VARCHAR(10)`) 중 12-3 표대로 10을 유지했다 — 근거: "status 길이는 10으로 핏하게 하고" (Claude Code)
- [수용] AI가 시드 점검에서 알린 `row_no` VARCHAR 정렬 문제(1, 10, 2…)를 보고 열 번호를 INT로 바꾸기로 했다. 머지된 V20261029_1은 고치지 않고 새 마이그레이션으로 바꾸고 SA·응답 예시까지 맞춘다(ADR 0033) — 근거: "몇 열, 몇 번째 좌석은 숫자여야 하는데 VARCHAR로 돼있다? 이건 아주 큰 설계 오류네" (Claude Code)
- [거부] AI가 기존 코드 모양(BaseEntity·결제 서비스)을 따라 공연 엔티티에 손으로 쓴 getter, `protected` 기본 생성자, 기본 이름 규칙과 같은 `@Column(name = ...)`을 쓰지 않고 Lombok `@Getter`·`@NoArgsConstructor(access = AccessLevel.PROTECTED)`와 Spring Boot 기본 이름 변환(camelCase → snake_case)을 쓰기로 했다. Lombok은 팀 결정 D13으로 허용됐고 내 엔티티라 code-style 8절("기존 코드는 일부러 바꾸지 않는다")에 걸리지 않는다. 공통 모듈 BaseEntity와 다른 서비스 코드는 그대로 둔다 — 근거: "@Getter로 저거 다 바꿔도 되는 거 아닌가?" "너가 어노테이션을 적극적으로 활용하지 않은 이유가 있을까?" (Claude Code)
