# 2026-11-05 hyoseung AI 판단 일지

- [부분 수용] AI가 오늘 할 일로 "ISE-62 정리 → 예매 한 건 흘려 보기 → k6 기준선 → 캐싱 설계 시작"을 제안했다. 캐싱 설계는 빼고, 급한 일이 없으니 하루를 MVP 흐름 이해와 측정에만 쓰기로 했다. 순서는 흐름을 먼저 이해한 뒤 측정이다.
  - 근거: "캐싱 설계는 뺐어. 오늘은 오늘 안에 할 게 없어서 MVP 이해와 측정에만 온전히 시간을 보내도 될 거 같은데 맞니? 맞다면 흐름부터 온전히 이해하고 측정해보자." (Claude Code)
- [수용] AI가 오늘 k6 측정 대상을 공연 목록에서 좌석 조회(ISE-189 대상)로 바꾸자고 제안했다. 받아들이고 개선 전·P4a·P4b·P4c를 차례로 재기로 했다. 공연 목록은 고칠 거리가 뚜렷하지 않다고 봤다.
  - 근거: "원래 공연 목록 하려고 했다는데 이거는 뭔가 의미가 없어보인다? ... 이 좌석 조회는 딱이네. ... 개선 전, 첫 번째 개선, 두 번째 개선 이렇게 재보면 좋겠다 그치?" (Claude Code)
- **[거부]** AI가 팀 공지(k6는 Docker 이미지로 실행)를 이유로 묻지 않고 k6 설치 대신 Docker 이미지를 쓰고, 기준선 측정 스크립트를 직접 만들어 대신 돌렸다. 처음 합의대로 k6를 직접 설치해 사용자가 직접 실행하기로 했고, 돌던 측정은 중지했다.
  - 근거: "아니 k6 직접 설치해서 하기로 했잖아. k6가 뭔지도 모르는데 직접 설치해서 해봐야지;" (Claude Code)
- [거부] AI가 권우 님 ISE-181 브랜치와 Grafana 변경을 나열만 하고 "dev를 받을지는 사용자가 정한다"고 넘겼다. 팀 분담과 지금 할 일이 빠졌고 최신 dev는 당연히 받아야 한다고 지적했다. dev를 받고, 분담표(open-peak-load-plan.md 7절) 기준으로 효승 몫(Z2·Z6·Z9)과 할 일 순서(k6 설치 → K1으로 개선 전 측정 → P4a 구현 → 재측정·PR → ISE-189 일정 답)를 정리했다.
  - 근거: "팀원별로 지금 무엇을 맡고 있는지부터 알려 줘. 최신 dev는 당연히 받아야 하고, 그 위에서 내가 지금 할 일을 정리해 줘." (Claude Code, 말투 다듬음)
- [부분 수용] AI가 좌석 조회 측정은 최권우 K1 스크립트를 그대로 쓰자고 제안했다. 비교용으로 K1도 쓰되, 남이 만든 것만 돌리면 어떻게 굴러가는지 모르므로 좌석 조회 측정 스크립트를 처음부터 같이 단계별로 만들기로 했다. 이강민도 권우 방식과 다른 방식을 함께 해 보고 있다는 점을 근거로 들었다.
  - 근거: "권우님 방식과 다른 방법을 함께 해 보는 분도 있으니 우리 방식으로도 해 보자. 완성된 스크립트를 돌리기만 하면 어떻게 동작하는지 알기 어려우니 처음부터 같이 만들어 보자." (Claude Code, 말투 다듬음)
- [부분 수용] AI가 다음 단계로 좌석 조회를 1명이 부르는 스크립트(토큰 준비 흐름)를 제안했다. 한 명씩 부르는 확인보다 API마다 실제 부하를 걸어 보는 것을 먼저 하기로 했고, 이미 돌려 본 공연 상세부터 초당 요청 수를 단계적으로 올리는 부하 스크립트로 바꿨다.
  - 근거: "하나씩 하는 게 아니라 부하테스트니까 부하테스트를 각각 해봐야지" (Claude Code)
