# 브랜치 리뷰 후속 수정 방향 선택

## 맥락
- 해결하려던 작업: ISE-5 브랜치의 구현 상태·커밋 구성·문서를 AI에게 리뷰받고 수정 방향을 정했다.
- AI 활용 방식: 현재 브랜치 구현 상황, 커밋 분할, 구현 지식의 문서화를 점검해 달라고 요청했다.

## AI 제안
- 커밋이 하나도 없으니 10개로 나눠 커밋한다.
- Gateway와 서비스에 복사된 JWT 검증 계약과 공개·관리자 경로 판정을 공유 상수·공통 테스트로 맞춘다.
- Gateway 요청마다 정규식·목록을 만드는 부분을 `static final`로 뺀다.
- 로그인에 응답 시간 차이와 횟수 제한이 없는 점을 후속 과제로 남기거나 구현한다.
- 내부 신뢰 모델(HS256 공유 비밀, 헤더 신뢰, Redis 무인증)을 한곳에 문서화한다.
- 작업 이력이 섞인 `workspace.md`를 정리하고 낡은 `common-foundation.md`를 정리하며 ADR을 보충한다.

## 판단
- 결과: 부분 수용
- 판단자: Junhyun An
- 근거: 경로 판정에 대해 "왜 둘로 나뉘었는지 모르겠지만, 게이트웨이쪽에서 하나의 메서드로 처리하게 해줘". 나머지는 별도 이유 미기재.
- 사용자 원문: "커밋은 너가 제안한대로 해주고, 코드에서 볼 점도 고쳐줘. 계약중복을 없애주고, 경로판정도 일원화해줘. … 모든 코드 스타일은 읽기 쉬운 형태로 해줘. pony-tail 스킬을 참고해줘. / 게이트웨이 요청도 static final 보다 더 최적화 할 수 있으면 그 방향으로 해주고, 로그인 보안도 달아줘. 로그인 횟수 제한도 5회로 해주고, 로그인 성공시 횟수초기화, 관리자가 비밀번호 초기화 하는 로직도 제대로 구현해야하고. 내부 신뢰모델은 좀 제대로 설계할 필요가 있겠다. 일단 진행하고, 인증 설계와 신뢰모델은 그거 이후에 바로 설계하자."
- 수용: 10개 커밋 분할, 계약 중복 제거, 코드 스타일 정리
- 변경: 경로 판정은 AI의 "공유 상수·테스트"가 아니라 Gateway 한 메서드로 일원화. `static final`보다 더 나은 최적화 요구. 로그인 보안은 후속 과제가 아니라 5회 제한·성공 시 초기화·관리자 초기화로 확장
- 보류: 내부 신뢰 모델과 인증 설계는 이번 수정 뒤 따로 설계한다.

## 반영
- 기준선 커밋 9개와 수정 커밋 3개(Gateway 정책·common-auth, 로그인 잠금·초기화, 스타일 정리)로 나눠 반영했다. 문서는 가이드·ADR·판단 기록·트러블슈팅으로 나눠 커밋한다.
- [ADR 0006](../../decisions/0006-gateway-single-access-policy.md), [ADR 0007](../../decisions/0007-login-lockout-admin-reset.md), [워크스페이스 가이드](../../guides/workspace.md), [공통 모듈 가이드](../../guides/common-modules.md).

## 검증
`./gradlew clean build`의 모듈 테스트와 PostgreSQL·Redis 통합 테스트가 통과했다. Compose 스택을 다시 빌드해 `smoke-workspace.py --redis-failure`의 HTTP 계약 54건(로그인 잠금·관리자 초기화·임시 비밀번호 변경 포함)과 Config·Eureka·Kafka·관측성 확인이 통과했다. 이 환경에서 Zipkin 컨테이너가 unhealthy여서 재시작한 뒤 확인했다.

## 판단 이력
- 2026-10-27 부분 수용: 리뷰 제안 중 경로 판정 방식과 로그인 보안 범위를 사용자가 바꾸고, 신뢰 모델 설계는 보류
- 2026-10-27 보류 해제: 서비스 단독 방어가 약해진 것을 인지한 채로 내부 신뢰 모델과 인증 설계를 진행하기로 했다. 같은 시점에 dev의 SA MASTER v3.1을 병합했다. 설계는 [ADR 0008](../../decisions/0008-internal-trust-and-auth-design.md)

## 발표·면접 포인트
- 인증 판정이 두 곳에 흩어져 있던 것을 리뷰로 발견하고, 어긋남을 맞추는 대신 판정 지점을 하나로 줄이는 쪽을 선택했다. 서비스 단독 방어를 잃는 대가는 신뢰 모델 설계의 입력으로 남겼다.
