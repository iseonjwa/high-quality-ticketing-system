# D1에서 서비스가 사용자 JWT를 직접 검증하는 C 선택

## 맥락

- 해결하려던 작업: MSA 서비스가 Gateway의 사용자 헤더를 신뢰하는 구조에서 신원 전달 방법을 비교했다.
- AI 활용 방식: 사용자 JWT 직접 검증과 Gateway 내부 토큰을 비교하고, 이중 검증의 비용·보안 절충을 설명해 달라고 요청했다.

## AI 제안

Codex는 서비스가 User 발급 Access JWT를 직접 검증하는 C와 비대칭 서명을 제안했다. 후속 비교에서는 이중 검증이 필수 조건은 아니며 내부 신뢰 범위와 비용에 따라 기존 Gateway 집중 방식도 선택할 수 있다고 설명했다.
설명은 [D1 학습 노트](../../learning/junhyun/qna/2026-10-27-msa-service-identity-verification.md)에 남겼다. D2의 서명 알고리즘 선택은 별개다.

추가 기술 검토: 사용자 헤더만 신뢰하지 않고 검증한 JWT에서 신원을 구성하면 Gateway 우회와 내부 헤더 위조에 대비한다는 근거가 성립한다.
Gateway에 대한 신뢰 축소는 범위를 구분해야 한다. HS256에서는 Gateway도 토큰을 만들 키를 가지며, User만 개인키를 가진 RS256에서 발급 권한을 더 분리할 수 있다.
RS256도 Gateway가 관찰한 유효 토큰의 재사용이나 Gateway에만 둔 정책 생략을 모두 막지는 않는다. 이는 설계의 조건과 한계를 검토한 설명이며 실행 검증 결과가 아니다.

## 판단

- 결과: 수용. D1의 C 선택에 한정한다.
- 판단자: Junhyun An
- 사용자 원문: "일단 C로 했는데, D2: Access 토큰 서명 방식은요? … 이것들 차이도 알려줘"
- 근거 (사용자의 선택 의도): 헤더 위조를 막고 Gateway를 전적으로 신뢰하지 않음으로써 보안을 보강하기 위해서다.
- 근거 원문: "헤더 위조를 막고, 게이트웨이를 전적으로 신뢰하지 않음으로서 보안을 보강하기 위해서"
- 검토한 대안: Gateway가 서명한 내부 신원(B), Gateway만 검증하고 일반 헤더를 전달하는 기존 방식(A).
- D2 상태: HS256·RS256 설명 요청만 확인했다. 선택지 커서를 최종 선택으로 보지 않는다.
- 팀 합의 상태: 미확인. 개인 선택을 팀 확정으로 기록하지 않는다.

## 반영

[ADR 0009](../../decisions/0009-service-access-jwt-verification.md)를 제안 상태로 작성하고 [ADR 0008](../../decisions/0008-internal-trust-and-auth-design.md)에 D1 선택을 연결했다.
이 질문에서는 인증 코드, 키, SA MASTER 또는 Notion을 변경하지 않았다.

## 검증

로컬 소스를 확인한 시점에 `GatewayIdentityFilter`는 `X-User-*`를 요청 속성으로 옮기고, `TokenDecoders`와 `JwtTokens`는 HS256을 사용했다.
선택 사실과 기존 구현을 구분해 기록했다. C의 구현·실행 검증은 이 대화에서 수행하지 않았다.

## 판단 이력

- 2026-10-27 수용: 사용자가 D1의 C 선택을 전달했다. D2는 비교 중이다.
- 2026-10-27 근거 보완: 선택을 처음 전달할 때는 이유가 미기재였다. 후속 답변에서 헤더 위조 방지와 Gateway에 대한 전적인 신뢰를 줄이는 것을 선택 근거로 밝혔다.
- 2026-10-27 근거 검토 요청: 사용자가 "근데 맞는 근거야? 그냥 그렇게 생각했을 뿐인데"라고 물었다. 선택 의도와 AI의 기술 검토를 구분해 보완했다.

- 2026-10-27 철회: 같은 날 사용자가 SA 7-2·7-3 유지로 되돌렸다. 근거는 "비대칭 서명은 MVP이후로 미루는 게 맞는 것같다". 이 기록은 고민 과정으로 보존한다([철회 기록](2026-10-27-auth-trust-follow-sa.md)).

## 발표·면접 포인트

- 서비스가 신원을 믿는 방법(D1)과 검증 키 보유자가 발급 능력도 가지는지(D2)를 나누어 비교한다.
- 사용자가 말한 선택 의도를 보존하고, 기술적 성립 조건과 방어 한계는 AI 제안·학습 노트에 구분해 남긴다.
