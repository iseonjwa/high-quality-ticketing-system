# AI가 만든 좌석 선택 샘플과 디자인 시스템 초안(이선좌 워드마크, 인디고, 검정+체크 선택 좌석)을 그대로 확정

## 맥락
- 해결하려던 작업: ISE-106 디자인 시스템 설계. 구현(ISE-111) 전에 토큰, 좌석 상태, 컴포넌트, 화면 상태를 정한다.
- AI 활용 방식: "디자인 시스템 설계로 넘어가자. 샘플 페이지 하나 만들어줘"라고 요청했다. Claude Code가 SA·예매 계약을 확인하고, 좌석 선택 화면 HTML 샘플과 디자인 시스템 문서 초안을 만들었다. headless Chrome으로 여섯 상태를 렌더링해 확인했다.

## AI 제안
- 좌석 선택 화면을 샘플로 골랐다. 좌석 상태색, 매수 선택, 남은 시간, 선택 요약, 409 안내가 한 화면에 모이기 때문이다.
- API 계약에서 화면 규칙을 끌어냈다.
  - 좌석 조회가 `available`만 주므로 "선택할 수 없음" 한 상태로 그린다
  - 409가 어느 좌석인지 알려 주지 않으므로, 다시 조회해 빠진 좌석만 풀고 나머지는 유지한다
  - 좌석이 바뀌면 새 멱등키를 쓴다
  - 결제 가능 시간은 결제 토큰 기준 4분 50초로 보인다
- 방향 다섯 가지를 초안으로 냈다: "이선좌" 워드마크, 인디고 `#3B3BD4`, 선택 좌석은 검정 + 체크, 다크 모드 없음, 화면마다 HTML 샘플을 먼저 만드는 방식.
- 상세: [`docs/design/frontend/design-system.md`](../../design/frontend/design-system.md), [`samples/seat-selection.html`](../../design/frontend/samples/seat-selection.html)

## 발표·면접 포인트
- 화면 규칙을 백엔드 계약에서 끌어냈다. 409가 겹친 좌석을 알려 주지 않으니 다시 조회해 빠진 좌석만 풀고, 좌석이 바뀌면 새 멱등키를 쓴다. 결제 가능 시간도 선점 시간이 아니라 결제 토큰 만료 기준으로 보인다.
