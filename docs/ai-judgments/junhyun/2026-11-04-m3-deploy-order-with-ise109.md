# M3 배포 작업 순서를 받아들이고, 프론트 nginx(ISE-109)를 M4에서 M3로 당겨 이미지 워크플로(ISE-173)와 함께 함

## 맥락
- 해결하려던 작업: AWS 계정에 키 페어와 보안 그룹까지 만든 뒤, M3 마감(11/11)까지 배포를 끝내는 순서 정하기.
- AI 활용 방식: "이제 다음 뭐하지?"라고 물었다.

## AI 제안
- 순서: 11/4 ISE-173(이미지 워크플로)과 ISE-178(Loki·Alloy) → 11/5 ISE-176(로컬 부하 중 메모리 측정, 크기 결정) → 11/6~7 ISE-174(배포 compose, 배포 EC2)·ISE-177(배포 DB 시드, 샘플 계정) → 11/8~9 ISE-175(Jenkins) → 11/10 리허설.
- 이유: EC2는 켜는 순간부터 과금되므로 가능한 늦게 만든다. ISE-176의 측정 범위에 관측 구성이 들어 있어 Loki를 먼저 붙인다.
- ISE-109(프론트 nginx 컨테이너)는 M4로 잡혀 있지만, 배포 서버에서 화면을 띄우려면 필요하고 ISE-173 범위에도 프론트 nginx 이미지가 있다. 그래서 M3로 당겨 ISE-173과 함께 하자고 했다. 함께 하면 공개 진입점이 nginx 포트가 되어 배포 보안 그룹 규칙이 바뀌고, 팀원 로컬 compose에 프론트 빌드가 더해진다.

- 검토한 대안: ISE-109를 M4에 그대로 두기(배포 서버에서 화면을 띄울 수 없어 시연을 로컬 화면으로 해야 한다)

## 반영
- Linear ISE-109의 마일스톤을 M3로 옮겼다.
- 워크플로 설명은 워크플로 파일 주석과 저장소 문서에 남긴다(사용자 요청).
