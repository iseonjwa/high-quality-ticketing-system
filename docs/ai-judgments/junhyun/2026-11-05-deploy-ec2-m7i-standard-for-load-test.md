# 부하 테스트에 대비해 배포 EC2를 flex(m7i-flex.xlarge)에서 같은 크기의 일반 인스턴스(m7i.xlarge)로 바꿈

## 맥락
- 해결하려던 작업: 배포 서버에서 부하 테스트(ISE-176·181)를 하기 전에 CPU 성능 조건을 고정하기.
  - 11/4에는 크레딧 버스트형(`t3.xlarge`)을 피하려고 `m7i-flex.xlarge`를 골랐다(`docs/learning/junhyun/qna/2026-11-04-deploy-cost-and-single-host-db.md` 1절).
- AI 활용 방식: 사용자가 "인스턴스 부하테스트때문에 flex 인스턴스에서 일반 인스턴스로 바꾸려는데, 그냥 내리고 다시 올리면 되나?"라고 물었다.

## AI 제안
- 순서는 중지 → 인스턴스 유형 변경 → 시작이다.
  - 종료(Terminate)는 루트 디스크까지 지워 DB 데이터와 `.env`가 사라지므로 쓰지 않는다.
- 같은 4 vCPU·16GiB의 일반 인스턴스는 `m7i.xlarge`다.
  - 같은 Nitro·Intel x86_64 계열이라 이미지를 그대로 쓴다.
- 중지·시작해도 이 프로젝트에서는 그대로다.
  - 탄력적 IP, 사설 IP(`DEPLOY_HOST`), EBS 데이터가 남는다.
  - 컨테이너는 `restart: unless-stopped`로 다시 뜬다.
- 부하 측정에는 성능이 고정된 일반 인스턴스가 측정값을 설명하기 쉽다.
  - flex는 vCPU당 40% 기준 성능에 "대부분의 시간" 최대 성능이다.
  - AWS도 지속적인 고CPU 작업에는 M7i를 권한다.
- 요금은 시드니 기준 시간당 0.2394달러에서 0.252달러로 약 5% 오른다(AWS 가격 데이터).
- 릴리스·Jenkins 배포가 돌지 않을 때 바꾸고, 바꾼 뒤 배포 문서와 요금 계산을 고친다.

- `docs/design/infra/deployment.md` 첫 배포 기록과 7절 결정 표에 `m7i.xlarge`를 적었다.

## 발표·면접 포인트
- 성능 측정 대상은 성능이 고정된 인스턴스로 맞춘다. 버스트형이나 flex는 CPU 성능을 조건부로 주므로 같은 테스트도 결과가 흔들릴 수 있다.
- 수직 확장(인스턴스 유형 변경)은 중지 → 변경 → 시작이라 중단이 따른다. 그래서 서버가 이미 멈춰 있던 시간에 바꿨다.
