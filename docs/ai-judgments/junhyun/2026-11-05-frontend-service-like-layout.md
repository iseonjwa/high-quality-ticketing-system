# 핵심 흐름만 보이던 AI의 화면 구성을 실제 서비스형 레이아웃·그림 에셋으로 바꾸게 함

## 맥락
- 해결하려던 작업: 머지된 프론트(ISE-115~124)를 프로덕션 빌드로 띄워 직접 확인했다.
- AI 활용 방식: 디자인 시스템(ISE-106·111)과 화면(ISE-112~124)을 Claude Code가 설계·구현했다. 원칙은 "지금 상태와 다음 행동이 먼저 보인다"였다(design-system.md 1절).

## AI 제안
- 모든 화면을 같은 카드 목록 배치로 만들었다. 공연 이미지가 API에 없어 포스터 자리는 색 면으로 두었다.
- 시연 흐름(공연 → 대기열 → 좌석 → 결제 → 결과)을 정확히 보이는 데 집중했다.

## 판단
- 결과: 부분 수용(흐름·상태 규칙은 그대로, 레이아웃과 에셋은 바꿈)
- 판단자: Junhyun An
- 근거: "프론트 좀 더 실제 서비스처럼 고쳐줄래? 지금은 핵심 흐름을 보여주는데만 집중하고 있는데, 좀 더 다양한 레이아웃을 사용해도 될 것 같아. 에셋들도 실제처럼 했으면 좋겠어", "지금부터 하는 작업들은 배포환경도 고려해줘"
- 검토한 대안
  - 사진 에셋: 외부 사진 서비스의 이미지를 내려받는 방법. 저작권·초상권 확인이 필요하고 외부 서버에 기대게 돼 고르지 않았다.
  - 직접 그린 그림(채택): 캔버스로 그린 원본 8종을 저장소에서 다시 만들 수 있게 두었다.

## 반영
- ISE-187: 헤더 메뉴·로고·사이트 아래 정보, 홈(대표 배너, 티켓 오픈 달력, 포스터 격자, 추첨 안내 띠), 공연 상세(흐린 그림 배경 배너, 회차 선택 예매 패널, 공연 정보·예매 안내 탭), 그림 생성기(`frontend/tools/concert-art/`)와 WebP 에셋.
- 디자인 문서: `docs/design/frontend/design-system.md` 10절, `docs/design/frontend/README.md` "서비스형 홈·공연 상세 규칙".
- 남은 화면(내 예매, 내 정보, 추첨, 인증, 운영자)은 후속 이슈로 이어서 바꾼다.

## 검증
- 이 브랜치로 만든 프로덕션 nginx 이미지에서 확인했다. 그림은 `image/webp`·1년 immutable 캐시로 내려오고, 홈 그림은 174KB(1280px), 컨테이너 메모리는 10.3MiB다.
- 로컬 compose 백엔드로 홈·공연 상세를 1280px·375px에서 확인했고 가로 넘침이 없었다.

## 판단 이력
- 2026-11-05 부분 수용: 흐름과 상태 규칙은 두고 레이아웃·에셋을 실제 서비스형으로 바꿈

## 발표·면접 포인트
- 백엔드에 없는 데이터(이미지, 장르, 가격)는 꾸며 내지 않고, 있는 데이터(다음 회차 시각, 회차 목록)로 묶음과 배치를 다양하게 만들었다.
- 에셋을 번들에 넣어 배포 서버가 외부 이미지 서버에 기대지 않게 했다.
