# 오류 응답이 Accept에 따라 비는 결함을 상담 서비스 안이 아니라 공통 예외 처리기에서 고치기로 함

## 맥락
- 해결하려던 작업: 내부 AI 상담(ISE-126, #404)의 스트리밍 답변 화면을 만들던 세션이 셀프 리뷰를 돌렸다. 그 리뷰가 SSE 엔드포인트의 오류 응답 결함을 재현했다. assistant-service를 따로 띄우고 curl로 확인했다.
  - `Accept: text/event-stream`만 보내면 400이 빈 본문으로 온다.
  - 429는 500 + 빈 본문 + ERROR 로그로 온다.
- AI 활용 방식: 머지 세션이 원인 위치를 코드에서 확인하고, 고칠 위치 두 안을 사용자에게 물었다.

## AI 제안
- 원인: 공통 예외 처리기(`CommonExceptionHandler`)와 상담 컨트롤러의 429 처리기가 Content-Type을 정하지 않는다. 그래서 Spring이 요청 Accept로 응답 형식을 고르는데, JSON 변환기가 `text/event-stream`과 맞지 않아 `HttpMediaTypeNotAcceptableException`이 난다. 응답에 Content-Type을 미리 정하면 Spring은 Accept 협상을 건너뛴다.
- 1안(추천): common에서 고친다.
  - 공통 처리기의 오류 응답 다섯 곳에 JSON Content-Type을 붙인다.
  - 모든 서비스의 모든 오류 경로(400·401·415·429·500)가 함께 고쳐진다.
  - 공유 코드라 contract 이슈로 팀에 알린다. 동작은 Accept에 JSON이 없을 때만 달라진다.
- 2안: 상담 서비스 안에서만 고친다. 공통 처리기를 상속한 전용 처리기로 Content-Type만 덧붙인다. 팀 알림은 필요 없지만 다른 서비스에는 같은 문제가 남는다.
- 처음에 후속 PR 시점을 물을 때는 2안에 가까운 설명("assistant 안에서 고친다")을 붙였다. 그 뒤 공통 처리기 코드를 읽고, 공통 쪽 수정이 몇 줄이고 모든 오류 경로를 덮는다는 것을 확인해 1안을 다시 제안했다.
