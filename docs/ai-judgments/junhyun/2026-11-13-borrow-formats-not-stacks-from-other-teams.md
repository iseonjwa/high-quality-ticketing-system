# 다른 조 저장소에서 스택과 결정이 아니라 형식과 판단 방식만 가져오기로 하고, 바로 할 것 두 가지와 전체 적용 설계·CodeRabbit 적용까지 맡김

## 맥락
- 해결하려던 작업: 다른 조 저장소 5곳(ITDA, commerce-settle, 4조, Good-Ticket, travelpay)에서 우리 프로젝트에 적용할 만한 좋은 점을 뽑는 일.
- AI 활용 방식: 저장소마다 하위 에이전트 하나가 같은 질문(발제 필수 산출물을 어떻게 보였나, 테스트·CI·리뷰, 측정 방법, 따라 하면 안 되는 것)으로 읽었다. 메인이 결과를 주제별로 묶고, 핵심 근거(ArchUnit 파일, 동시성 리뷰 체크리스트, k6 합격 조건, ITDA PR #258 수치, travelpay의 "도입하지 않은 것"·"알려진 한계" 절)를 원문으로 다시 확인했다. 정리는 `docs/learning/junhyun/qna/2026-11-13-other-teams-repos-lessons.md`.

## AI 제안
가져올 것 일곱 가지(판정 기준 사전 고정, 전/후 표에 원인·대가·환경·한계, 실패 시나리오 표, 도입하지 않은 것·알려진 한계 표, ArchUnit 계층 규칙, AI 리뷰 보강, CI 중복 실행 취소와 Synthetic CSV 재생성 테스트)와 따라 하지 말 것(Kafka·SAGA를 빼는 선택, 거대 단일 문서, 봇 리뷰 건수 내세우기, 다른 팀 기준값 그대로)을 냈다. 바로 할 수 있는 두 가지로 (1) 제 PR에 반영할 것 네 개, (2) 팀원 이슈에 해당 항목 댓글을 제안했다.

## 판단
- 결과: 수용
- 판단자: Junhyun An
- 근거: "저런 스택과 결정을 따라하는게 아니라, 저런 형식과 판단 방식을 가져오는게 좋다! 두가지 반영해주고. 가져올것 전부 추가로 적용하는 방안 설계까지 해줘!" 이어서 "코드래빗을 적용할 생각도 있어."
- 검토한 대안: 다른 팀의 기술 선택(Kafka 없이 원장 한 트랜잭션, ECS·Terraform, GitHub Actions 배포 등)을 가져오는 것. 사용자가 원칙으로 배제했다.

## 반영
- 원칙을 설계 문서 첫머리에 적었다: 스택·결정은 가져오지 않고 형식·판단 방식만 가져온다(`docs/presentation/evidence-formats.md` 1절).
- PR #583: A0 임계값을 판정 기준으로 바꾸고(요청 수 1,000·409 0건·오류율 1% 미만, 어기면 종료 코드 99), `a0-report.py`에 판정 열, 설계 문서 5-0절에 측정 전 판정 기준(유효성·정합성·LLM 예측별 지표), `compare.py`에 초당 최대·1분 구간·등급별 409 표, 커밋한 CSV 재생성 일치 테스트.
- PR #580: 리뷰 프롬프트에 잠근 뒤 상태 재확인, 멱등하지 않은 요청의 재시도, `@Transactional` 오용, 살아남은 변이를 더하고 답글에 반영 커밋 SHA 규칙. 형식 견본 T1~T11과 적용 표, ArchUnit 설계(`evidence-formats.md`).
- PR #597(ISE-274): `build.yml` PR 빌드 중복 실행 취소.
- 새 이슈: ISE-275(ArchUnit, 강민 언급), ISE-276(도입하지 않은 것·알려진 한계). 팀원 이슈(ISE-264~270)에 해당 견본을 댓글로 알림.
- CodeRabbit은 뒤이은 결정으로 넣지 않는다.

## 검증
- A0 임계값: `k6 inspect`와 같은 형식의 작은 스크립트를 k6 1.0.0으로 돌려 `count==N`·태그 하위 지표 조건이 동작함을 확인. `a0-report.py`는 가짜 요약 4개로 합격·무효·불합격을 확인.
- Synthetic 테스트 16개 통과, 커밋한 CSV 재생성 일치는 Python 3.9·3.11·3.12·3.14·3.15에서 통과.
- PR #597: 같은 PR에 빈 커밋을 올려 앞선 build 실행이 `cancelled`로 끝나는 것을 확인. push 빌드가 취소되지 않는지는 머지 뒤 확인.
- 프롬프트 보강분으로는 아직 리뷰를 돌려 보지 않았다.
- 설계 중 바로잡은 것: 처리량 "200/s 이상이면 목표 충족" 기준을 넣으려다 SA 3장이 고정 목표를 버린 것(결정 47번)을 확인하고 뺐다. CI 그룹을 브랜치로 두려다 `images.yml`의 주의(한 그룹에 대기 실행은 하나만 남음)를 보고 push는 커밋별 그룹으로 바꿨다.

## 판단 이력
- 2026-11-13 수용: 형식과 판단 방식만 가져오는 원칙으로, 바로 할 것 두 가지와 전체 적용 설계, CodeRabbit 적용 설계를 맡김
- 2026-11-13 일부 변경: CodeRabbit은 호출 한도 때문에 넣지 않기로 했다([기록](2026-11-13-no-coderabbit-prompt-review-only.md)). 리뷰 형식은 프롬프트로 옮긴다

## 발표·면접 포인트
- 다른 팀을 볼 때 무엇을 만들었는지보다 어떻게 증명했는지를 봤다. 기술 선택은 도메인마다 달라 가져오지 않았고, 측정 전에 기준을 고정하고 대가와 한계를 같이 적는 형식만 가져왔다.
