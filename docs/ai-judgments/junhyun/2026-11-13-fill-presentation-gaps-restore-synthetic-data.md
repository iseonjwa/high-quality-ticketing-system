# 발표 전 보완 제안 세 가지를 받아들이고, 취소된 Synthetic Data를 되살림

## 맥락
- 해결하려던 작업: 최종 발표(11/19)에서 심사위원이 좋게 평가하려면 무엇을 더 채워야 하는지 물었다. 발표 자료에는 직접 겪고 해결한 경험을 기본으로 넣고 판단의 비중을 크게 둘 생각이었다. 4조 저장소(`gongmoju-4jo/ipo-subscription`)도 비교 대상으로 줬다.
- AI 활용 방식: Claude Code가 Notion 발제문의 필수 항목·산출물을 읽고 저장소·Linear 상태와 대조했다. 4조 저장소는 하위 에이전트가 읽기만 해서 조사했고, PR 리뷰 수는 GitHub GraphQL로 두 저장소를 같은 방식으로 셌다. 정리는 `docs/learning/junhyun/qna/2026-11-13-final-presentation-gaps-vs-rubric.md`에 있다.

## AI 제안
보완할 것을 급한 순서로 넷 냈다.
1. 빈 필수 산출물 채우기: Synthetic Data(ISE-28이 11/11 취소, 저장소에 CSV·프롬프트 원문 없음), 동기형·접수형 비교(ISE-18 Backlog), 발제 기준(100명 × 10회) 요약 표, Kafka-UI·SAGA 보상 캡처.
2. AI가 만든 코드를 어떻게 검증했는지 보이기: 리뷰가 남은 PR이 316개 중 12개(4조는 81개 중 76개, 리뷰 384건). 해 온 방법을 적고 남은 PR부터 리뷰를 PR에 남긴다.
3. AI 대표 사례 2건을 발제 형식으로 정리.
4. 비어 있는 발표 폴더 채우기.

## 판단
- 결과: 수용(1~3번)
- 판단자: Junhyun An
- 근거: "Synthetic Data 필요해. 없애기로 했다면 오판이야." AI 코드 검토 방법은 자세히 써 달라고 했다. 앞서 "우리가 AI가 생산한 코드를 검토하는 방법도 만들어서 넣어야겠다. 다른 조는 코드래빗도 달았고, 좀 리뷰를 적극적으로 했구나"라고 했다. 필요하면 다른 팀원 세션에서도 돌릴 수 있게 프롬프트나 스크립트를 만들어 알려 달라고 했다.
- 검토한 대안: ISE-28 취소 사유(대기열 담당, 11/11)는 "회차마다 Redis 키가 따로라 인기 회차 쏠림은 지금 Q1~Q3와 결과가 같고, 좌석 구역 쏠림은 좌석 담당 판단"이었다. 발제의 Synthetic Data는 회차 쏠림 하나가 아니라 실제 사용 패턴을 모사한 LLM 생성 데이터와 그 비교 결과를 산출물로 요구한다.

## 반영
- Linear ISE-262(Synthetic Data, 발제 기준선 A0), ISE-263(AI 코드 검토 방법, 대표 사례)을 만들고 ISE-262를 ISE-28·ISE-18과 연결했다.
- 동기형·접수형 비교는 ISE-18 담당(권우)이 하도록 두고, 쓸 수 있는 시나리오와 실행 지시문을 넘긴다.
