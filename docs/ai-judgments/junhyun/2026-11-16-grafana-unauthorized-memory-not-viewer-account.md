# 공개 Grafana를 "로그인 없이 볼 수 있다"고 쓴 AI의 브로셔 문장이 실제와 다르다고 지적함

## 맥락
- 해결하려던 작업: 10기 최종 발표회 브로셔(ISE-298)를 노션에 반영한 뒤 사용자가 링크를 직접 열어 봤다.
- AI 활용 방식: AI(Claude Code)가 브로셔 원문과 노션에 "실시간 지표: https://52.63.10.174/grafana/ (로그인 없이 볼 수 있는 대시보드 6개)"와 "심사위원도 공개 Grafana에서 바로 볼 수 있습니다"를 썼다.

## AI 제안
- 브로셔 문장: 공개 Grafana는 로그인 없이 대시보드 6개를 볼 수 있다. 근거는 같은 날 ISE-278로 익명 Viewer를 켠 설정과 배포 뒤 주소 확인(200)이었다.
- 지적을 받은 뒤의 분석: 같은 Chrome과 터미널에서 다시 확인하니 익명 보기는 정상이었다(대시보드 6개 목록, 패널 쿼리 200). 대신 대시보드를 보는 중에 Grafana가 17:13과 17:24(KST)에 다시 시작되어 502·503과 빈 패널이 보였다. 힙 사용이 GC 주기마다 약 200MB → 370MB로 오르내렸고, 370MB 근처에서 상한(384MiB)을 넘어 죽었다. Unauthorized 자체는 재현하지 못했다.
- 사용자가 낸 Viewer 계정 안에 대한 AI 의견: 만들지 않기를 권했다. 익명 보기가 이미 Viewer와 같은 권한이라, 재시작 중에는 계정이 있어도 똑같이 보이지 않는다. 공개 노션에 올린 비밀번호는 누구나 아는 값이 되어 로그인 단계만 늘어난다. 운영 서버의 관리자 로그인이 필요해 AI가 대신 만들 수도 없다. 대신 Grafana 상한을 640MiB로 올리고 `GOMEMLIMIT`을 두자고 했다(PR #700, ISE-301).

## 판단
- 결과: 거부
- 판단자: junhyun
- 근거: "그라파나 볼 수 있다면서 Unauthorized 뜬다!" 브로셔 문장대로 열리지 않았다.
- 검토한 대안: 사용자가 "viewer 권한만 가진 계정 만들어서 정보 같이 올려놓을 수 있을까?"를 제안했다. AI 의견에 대한 판단은 아직 없다.

## 반영
- `compose.deploy.yml` grafana 상한 384m → 640m, `GOMEMLIMIT: 512MiB`(PR #700, ISE-301). 배포 서버 반영은 dev·main 머지 뒤다.
- `docs/troubleshooting.md` TS-79.
- 브로셔 문장은 그대로 두었다. 익명 보기 설정은 맞고, 문제는 재시작이었다.

## 검증
- 익명 보기: `/grafana/api/search` 200(대시보드 6개), `/grafana/api/ds/query` 200, Chrome에서 대기열·요청 로그·좌석 선점 대시보드가 로그인 없이 열렸다.
- 재시작: `/grafana/metrics`의 `process_start_time_seconds`가 17:13:21과 17:24:32(KST)로 바뀌었고, 그때 10초 새로고침 묶음과 상태 확인이 502·503이었다.
- AI가 처음에 "RSS가 상한에 붙었다"고 설명했지만, 이후 RSS가 약 502MB로 상한보다 크게 나와(파일 매핑 포함) 근거를 힙 사용으로 고쳤다.
- 상한 640m의 효과는 배포 전이라 미확인이다.

## 판단 이력
- 2026-11-16 거부: 브로셔의 "로그인 없이 볼 수 있다"가 실제와 다르다고 지적했다. AI가 원인을 권한이 아니라 메모리 상한 재시작으로 찾았다.

## 발표·면접 포인트
- 설정이 맞아도 공개 화면이 "보인다"고 말하려면 여러 명이 동시에 볼 때를 재야 한다. 관측 도구도 공개하면 사용자 트래픽을 받는 서비스라 메모리 상한을 다시 잡았다.
