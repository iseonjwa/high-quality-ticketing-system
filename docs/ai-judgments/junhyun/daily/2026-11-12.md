- [선택] AI가 오늘 기록(판단 일지, HTTPS 학습 노트)을 올릴 때 보안 점검 문서를 뺄지 정해야 한다고 하자, 점검 문서는 빼고 커밋하기로 했다. AI 근거는 저장소가 공개라 배포 서버가 떠 있는 동안 점검 문서가 공격 순서를 드러낸다는 것이었다. AI는 점검 문서를 로컬에만 두고(`.git/info/exclude`), 기록에서 그 문서로 가는 링크와 항목별 수정 순서 나열을 지웠다 — 근거: 미기재("보안점검 문서는 빼고 커밋하자!") (Claude Code)
- [수용] 결제 동시 처리 한도를 묻자 AI가 "배포에서 잰 적이 없고, 설정(PG 동시 허가 10 ÷ Mock PG 지연 0.3초)으로 계산한 초당 약 33건뿐"이라고 답하며 PAY1을 배포에서 재자고 하자 재보기로 했다. AI는 PAY1이 서버에서 만든 회차(`SCHEDULE_ID`)를 받게 고쳐 PR #507로 올리고, PG 지연 300ms 판(PG 한도)과 지연 없는 판(결제 서비스 자체 한도) 두 번을 재는 순서를 냈다 — 근거: 미기재("재보자!") (Claude Code)
- [부분 수용] AI가 PAY1 측정 순서에서 "다른 팀원이 측정 중이 아닌가"를 팀 채널로 확인하라고 적자, 팀은 측정자가 측정 모드를 먼저 켜고 재므로 `measure-mode.sh status`에 다른 사람의 측정 모드가 켜져 있으면 꺼질 때까지 기다리는 것이 기준이라고 바로잡았다. AI는 그 기준대로 상태 확인을 첫 단계로 두고, 켜져 있으면 기다리게 순서를 고쳤다 — 근거: "다른 사람 측정모드가 켜져있으면 꺼질때까지 대기해야해" (Claude Code)
- [거부] AI가 PAY1 시작 순서 첫 단계로 팀 채널에 시작 알림 문구를 직접 올리라고 하자, 측정 모드를 켜는 스크립트가 알림을 자동으로 보내지 않느냐고 바로잡았다. AI가 `measure-mode.sh`를 확인하니 `on`이 측정 전용 채널(없으면 성능-모니터링 채널)에 측정자·시각·커밋과 "main 머지를 멈춰 주세요"를 보내고, 웹후크가 둘 다 비었을 때만 직접 알리라고 안내한다. AI는 손 알림 단계를 빼고 켜기·키 옮기기 두 단계로 줄였다. `loadgen.md` 4절 1번의 손 알림 문구는 자동 알림이 생기기 전 내용이다 — 근거: "그거 자동으로 뭐 스크립트 보내면 하는거아니었어?" (Claude Code)
- [수용] PAY1 결과를 보고 AI가 결제 처리량 개선 순서로 PG 동시 허가 10 → 30(PAY-1), 짧은 대기 100~200ms(PAY-2), 측정 뒤 설정값 반영을 내고 인스턴스 증설·비동기 호출·Gateway 상한 조정은 하지 않겠다고 하자, 단계마다 바꿔 보며 재고 기록을 모두 남기기로 했다. AI 근거는 PG 호출 중 DB 연결을 잡지 않고(Hikari 활성 최대 2) PG가 빠르면 초당 약 190건을 받는다는 측정값, 대기열 입장 초당 50명이 PG 300ms 한도 31건보다 크다는 것이었다 — 근거: "각각 단계에서 개선해보면서 측정하고 기록 다 남기자!" (Claude Code)
- [선택] AI가 결제 서비스 재기동 직후 첫 단계 p99가 1.1~1.4초인 콜드 스타트의 원인 후보(JIT, PG HTTP 첫 연결, 클래스 로딩)를 가르지 않은 채 "미확인"으로 적자, 코드 수정을 끝낸 다음 테스트해서 원인 후보를 특정하기로 했다. AI는 그전에 이미 있는 Prometheus 값으로 좁혀 보았고(첫 1분 최대값: 승인 1.4~2.0초, PG 호출 0.45~0.55초, 첫 `findByReservationId` 0.6~0.9초, 커넥션 획득 0.03~0.16초), 확정은 코드 수정 뒤 측정으로 미뤘다 — 근거: "코드 수정 완료한 다음 테스트해서 원인후보 특정 완료하자"(md 뷰어 코멘트) (Claude Code)
- [수용] AI가 낸 결제 서비스 개선 방안 8가지(예매 대사 켜기, PG 동시 허가 30, Mock 건너뛰기 기본값, 재기동 뒤 공백, 503 자동 재시도, 빌링키 등록 제한, 결제 토큰 서명 방식, 기동 웜업)를 문서로 확인한 뒤 전부 적용하기로 했다. 적용할 때마다 설계 문서와 상세 이론 문서를 함께 남기게 했다. AI는 "시연 전에는 앞의 세 가지만"을 권했지만 사용자는 전부를 골랐다. AI는 이슈마다 PR을 나누고, 다른 담당 영역(Gateway 공통 설정, 예매 쪽 토큰 서명)은 `contract` 이슈로 알리며 머지 시점은 사용자가 정하게 했다 — 근거: "문서 확인했어! 전부 적용해줄래? 하나하나 적용할때마다 설계 및 상세 이론 문서까지 남겨줘." (Claude Code)
- [선택] AI가 결제 개선 PR을 올릴 때마다 "머지는 직접 하면 된다"고 넘기자, PR을 그때그때 머지하면서 진행하라고 맡겼다. AI는 내 담당 영역 PR은 CI 통과를 확인하고 최신 dev를 합친 뒤 squash로 머지하고, 다른 담당 영역을 바꾸는 PR(Gateway 공통 설정, 예매 쪽 코드)과 초안 PR은 머지하지 않고 리뷰를 기다리기로 했다 — 근거: "pr 그때그때머지하면서 진행해줘!" (Claude Code)
- [거부] AI가 다른 담당 영역을 바꾸는 PR(#526 서비스 발견 주기, #533 결제 토큰 ES256)은 담당 리뷰를 기다리고 #533은 시연 뒤 머지를 권하자, 리뷰를 기다리지 말고 머지하라고 했다. 팀 규칙은 필수 승인 없이 작성자가 검증 뒤 머지하고 팀에 알리는 것이다(`git-workflow.md` 5절). - [선택] AI가 토스 모드에서 "Mock으로 건너뛰기" 기본값이 꺼짐으로 바뀌니(ISE-240) 시연에서 쓸지 정해야 한다고 하자, 토스 모드에서 건너뛰기 버튼을 쓰기로 했다. 서버 `.env`에 `PAYMENT_PG_MOCK_BYPASS=true`를 넣는다 — 근거: "토스모드에서 건너뛰기 버튼 쓸거야" (Claude Code)
