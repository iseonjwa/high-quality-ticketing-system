# 결정 기록 운영: 바뀐 결정을 기존 항목 이력에 덧붙이자는 AI 제안 대신 기존 항목은 대체됨으로 바꾸고 새 항목을 만든다

## 맥락
- 해결하려던 작업: 튜터 피드백으로 v2 접수형에 요청 행을 남기는 쪽으로 바뀌게 되어, 기존 결정(좌석 선점 #33, 데이터 모델 #50의 D4)을 어떻게 기록할지 정해야 했다.
- AI 활용 방식: 튜터 피드백과 팀 대화를 정리해 달라고 했다.

## AI 제안
- D4를 되돌리는 일이므로 결정 기록 #33·#50의 판단 이력에 "10/26 튜터 피드백으로 재검토"를 덧붙이자고 했다.
- 같은 날 #9 역할 분담, #10 서비스 구성도 기존 항목 본문을 고쳐 상태를 결정으로 바꾸는 수정안을 냈다.

## 판단
- 결과: 거부
- 판단자: 팀 (전달: GGangMY)
- 근거: "이후 새로운 결정 기록들은 기존 결정 기록은 대체됨 상태로 전환하고 새 항목을 생성해서 기록하기로 했음"
- 검토한 대안: 기존 항목 본문을 고치고 판단 이력에 덧붙이기

## 반영
- 이후 결정 기록 수정안은 잠정 결정과 내용이 다를 때만 "기존 항목 상태 → 대체됨" + "새 항목 본문" 두 부분으로 만든다. 내용이 같으면 상태 변경과 본문 수정만 한다.
- 이미 만든 #9·#10 본문 수정안(덮어쓰기 방식)은 그대로 두고, 다음 결정부터 새 규칙을 적용한다 (GGangMY: "이번 거까진 두고 다음부터 그렇게 하자").

## 검증
해당 없음

## 판단 이력
- 2026-10-26 거부: 결정이 바뀌면 기존 항목은 대체됨, 새 항목 생성으로 팀 규칙을 정함
- 2026-10-26 규칙 보완: 잠정 결정(AI 추천)과 내용이 같으면 새 항목 없이 상태 변경과 본문 수정으로 확정하고, 내용이 다를 때만 대체한다. 근거: "결정 내용이 바뀐 것이 아니면 추천대로 근거에 수긍하고 진행하는 것이기 때문에 추가 포스트 없이 상태 변경 및 본문 수정으로 마무리". AI가 앞서 제안한 구분 기준(내용이 바뀌면 대체, 상태만 확정이면 상태 변경)과 같은 방향이다
- 2026-10-26 규칙 재보완: 기존 내용에서 크게 바뀌지 않으면 대체하지 않고 기존 본문을 고친 뒤 수정 내역(바뀐 점과 이전 결정)을 남긴다. 새 주제만 새 항목. 근거: "기존 내용에서 크게 변하지 않으면 새로 대체됐다고 하기보단 기존 본문 수정하고 수정 내역 남기면 될 것 같아. 지금 쓸데없이 작업이 늘어난다"

## 발표·면접 포인트
- 결정을 덮어쓰지 않고 대체 관계로 남겨, 언제 무엇이 왜 바뀌었는지 항목 단위로 추적할 수 있게 했다. ADR의 superseded 방식과 같다.
