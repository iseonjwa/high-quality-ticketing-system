# PR CI 자동 수정을 끄자는 추천을 거부하고 켜기로 함

## 맥락
- 해결하려던 작업: ISE-84 PR `#139`를 연 뒤 CI(`build`, `records-check`) 결과를 어떻게 지켜볼지 정하는 단계.
- AI 활용 방식: "CI 실패라는게 무슨 말"이라는 질문에 CI와 Claude Code 앱의 자동 수정(Auto-fix) 기능을 설명받았다.

## AI 제안
- 평소 커밋·푸시를 직접 하는 방식이므로 자동 수정은 끄고, 실패하면 원인을 함께 보는 쪽을 추천했다.
- 근거: 자동 수정을 켜면 사용자가 보기 전에 커밋이 PR에 추가된다.

## 판단
- 결과: 거부
- 판단자: 이강민
- 근거: 미기재("자동 수정 켜기")
- 검토한 대안: 끄고 직접 확인(AI 추천)

## 반영
- PR `#139`에 자동 수정을 켰다. CI 실패·머지 충돌·리뷰 코멘트가 오면 에이전트가 고쳐 커밋·푸시한다.

## 검증
- 켠 시점에 `build`, `records-check` 모두 통과 상태였다.

## 판단 이력
- 2026-11-01 거부: 끄자는 추천 대신 자동 수정을 켬.

## 발표·면접 포인트
- 작은 문서·도메인 PR에서는 CI 실패 대응을 자동화해 대기 시간을 줄이고, 결과는 PR 이력으로 검토한다.
