# EC2 종료 동작 설명이 틀린 것 아니냐고 지적했고, 사실 오류가 아니라 용어 혼동으로 정리함

## 맥락
- 해결하려던 작업: 떠 있는 EC2를 2시간 뒤 자동으로 내리는 방법을 확인하던 중이었다.
- AI 활용 방식: 셸 명령으로 예약할 수 있는지 묻고, 인스턴스 종료와 서버 끄기의 차이와 종료 동작 설정을 이어서 물었다.

## AI 제안
서버 안에서 `sudo shutdown -h +120`으로 예약하되, 먼저 인스턴스의 "종료 동작"(`InstanceInitiatedShutdownBehavior`)을 확인하라고 안내했다. 값이 `stop`이면 중지되고 `terminate`면 삭제된다고 설명했다. 설정 이름의 "종료"가 콘솔의 "인스턴스 종료"(Terminate)와 다른 뜻이라는 점은 처음부터 밝히지 않았다.

## 판단
- 결과: 거부
- 판단자: GGangMY
- 근거: 인스턴스 종료는 인스턴스를 삭제하는 것이고 인스턴스 중지가 잠시 꺼 두는 것인데, 잘못 알려 준 것 아니냐고 지적했다.
- 검토한 대안: 미기재

## 반영
AI가 지적을 검토한 결과, 중지와 종료의 사실 설명은 사용자 이해와 같았고 "종료 동작"이라는 표현이 혼동을 만들었다. [학습 노트](../../learning/kangmin/qna/2026-11-06-ec2-scheduled-shutdown.md)에 설정 이름의 "종료"가 OS `shutdown`을 가리킨다고 적었다.

## 검증
AWS 공식 문서와 실제 서버에서 다시 확인하지 않았다. 두 서버의 종료 동작 값도 확인하지 못했다.

## 판단 이력
- 2026-11-06 거부: 설명이 틀렸다고 지적했고, 사실 오류가 아니라 용어 혼동으로 정리했다.

## 발표·면접 포인트
- EC2의 중지는 다시 켤 수 있고 종료는 인스턴스를 삭제한다. OS 안에서 `shutdown`을 실행했을 때 어느 쪽이 되는지는 종료 동작 설정이 정한다.
