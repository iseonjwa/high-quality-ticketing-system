# 에이전트로 k6를 돌릴 때 토큰이 많이 드는 원인(진행 표시줄 출력, 느린 기록 검사 훅) 진단 중 k6 출력 건만 이슈로 올리기로 함

## 맥락
- 해결하려던 작업: 대기열 담당이 에이전트로 테스트할 때 실행 한 번에 토큰 약 1만 개가 들고 기록 구조 검사가 오래 걸린다고 해서 원인을 찾았다.
- AI 활용 방식: 팀 대화를 붙여 넣고 원인 유추와 해결을 요청했다.

## AI 제안
- 원인 1: `loadtest/k6/run.sh`가 k6 출력을 `tee`로 그대로 내보낸다. 터미널이 아니면 k6가 진행 표시줄을 1초마다 새 줄로 찍는다. 11/6 결과에서 stdout 39.8KB·43.7KB 가운데 94~97%가 진행 표시줄이고 요약은 1.3~2.3KB였다. 해결안은 k6 `--quiet`와 에이전트가 요약·`summary.json`만 읽는 규칙이다.
- 원인 2: `script/records-check.sh --hook`이 Windows Git Bash에서 1분 45초가 걸려 훅 시한 30초를 넘는다. 비밀값 검사가 파일 1,708개마다 grep을 띄워 42초가 들고, `git grep --untracked` 한 번이면 0.2초였다. 나머지는 머리말 검사의 awk 반복으로 추정했다.
- 기대 효과(추정): 원인 1을 고치면 실행 한 번의 출력 토큰이 약 1만 개에서 수백~1,500개로 준다. 원인 2는 주로 대기 시간이고, 검사가 실패해 에이전트가 한 턴 더 돌 때만 토큰에 영향이 있다.

## 판단
- 결과: 부분 수용
- 판단자: kangmin
- 근거: 미기재. 이슈 초안 2건 가운데 원인 1(k6 출력)만 올리기로 했다. 원인 2(기록 검사 훅)는 이슈로 올리지 않았다
- 검토한 대안: 두 원인을 이슈 2건으로 나눠 올리는 안, 하나로 합치는 안

## 반영
Linear ISE-219 등록(원인 1). 원인 2는 미반영. 코드는 미반영.

## 검증
- 측정함: 결과 파일 바이트 구성, 훅 실행 시간(1분 45초), 비밀값 검사 전후 시간(42초 → 0.2초).
- 확인 못 함: k6 1.0.0 `--quiet`의 실제 효과(Docker 꺼짐), 토큰 수(바이트를 4바이트당 1토큰으로 환산한 추정), 대기열 담당의 실제 실행 방식.
