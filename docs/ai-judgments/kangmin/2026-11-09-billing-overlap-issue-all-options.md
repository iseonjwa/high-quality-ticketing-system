# 자동결제 겹침 contract 이슈를 추천안 하나로 좁히지 않고 모든 선택지와 트레이드오프를 담아 결제 담당과 고르기로 함

## 맥락
- 해결하려던 작업: 추첨 당첨 자동결제와 일반 예매 결제가 겹칠 때의 문제와 대응을 정리해 결제 담당(alloy0301)에게 보낼 contract 이슈 초안 작성(ISE-94·ISE-89, ADR 0039).
- AI 활용 방식: 코드에서 겹침 문제를 찾고 대응 선택지를 정리하게 한 뒤, 레이트 리미터 도입 여부와 "바쁠 때 자동결제가 빠지는" 방식을 추가로 물었다.

## AI 제안
- 문제 9개(P1~P9)를 코드 근거와 함께 정리했다. 새로 찾은 것은 기한이 지난 결제 명령이 승인 뒤 환불되는 문제, 빌링 장애가 공유 CB를 여는 문제, 재시도·승계 요청이 큐 끝에 붙는 문제다.
- 이슈 초안 1판은 "A(전용 토픽 + 전용 그룹) + 결제 기한 필드"를 추천안으로 두었다.
- 레이트 리미터는 겹침 문제를 거의 풀지 못하고 외부 API 한도용이라고 답했다. 바쁠 때 양보하는 방식은 Bulkhead 남은 자리 확인을 추천하되 토픽 분리와 기아 방지가 전제라고 답했다.

## 판단
- 결과: 부분 수용
- 판단자: kangmin
- 근거: "가능한 가짓수 모두 고려해 트레이드오프까지 포함 내용 정리해서 이슈 뽑아내보려해 등록은하지말고 초안 제공해봐"
- 검토한 대안: 1판처럼 A + 기한 하나로 좁혀 보내는 안.

## 반영
- contract 이슈 초안 2판(대화)에 모든 후보(격리·속도·토픽 막힘·기한·복구 경로·운영 정책)와 조합안, 트레이드오프를 담았다. Linear 미등록.
- 근거 설명: `docs/learning/kangmin/qna/2026-11-09-billing-vs-general-payment-overlap.md` 5~7절.

## 검증
구현 전. 후보 선택은 11/10 L2-a·L2-b(·L2-c) 측정 결과로 한다.

## 판단 이력
- 2026-11-09 부분 수용: 분석은 받고, 이슈는 추천안 하나 대신 모든 선택지를 펼쳐 결제 담당과 고르기로 했다.

## 발표·면접 포인트
- 서비스 경계를 넘는 설계는 한쪽이 답을 정해 보내지 않고, 선택지와 대가를 펼쳐 상대 담당과 측정값으로 고르게 했다.
