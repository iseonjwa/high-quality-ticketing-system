# 부하 발생기 EC2 안내가 강민 혼자 쓰는 구성이라 팀 공용으로 바꾸게 함

## 맥락
- 해결하려던 작업: 계정 주인(안준현)이 11/9 점심에 k6 부하 발생기 EC2를 띄울 수 있게 콘솔 값과 순서를 정리한 안내 페이지 작성.
- AI 활용 방식: 안내 페이지 초안을 만들게 했다.

## AI 제안
- 발생기 보안 그룹의 SSH(22) 소스를 강민 공인 IP 하나로, 접속 키는 사용자 데이터로 강민 공개 키 하나만 넣었다.
- 측정이 끝난 날 바로 종료(Terminate)하게 했다.

## 판단
- 결과: 거부
- 판단자: kangmin
- 근거: "그럼 부하 발생기 EC2가 저렇게 세팅하면 나만 쓸 수 잇는거임? 모두가 다 써야됨"
- 검토한 대안: 측정 담당마다 발생기를 따로 만드는 안. 계정 주인이 매번 만들어야 해서 고르지 않았다.

## 반영
- SSH 소스는 배포 서버 보안 그룹 22번 규칙의 팀원 IP를 그대로 옮기고, 키는 배포 서버 `authorized_keys`(11/5 등록된 팀원 키)를 복사하게 바꿨다.
- 같이 쓰는 규칙을 더했다: 측정은 한 번에 한 사람(같은 서버를 재므로), 각자 폴더 `~/<영문 이름>/iseonjwa`, 측정 전용 키 `.env`는 그날 측정자 폴더에만, 측정 날 사이 중지·팀 마지막 측정 뒤 종료.
- 안내: https://claude.ai/artifact/T6SXHZeCDWpZ3XzbvqWNSN (3판)

## 검증
키 복사 명령과 사용자 데이터 방식은 직접 실행하지 않았다. 안내 페이지에 "확인 못 함"으로 적었다.

## 판단 이력
- 2026-11-09 거부: 1인용 구성 대신 팀 공용 구성으로 바꿈.
