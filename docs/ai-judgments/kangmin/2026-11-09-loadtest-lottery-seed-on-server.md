# 배포 측정에서 L1~L3의 관리자 로그인 문제를 서버 추첨 생성 + k6 ID 전달(1안)로 풀기로 함

## 맥락
- 해결하려던 작업: 11/9 팀 공용 발생기 준비를 마친 뒤, 11/10부터 배포 서버에서 L1(응모 몰림)을 재려 했다.
- AI 활용 방식: 발생기 준비를 단계별로 안내받다가 "L1/L2의 adminLogin에 왜 AWS 담당 동의가 필요한가", "지금 가장 급한 것은 무엇인가"를 물었다.

## AI 제안
- L1~L3 스크립트는 `setup()`에서 `adminLogin()`으로 회차·추첨을 만드는데, ADR 0046 변경(운영 관리자 비밀번호는 발생기에 두지 않는다) 때문에 배포에서 돌지 않는다.
- 1안(추천): 서버에서 회차·추첨을 만들고 k6는 ID만 받는다(Q1~Q3의 `SCHEDULE_ID`와 같은 방식).
- 2안: 측정 동안만 쓰는 관리자 계정을 발생기에 둔다.
- 1안의 `seed-demo.sh` 수정은 강민이 맡고 AWS 담당은 리뷰하는 형태로 제안하면 답이 빠르다.

## 판단
- 결과: 수용
- 판단자: kangmin
- 근거: "1안으로 가고 이슈 따로 기록해 남겨서 리뷰 요청할게. 스크립트도 내가 고칠 수 있게 하고 안내하자"
- 검토한 대안: 2안(측정 전용 관리자 계정). 관리자 권한이 발생기에 놓이고 팀 규칙에 예외가 생겨 버렸다.

## 반영
- Linear ISE-216(contract, 담당 AWS 담당, related ISE-191·ISE-94·ISE-215)에 고른 방식과 리뷰 요청을 올렸다.
- 구현은 강민이 직접 한다. 에이전트는 단계 안내와 리뷰만 한다(AGENTS.md 대전제 6). k6 L1~L3 쪽 수정은 herdr ③ 세션이 맡는다.
