# 측정 모드를 AWS 담당 한 명이 아니라 측정자가 직접 켜고 끄고, 시작·끝 알림으로 겹침을 막기로 함

## 맥락
- 해결하려던 작업: 11/10부터 팀원 여럿이 같은 배포 서버를 번갈아 측정한다. 지금 규칙(ADR 0046 변경, 11/8)은 측정 모드(`measure-mode.sh on/off`)를 계정 주인(AWS 담당)만 켜고 끈다.
- AI 활용 방식: 왜 AWS 담당만 켜는지 묻고, 선택지(A 측정자 직접, B AWS 담당 한 명)를 비교받았다.

## AI 제안
- B(현행) 유지를 추천했다. 운영 서버를 손으로 다시 띄우는 유일한 예외이고, 비밀값과 Jenkins를 함께 다뤄 한 사람에게 묶어야 사고가 준다는 이유였다.
- AWS 담당이 병목이 되면 측정자 위임 절차를 정하자고 했다.

## 판단
- 결과: 거부(A 선택)
- 판단자: kangmin
- 근거: "측정자가 직접 켜고 끄고 서로 시작과 끝을 알려 겹치는 일을 해소할 것임"
- 검토한 대안: B 현행 유지

## 반영
- ADR 0046에 변경을 더하고, 측정 날 순서 문서들의 "계정 주인/AWS 담당이 켠다"를 "측정자가 켠다"로 바꾼다. 진행은 사용자 확인 뒤에 한다.
- AWS 담당 동의를 받았다(사용자 전달 "동의받음", 2026-11-09). 동의는 저장소 밖(Slack 등)에서 받았다.

## 검증
진행 전이라 해당 없음.

## 판단 이력
- 2026-11-09 거부: AWS 담당 병목을 피하려고 측정자 직접 운영을 골랐다.
- 2026-11-09 팀 합의: AWS 담당이 동의했다.

## 발표·면접 포인트
- 운영 권한을 한 사람에게 모을지 실행자에게 나눌지는 사고 위험과 병목 사이의 선택이다. 나누는 대신 시작·끝 알림과 상태 확인(`measure-mode.sh status`)으로 겹침을 막는다.
