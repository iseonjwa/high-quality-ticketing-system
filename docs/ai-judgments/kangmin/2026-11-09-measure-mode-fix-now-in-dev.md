# 측정 모드 개선(꺼진 상태 off 건너뛰기, 설정 변경 구분)을 측정 기간 뒤로 미루자는 제안 대신 dev에서 먼저 처리해 두기로 함

## 맥락
- 해결하려던 작업: 11/9 서버 시험에서 이미 꺼진 상태의 `off`가 재기동과 "알 수 없음" 알림을 만들고, 같은 측정자의 재적용도 겹침으로 알리는 문제를 찾았다.
- AI 활용 방식: 고칠지, 언제 반영할지 선택지를 받았다.

## AI 제안
- 서버 스크립트라 main 반영이 필요하고 내일부터 측정 기간이라, 측정 기간 뒤(11/14~)로 미루고 그동안은 공지 문구("off는 한 번만")로 막자고 했다.

## 판단
- 결과: 거부
- 판단자: kangmin
- 근거: "아무도 측정 안하고있을때 main으로 넘기면 되니까 dev에서 우선 진행해서 처리해두자"
- 검토한 대안: 오늘 밤 3차 반영, 측정 기간 뒤 처리

## 반영
- ISE-228을 등록하고 PR `#444`(dev 대상)로 구현했다. main 반영은 측정이 없는 시간에 한다.

## 검증
- `DRY_RUN` 검사 17개 통과. 변이 3가지(같은 사람 판정 뒤집기, 꺼진 상태 건너뛰기 끄기, 마지막 사람 기록)가 모두 검사에 걸렸다.
- 첫 변이 하나(`[[ ... && false ]]`)는 `false`가 글자로 취급돼 항상 참인 동등 변이라 걸리지 않았고, 변이를 고쳐 다시 확인했다.

## 판단 이력
- 2026-11-09 거부: dev에서 먼저 구현, main은 측정이 없을 때.

## 발표·면접 포인트
- 코드 반영(dev)과 배포(main)를 나눠 생각하면, 측정 기간에도 개선을 멈추지 않고 배포 시점만 고를 수 있다.
