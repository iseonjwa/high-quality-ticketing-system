# 측정 모드를 켜고 끌 때 슬랙 자동 알림을 붙이기로 함(사람 알림만으로 두지 않음)

## 맥락
- 해결하려던 작업: ISE-218에서 측정 모드를 측정자가 직접 켜고 끄도록 바꿨다. "측정 모드 on/off가 슬랙으로 오는가"를 물었는데, 오지 않았다.
- AI 활용 방식: 지금 슬랙 알림 경로(Jenkins 배포 알림, Alertmanager)를 코드로 확인하고 선택지를 비교받았다.

## AI 제안
- A: 지금처럼 사람 알림만 둔다.
- B: `measure-mode.sh on/off`가 끝날 때 자동으로 알린다(추천). 서버 `.env`의 기존 웹훅을 써서 비밀값이 밖으로 나가지 않는다.
- C: B에 더해 이미 켜져 있으면 `on`을 막는다.

## 판단
- 결과: 수용(B)
- 판단자: kangmin
- 근거: "자동 알림 붙이자"
- 검토한 대안: A, C

## 반영
- ISE-223, PR `#429`. AWS 담당(@alloy31)께 채널 선택과 `.env` 형식 확인을 리뷰로 요청했다.
- C는 넣지 않았다. 대신 이미 켜져 있던 상태에서 다시 켜면 그 사실을 알림에 드러낸다.

## 검증
- `DRY_RUN` on·off 출력, 이미 켜진 상태에서 on, 로컬 HTTP 수신 서버로 실제 전송(한글·따옴표·역슬래시·줄바꿈), 웹훅 실패·키 없음 경로를 확인했다.
- 시험 중 두 문제를 고쳤다. Windows에서 `curl -d` 인자로 넘긴 한글이 `?`로 깨져 표준 입력으로 바꿨고, `TZ=Asia/Seoul`이 UTC로 떨어져 `TZ=KST-9`로 바꿨다.
- 실제 슬랙 전송은 main 반영 뒤 서버에서 확인한다(미확인).

## 판단 이력
- 2026-11-09 수용: 자동 알림(B)을 골랐다.
