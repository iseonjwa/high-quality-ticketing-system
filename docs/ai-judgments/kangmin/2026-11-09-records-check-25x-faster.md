# 기록 검사 훅 속도 개선(약 25배)을 변이 31가지 비교로 검증한 뒤 올리고, 한글 경로 표시 개선을 함께 넣음

## 맥락
- 해결하려던 작업: 에이전트 종료 훅(`records-check.sh --hook`, 시한 30초)이 Windows에서 약 93초 걸려 검사가 끝나지 못했다(ISE-220).
- AI 활용 방식: 한 세션이 스크립트를 고치고, 다른 에이전트(herdr 작업자)가 저장소 밖 복제본에서 원래 스크립트와 출력을 비교했다.

## AI 제안
- 파일마다 외부 프로세스를 띄우던 방식을 `awk` 한 번, `git grep` 한 번으로 바꾼다.
- 공용 훅·CI 스크립트라서, 바로 올리지 말고 변이 비교 결과를 보고 올린다.
- 비교에서 다르게 나온 1건(한글 이름 파일의 비밀값)은 원래 스크립트의 누락이 고쳐진 것이다. 경로가 8진수로 나오지 않게 `core.quotePath=false`를 함께 넣는다(A안).

## 반영
- PR `#427`(ISE-220)로 올렸다. `docs/troubleshooting.md` TS-44에 문제·원인·해결·검증을 적었다.
- 처음에는 토큰 문제로 함께 다뤘는데, 이 개선은 토큰이 아니라 검사 한 번의 시간을 줄이는 것이라고 정리했다.

## 검증
- 실행 시간: 92.8초 → 3.6초(3회 중앙값, dev 복제본, Windows Git Bash).
- 변이 31가지에서 출력과 종료 코드를 바이트 단위로 비교했다. 30가지가 같았고, 1가지는 누락이 고쳐진 것이다.
- 한글 경로 표시는 복제본에서 확인했다.
- 프로세스 생성 비용은 `/usr/bin/true` 200번으로 쟀다. 평균 약 26ms였다.
- macOS bash 3.2는 확인하지 못했다.

- 원인을 "느리다"에서 멈추지 않고 숫자로 좁혔다. 프로세스 약 3,500번 × 26ms ≈ 90초로 계산해 측정값 93초와 맞췄다.
- 검사 도구를 고칠 때는 결과가 같다는 것을 증명해야 한다. 일부러 틀린 입력 31가지로 전후를 비교했고, 고친 에이전트가 아닌 다른 에이전트가 검증했다.
- 리팩토링 중 원래 도구의 숨은 누락(한글 경로의 비밀값을 건너뜀)을 발견했다.
