# 이슈 자동 완료를 피하려고 PR 제목·브랜치에서 이슈 번호를 뺀 AI 방식을 거부하고, 번호를 넣은 채 연결 종류로 완료를 막게 함

## 맥락
- 해결하려던 작업: 11/10 측정 기록 PR(`#455`, ISE-94)과 Gateway 실패 원인 기록 PR(`#463`, ISE-230)을 에이전트가 만들어 dev에 머지했다.
- AI 활용 방식: 커밋·PR·dev 머지를 에이전트에게 맡겼다.

## AI 제안
- 두 이슈 모두 후속 작업이 남아 있어, 머지 때 Linear가 이슈를 자동으로 완료하지 않도록 브랜치 이름과 PR 제목에 이슈 번호를 넣지 않았다. 본문에만 이슈를 적었다(`#463`은 `Part of ISE-230`).

## 판단
- 결과: 거부
- 판단자: kangmin
- 근거: "이거 뭔데 이슈 넘버도 없고 리니어에 보이지도 않고. 제대로 정리 다시해." Linear 리뷰 목록에서 번호 없는 PR은 어느 이슈 작업인지 알아볼 수 없다. 팀 커밋·PR 제목은 `#ISE-번호`를 붙이는 것이 관례다(최근 dev 15개 중 10개).
- 검토한 대안: 번호를 빼는 방식 유지

## 반영
- `#463`, `#455` PR 제목에 `#ISE-230`, `#ISE-94`를 붙이고, 본문의 "번호를 넣지 않았다" 문장을 "이슈를 닫지 않고 기여(Part of)로만 연결한다"로 고쳤다.
- 제목에 번호를 넣자 Linear가 `#455`를 닫는 연결(closes)로 잡아 ISE-94가 Done으로 바뀌었다. 두 PR의 Linear 연결 종류를 기여(contributes)로 바꾸고 ISE-94를 In Progress로 되돌렸다. ISE-230은 In Progress 그대로다.
- 이미 squash 머지된 dev 커밋 제목(`017ae9d6`, `52fec9e5`)에는 번호가 없다. 공유 브랜치 이력을 다시 쓰지 않으려고 그대로 둔다.
- 앞으로: 브랜치·PR 제목에 항상 이슈 번호를 넣는다. 이슈를 닫으면 안 되면 PR 본문에 `Part of ISE-번호`를 쓰고, PR을 연 직후 Linear 연결 종류가 기여인지 확인한다.

## 검증
- Linear: `#463`·`#455` 연결 종류가 contributes, ISE-94·ISE-230 상태가 In Progress임을 확인했다.

## 판단 이력
- 2026-11-10 거부: 번호를 빼는 대신 번호를 넣고 연결 종류로 자동 완료를 막기로 함
