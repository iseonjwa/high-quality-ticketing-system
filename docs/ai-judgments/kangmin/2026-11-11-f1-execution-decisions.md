# F1 장애 주입의 실행 주체·정지 방법·NOT_SENT 대체·경보 범위·선점 만료 앞당기기를 AI 추천안대로 정함

## 맥락
- 해결하려던 작업: ISE-94 F1 장애 주입(결제 서버 강제 종료, Kafka 정지, 복구 뒤 결제 1회)과 F4 Slack 경보 확인을 배포 서버에서 하기 전에, 초안 절차서(`docs/design/lottery/f1-fault-injection.md`)의 남은 결정을 정하려 했다.
- AI 활용 방식: 에이전트가 절차서의 "확인 필요" 17곳을 코드·compose·스크립트로 확인하고, 11/9 이후 바뀐 운영 규칙과 어긋나는 곳을 찾은 뒤 결정 5개를 "선택지 → 추천 → 감수할 점"으로 냈다. 강민은 처음에 다섯 개를 한꺼번에 받아 판단 맥락이 흐려져 보류했고, 메인 세션에서 하나씩 다시 설명을 듣고 골랐다.

## AI 제안
| # | 항목 | 추천 | 다른 선택지 |
|---|---|---|---|
| 1 | 서버 명령 실행 주체 | 읽기·시드·`docker kill/stop/start`는 단계마다 강민 허락 뒤 에이전트가 SSH로 실행, DB 쓰기는 계정 담당 동의 뒤에만 | 절차서대로 계정 담당 실행, 강민이 직접 실행 |
| 2 | F1-b 정지 방법 | Kafka 컨테이너 정지 | reservation 릴레이만 끄기(서버 `docker compose up`이 필요해 금지 규칙에 걸림) |
| 3 | `NOT_SENT` 보이기 | 서버 `kill` 1회로 `APPROVED` 수렴·이중 결제 0을 보이고, `NOT_SENT`는 통합 테스트 4개로 대신 | `kill` 반복, Mock PG 지연(효과 없음) |
| 4 | reservation outbox 경보 | 넓히지 않고 "안 울린 경보"로 기록, `LotterySettlementSlow`가 울리는지 봄 | F1 전에 규칙 추가 후 배포(Mock PG 재생성으로 빌링키 사라짐) |
| 5 | 선점 만료 앞당기기 | 계정 담당 동의 뒤 DB UPDATE 1회, Kafka 약 12분 정지. 동의 없으면 F1-c만 | 앞당기지 않고 Kafka 30분 넘게 정지 |
