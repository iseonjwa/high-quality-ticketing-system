# F1을 측정 모드 없이 하자는 AI 추천을 거부하고, 배포 서버 테스트는 측정 모드를 켜고 팀에 알린 뒤에만 하기로 함

## 맥락
- 해결하려던 작업: ISE-94 F1 장애 주입을 배포 서버에서 진행하던 중이었다. 추첨 23(회차 93, 20석)을 만들고 응모 300건을 넣은 뒤, 16:10 추첨 직후 결제 서버를 자동으로 kill하는 감시 스크립트를 띄워 둔 상태였다(15:54:56 KST).
- AI 활용 방식: F1 준비 세션이 절차서 2절에 "F1은 측정 모드를 켜지 않는다"를 넣었다. 실행 세션은 이것을 다시 따져 보지 않고 따랐다.

## AI 제안
- 측정 모드를 켜지 않는다. 근거는 두 가지였다. 첫째, k6를 쓰지 않아 측정 전용 키가 필요 없다. 둘째, 측정 모드에서는 추적 샘플링이 0.01이라 Zipkin으로 장애 경로를 따라가기 어렵다.
- 빠진 것: 측정 모드는 키와 샘플링만 바꾸는 장치가 아니다. `measure-mode.sh`가 켜고 끌 때 슬랙 `#이선좌-부하측정`으로 자동 알림을 보내 "지금 누가 서버를 쓰는지"를 팀에 알리는 장치이기도 하다(ISE-223, ADR 0046 변경 2026-11-09). 이 역할을 따지지 않았다.

## 판단
- 결과: 거부
- 판단자: kangmin
- 근거: "배포환경에서 테스트하는 거면 무조건 측정모드 키고 팀원들한테 알려야 혼선 안 생겨. 이 과정 무시하고 진행하고 있는 건지 재점검해."
- 검토한 대안: AI 안(측정 모드 끔, 샘플링 1.0 유지). 대가로 추적 샘플링 0.01을 감수한다.

## 반영
- 서버: 15:56:06 KST에 감시 스크립트를 멈췄다. kill은 일어나지 않았다. 추첨 23은 정상 자동결제로 두고, F1 데이터가 아닌 일반 동작 기록으로 남긴다
- 절차서 `docs/design/lottery/f1-fault-injection.md`: 0절 6번, 2절의 측정 모드 줄
- 측정 모드를 켠 뒤 새 회차로 F1-a를 다시 한다

## 검증
- 측정 모드 켬·끔 알림과 스모크 결과는 절차서 7절에 적는다

## 판단 이력
- 2026-11-11 거부: 배포 서버 테스트는 측정 모드 on과 팀 알림이 필수다
