# O1 시나리오 검토 제안 네 가지 중 2~4번은 받아들이되 그림자 폴러는 multi_device에만 두고, 대기 이탈 비용은 별도 실행 대신 계산으로 보기로 함

## 맥락
- 해결하려던 작업: 일요일(11/15) Synthetic O1 측정 전에 `loadtest/k6/scenarios/o1-open-peak.js`가 대기열 서버 동작을 실제와 같게 흉내 내는지 점검했다.
- AI 활용 방식: 대기열 담당이 Linear 댓글로 제안 네 가지를 남겼다. Claude Code가 그 전제를 스크립트, 서버 코드, `o1-synthetic-3000.csv`로 다시 확인하고 제안마다 판단을 추천했다.

## AI 제안
| # | 제안(대기열 담당) | Claude Code 확인·추천 |
|---|---|---|
| 1 | 3,000명·50/s에서는 대기 이탈(`queue_patience_s`)이 작동하지 않는다. 인내 시간은 고치지 않는다 | CSV로 입장 순서를 모의 계산했다. 진입자 2,831명, 최대 대기 44.5초, 이탈 0명이고 폴링 지연 10초를 더해도 2명이다. 제안과 같다 |
| 1-추가 | 줄을 늘린 추가 실행(입장 속도 10/s 또는 진입 1만~3만 명) | 10/s를 추천했다. 같은 계산으로 최대 대기 약 236초, 이탈 137명이다. 진입 수를 늘리면 Gateway CPU 포화 구간에 걸려 원인이 섞인다 |
| 2 | `enter_clicks`를 기기 수로 보고, 기기 수 − 1만큼 그림자 폴러를 둔다 | 부분 수용을 추천했다. refresh_spammer의 `enter_clicks`(2~5)는 한 기기에서 연타한 횟수다. 그래서 그림자 폴러는 multi_device(210명, 2~4번)에만 둔다. 폴링 증가는 약 12%로 추정했고 측정으로 확인한다 |
| 3 | 진입 연타를 `http.batch()`로 한꺼번에 보낸다 | 수용을 추천했다 |
| 4 | 503의 `Retry-After`에 0~20%를 더해 기다리고, 없을 때만 3초 | 수용을 추천했다. 503에만 적용하고 다른 실패는 3초를 유지한다. `QueueExceptionHandler`가 헤더를 넣는 것을 확인했다 |

## 판단
- 결과: 부분 수용(1·3·4 수용, 2는 적용 범위를 좁혀 수용). 추가 실행은 11/13에 10/s를 골랐다가 11/14에 계산으로 대체
- 판단자: kangmin
- 근거: 11/13 "추천대로 진행"(AI 추천 그대로). 11/14 "대기 이탈에 대한 처리가 없는 상황인데 무엇의 효과를 본다는 것인가"라고 되묻고, 계산으로 대체하자는 AI 추천을 골랐다
- 검토한 대안: 진입 수를 10,000~30,000명으로 늘리는 추가 실행, 모든 연타 사용자에게 그림자 폴러를 두는 원안

## 반영
- 2~4번: PR #610(`loadtest/k6/scenarios/o1-open-peak.js`, `loadtest/k6/lib/http.js`).
- 1번: `docs/design/infra/synthetic-data.md` 7절에 비용 계산을 더하고, 10/s 덮어쓰기 파일과 README 절차를 지웠다.

## 검증
- 구현 전. 모의 계산 숫자(이탈 0·2·137명)는 CSV로 계산한 값이다. 실측은 일요일 측정에서 한다.

## 판단 이력
- 2026-11-13 부분 수용: 2~4번 반영, 그림자 폴러는 multi_device에만, 이탈 효과는 10/s 별도 실행으로 본다.
- 2026-11-14 변경: 서버에는 이탈 처리가 없고 입장은 순번 커서(`admit.lua`)라, 떠난 사람 한 명의 비용은 뒤 사람 1 ÷ 초당 입장 인원 지연으로 정해진다. 10/s에서도 마지막 사람 최대 약 14초라 25분짜리 실행 대신 계산으로 갈음한다.

## 발표·면접 포인트
- 동료 검토 제안도 데이터로 다시 확인했다. 같은 열(`enter_clicks`)이 페르소나마다 다른 뜻이라는 점을 찾아 적용 범위를 좁혔다.
- 효과가 안 보이는 변수(인내 시간)를 결과에 맞춰 고치지 않았다. 별도 실행도 서버 코드(입장 커서)를 읽어 결과를 계산할 수 있음을 확인하고 뺐다. 측정은 계산으로 답이 안 나오는 것에 쓴다.
