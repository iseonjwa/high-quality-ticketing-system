# 자율 성능 개선 반복 절차를 AI 검토안대로 보완해 정하고, 판정 기준·종료 조건·커밋·검토 방식을 직접 정함

## 맥락
- 해결하려던 작업: 좌석 선점 성능 개선을 에이전트가 자율로 반복(분석 → 개선안 → 검토 → 적용·측정 → 기록)하게 하는 절차
- AI 활용 방식: 사용자가 쓴 7단계 절차에 빠진 결정이 있는지 검토를 요청했다.

## AI 제안
- 반드시 정할 것: 종료 조건, 판정 기준과 지표 우선순위, 수정 범위(자율·알림·멈춤), 변경 단위·되돌리기(브랜치·로컬 커밋), 측정 신뢰 규칙(같은 시점 번갈아, 편차 안이면 효과 없음)
- 보완: 측정 전 정합성 회귀 관문(전체 테스트·동시성 C1~C7), 독립 검토(별도 에이전트), 기록 위치(작업 메모는 추적 안 함, 결과는 `docs/design/reservation/`), 자율 판단의 기록 방식, 첫 과제(상한의 Tomcat 스레드 고갈, 프론트 재시도 모사), 접수형 포함 여부, 테스트 DB 정리, 중간 보고

## 판단
- 결과: 부분 수용
- 판단자: 최권우
- 근거(사용자 말 요약)
  - 판정: p95 개선, 조회 성공률, 동시 처리 요청 수 증가, 실패율 저하를 종합해서 판단한다. 실제 서비스처럼 정합성과 멱등성, 소비자 경험을 고려한 설계여야 한다.
  - 종료 조건: 반복 5회
  - 수정 범위·기록 방식(8번): 제안대로
  - 커밋: 자율로 진행하고 기존 작업도 커밋한다. ISE-261 위에서 이어 간다.
  - 측정: 변경 전·후를 같은 시점에 번갈아 재고, 편차 안이면 효과 없음. 효과 없는 변경은 비용·위험이 있을 때만 되돌리고, 되돌린 근거를 누구나 납득하게 상세히 쓴다.
  - 검토: 새로 연 세션에 넘겨 할루시네이션을 줄인다.
  - 테스트 DB는 시작 전에 지운다. 반복마다 짧게 보고하고, 이 절차를 다음에도 쓸 수 있게 루트에 추적 안 되는 양식으로 남긴다.
- 검토한 대안: AI가 제안한 지표 우선순위(정합성 → 실패율 → 조회 성공률 → 처리량 → p95)의 엄격한 순서 대신 종합 판단을 택했다.

## 반영
- 루트 양식 `PERF-LOOP-TEMPLATE.md`(추적 안 함), 테스트 DB 픽스처 데이터 정리, 검토 세션 연결 확인
- 반복 기록은 측정 문서에 남긴다.
