# 자동 배정 API contract(ISE-287)를 AI 대조 결과대로 확인 완료로 답하고 후속 제안 세 건을 함께 남김

## 맥락
- 해결하려던 작업: 강민 위임 야간 작업(ISE-264)에서 나온 자동 배정 API(`POST /api/v1/schedules/{scheduleId}/reservations/auto`)에 대해, 좌석 선점 담당으로서 contract 이슈 ISE-287의 확인 요청 세 가지(잠금·멱등 규칙, `409 ZONE_SOLD_OUT`, 프런트 연결 후속)에 답해야 했다. PR #651·#657은 이미 main에 머지된 상태였다.
- AI 활용 방식: 이슈 본문에 적힌 변경 항목이 실제 코드·문서·테스트에 반영됐는지 대조하고, 확인 요청에 대한 답변 초안을 쓰게 했다.

## AI 제안
- 본문의 변경 10가지가 모두 반영됐고 본문과 다르게 된 점은 없다. 테스트는 CI 통과로만 확인했다(로컬 Docker 없음).
- 확인 요청 세 가지 모두 그대로 가도 된다. 자동 배정의 `SKIP LOCKED`는 직접 고르는 선점에서 버린 이유(ADR 0061, TS-73)가 해당하지 않는다.
- 작은 수정 두 가지: `AutoSeatHoldApiTest` 주석의 contracts.md 절 번호(1-3 → 1-2), `ZONE_SOLD_OUT` 메시지의 "구역"을 "범위"로.
- 감수할 점: 매진 직전에 잠깐 잠긴 좌석을 건너뛰어 남은 좌석이 있어도 `ZONE_SOLD_OUT`이 날 수 있다.
- 후속 제안(급하지 않음): 사전 조회 3번을 한 문장으로, 좌석 잠금 뒤 문장 줄이기(ADR 0062 순서), 겹치는 `(schedule_id, section)` 인덱스 정리.
- PR #661 병합이 자동 배정 경로를 건드린 점(동시 처리 상한 적용, `saveReservationSeats` 누락 수정)을 알리고, ADR 0059 채택 시점은 배포 재측정 뒤 담당이 정하게 둔다.
