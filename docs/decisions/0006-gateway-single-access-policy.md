# 0006. 경로별 인증 판정은 Gateway 한 곳에서만 한다

- 상태: 채택 (서비스 단독 방어와 신뢰 모델은 후속 설계)
- 날짜: 2026-10-27
- 결정자: Junhyun An
- 관련 AI 판단: [코드 리뷰 후속 수정 방향 선택](../ai-judgments/junhyun/2026-10-27-review-followup.md)

## 맥락

공개 경로와 관리자 경로 판정이 Gateway의 GatewayAuthenticationFilter와 MVC 서비스의 GatewayIdentityFilter에 따로 있었다. AI 리뷰는 두 곳이 어긋날 위험을 지적하고 공유 상수나 공통 테스트를 제안했다. 사용자는 "왜 둘로 나뉘었는지 모르겠지만 게이트웨이쪽에서 하나의 메서드로 처리하게 해줘"라고 지시했다.

## 결정

공개·로그인 필요·관리자 판정은 Gateway의 `AccessPolicy.of(method, path)` 한 메서드에서만 한다. 패턴은 한 번만 만들고 요청에서는 Gateway가 파싱한 경로를 그대로 비교한다. 라우터와 같은 PathPattern을 쓰므로 인코딩과 matrix parameter 변형도 라우터가 보는 경로로 판정한다.

서비스의 GatewayIdentityFilter는 경로로 판단하지 않는다. 사용자 헤더가 있으면 형식만 검증하고 요청 속성으로 옮긴다. 사용자 정보가 필요한 컨트롤러는 속성이 없으면 401이다. 비밀번호 초기화처럼 민감한 API는 서비스에서도 역할을 확인한다.

## 검토한 대안

- 공유 상수·공통 테스트로 두 곳을 맞추기: AI가 제안했다. 판정 지점이 둘이라는 구조는 그대로라서 사용자가 선택하지 않았다.
- 서비스가 경로 판정을 유지(방어 심층): 어긋날 위험이 있고 서비스마다 같은 규칙을 알아야 한다.

## 결과

판정 규칙이 바뀌면 AccessPolicy와 그 테스트만 고친다. 대신 Gateway를 우회해 서비스에 직접 도달하는 요청은 사용자 헤더만 갖추면 통과한다. 서비스가 Gateway 헤더를 어디까지 신뢰할지와 서비스 단독 방어는 인증 설계·신뢰 모델 논의에서 정하고 별도 ADR로 남긴다.
