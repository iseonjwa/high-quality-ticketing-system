# 0033. 공연장 좌석의 열 번호(row_no)는 정수로 둔다

- 상태: 제안 (좌석 응답 `row` 형식 변경, 좌석 선점 담당 확인 필요)
- 날짜: 2026-10-30
- 결정자: 반효승 (공연·좌석 담당)

## 맥락
- SA MASTER 12-3은 `venue_seats.row_no`를 `VARCHAR(5)`, `seat_no`를 `INT`로 정했고, 좌석 응답 예시도 `"row": "1"`(문자열), `"number": 7`(정수)이었다. 문자열로 둔 이유는 기록에 없다.
- ISE-65 시드는 모든 열을 1~20 숫자로 만든다. 공연장 등록 API는 MVP에 없어 이 시드가 유일한 좌석 배치다.
- 문자열 열 번호는 정렬이 사전순이라 `ORDER BY row_no`가 1, 10, 11, …, 19, 2, 20, 3 순서가 된다. 좌석 배치 조회마다 `row_no::int` 변환을 기억해야 하고, `'3열'`이나 공백 같은 값도 DB가 막지 못한다.
- `V20261029_1__concert_tables.sql`은 10/30 dev에 머지됐다(PR #96). 이미 적용된 환경이 있어 파일을 고치면 Flyway 체크섬 검증이 실패한다.

## 결정
- `row_no`를 `INT`로 바꾼다. 새 마이그레이션 `V20261030_1__venue_seats_row_no_int.sql`에서 `ALTER COLUMN row_no TYPE INT USING row_no::int`로 바꾸고, 시드는 `V20261030_2`로 둔다.
- `VenueSeat.rowNo`를 `int`로 바꾼다.
- 좌석 응답의 `row`를 JSON 정수로 바꾼다(`"row": 1`). SA 11장 좌석 조회·예매 조회 예시를 함께 고친다.

## 검토한 대안
- **문자열 유지 + 조회 시 정렬 변환**: 실제 공연장의 `A열`, `AA열`, `가열` 같은 문자 열 이름을 담을 수 있다. 이 프로젝트는 실제 공연장 배치를 들여오지 않고 숫자 격자 시드 하나만 쓰므로 그 유연성이 필요 없고, 정렬 변환을 빠뜨리는 실수 비용만 남는다.
- **`V20261029_1` 직접 수정**: 이미 머지된 마이그레이션이라 적용된 DB에서 체크섬 불일치로 기동이 실패한다.

## 결과
- 열 번호 정렬·범위 조회가 숫자 그대로 동작하고, 숫자가 아닌 값은 DB가 막는다.
- 문자 열 이름이 필요한 공연장을 들여오면 표시용 컬럼을 따로 추가해야 한다.
- 좌석 응답의 `row` 형식이 바뀌므로 좌석 선점 담당(최권우)과 부하 테스트 스크립트 작성자(권영은)에게 알린다. Notion SA 정본에도 같은 변경을 반영한다.
