## 2. 접속 준비: 공개 키와 개인 키

`ssh-keygen -t ed25519`를 실행하면 `~/.ssh/`에 파일이 **두 개** 생긴다.

| 파일 | 무엇 | 어디에 |
|---|---|---|
| `id_ed25519.pub` | **공개 키**. `ssh-ed25519 AAAA... 이름` 한 줄. 이미 보내 준 것 | 서버에 등록됨. 남에게 줘도 된다 |
| `id_ed25519` (확장자 없음) | **개인 키**. 여러 줄 파일 | 내 컴퓨터에만 둔다. 누구에게도 보내지 않는다 |

- 공개 키는 서버 문에 다는 자물쇠, 개인 키는 그 자물쇠를 여는 열쇠다.
- 2026-11-05에 강민·권우·효승·영은의 공개 키를 배포 서버와 Jenkins 서버에 등록했다.
- 접속 명령의 `-i`에는 **개인 키 파일 경로**를 넣는다. 공개 키 문자열이 아니다.
  - 기본 위치(`~/.ssh/id_ed25519`)에 만들었으면 `-i`를 빼도 된다.
  - 다른 이름으로 만들었으면 그 경로를 넣는다.
  - 내 개인 키가 어디 있는지 모르면 `ls ~/.ssh/`(Windows는 `dir $HOME\.ssh`)로 `.pub`과 이름이 같고 확장자가 없는 파일을 찾는다.
- 서버는 등록된 **IP에서 오는 SSH만** 받는다(AWS 보안 그룹).
  - 집·카페·교육장마다 공인 IP가 다르다. 접속이 갑자기 안 되면 대개 IP가 바뀐 것이다.
  - `curl https://checkip.amazonaws.com`으로 지금 IP를 확인해 담당에게 보내 준다.

## 3. 접속 명령

```bash
# 배포 서버
ssh -i ~/.ssh/id_ed25519 ubuntu@52.63.10.174

# 매번 치기 번거로우면 ~/.ssh/config에 적고 `ssh iseonjwa`로 접속한다
Host iseonjwa
  HostName 52.63.10.174
  User ubuntu
  IdentityFile ~/.ssh/id_ed25519
```

- Windows는 PowerShell의 `ssh`(Windows 10 이상 기본)나 Git Bash를 쓴다. 키 경로는 `C:\Users\<이름>\.ssh\id_ed25519`다.
- 처음 접속할 때 서버 지문을 물으면 `yes`를 입력한다.

**관리 화면은 SSH 터널로 연다.** 관리 화면 포트는 서버 밖에 열려 있지 않다. 터널 명령을 켜 둔 채 브라우저에서 `localhost`로 연다.

```bash
# 배포 서버 관리 화면
ssh -N -L 3000:127.0.0.1:3000 -L 8085:127.0.0.1:8085 -L 9090:127.0.0.1:9090 \
  -L 9093:127.0.0.1:9093 -L 9411:127.0.0.1:9411 iseonjwa
```

| 화면 | 주소 |
|---|---|
| Grafana | `http://localhost:3000` |
| Kafka-UI(읽기 전용) | `http://localhost:8085` |
| Prometheus | `http://localhost:9090` |
| Alertmanager | `http://localhost:9093` |
| Zipkin | `http://localhost:9411` |

```bash
# Jenkins 화면
ssh -i ~/.ssh/id_ed25519 -N -L 8081:127.0.0.1:8080 ubuntu@3.107.168.36
```

- 브라우저에서 `http://localhost:8081`로 연다.
- Jenkins 로그인 계정은 `admin` 하나다. 비밀번호는 담당에게 개인 메시지로 받는다.

## 4. 서버에서 지킬 것

`ubuntu` 계정은 `sudo`와 `docker` 권한이 있어 무엇이든 할 수 있다. 그래서 다음은 하지 않는다.

| 하지 않는다 | 이유 |
|---|---|
| `docker compose down -v`, `docker volume rm` | DB·Kafka 데이터가 지워진다 |
| 서버에서 직접 `deploy.sh`, `git checkout`, `docker compose up` | 배포는 main 머지 → Jenkins로만 한다. 손으로 바꾸면 기록(`.deploy/current`)과 실제 상태가 어긋난다 |
| `.env` 열기·복사·공유 | 운영 비밀값이 있다 |
| `~/.ssh/authorized_keys` 수정 | 다른 사람과 Jenkins의 접속이 끊길 수 있다 |
| 배포 서버에서 k6 실행 | 부하 도구가 서버 자원을 나눠 써서 측정이 왜곡된다(5절) |

- 해도 되는 것은 읽기 위주다.
  - `docker ps`
  - `docker logs -f iseonjwa-reservation-service-1`
  - `docker stats`
  - 터널로 Grafana·Zipkin 보기
- 컨테이너 재시작이 필요하면 팀 채널에 먼저 알린다.

### 5-2. 배포 서버 측정 방식
- **k6는 배포 서버에서 돌리지 않는다.**
  - 측정할 때만 배포 서버와 같은 VPC·같은 가용 영역에 **임시 발생기 EC2**를 띄우고, 끝나면 지운다(ADR 0046).
  - AWS 콘솔은 계정 주인만 쓰므로 발생기는 측정 시간이 정해지면 안준현이 만든다. 절차는 [`load-test.md`](../design/infra/load-test.md) 2-1절이다.
- **발생기에서 부르는 곳**
  - Gateway 사설 주소 `http://172.31.4.93:8080`을 부른다. 프론트 nginx는 거치지 않는다.
  - 배포 서버 보안 그룹은 측정 중에만 발생기 보안 그룹에서 오는 8080을 연다.
- **k6 실행 방식**
  - 설치하지 않고 Docker 이미지 `grafana/k6:1.0.0`으로 한 번 실행한다. K1 스크립트(`reservation-service/k6/run.sh`)와 같은 방식이다.
  - 발생기에서 `BASE_URL=http://172.31.4.93:8080`만 바꿔 쓴다.
- **노트북에서 배포 서버로 큰 부하를 쏘지 않는다.**
  - 한국–시드니 왕복이 약 0.27초라 결과에 네트워크가 섞인다.
  - 스크립트 확인이나 시연 수준의 작은 부하는 괜찮다.
- **측정하는 동안에는 main 릴리스를 하지 않는다.** Jenkins가 측정 중에 배포를 시작한다.

### 5-4. 서버 측정 전에 남은 것
- **토큰 준비**
  - 가상 사용자 Access 토큰과 입장 토큰을 어떻게 만들지 정한다.
  - 지금 입장 속도(`queue.admit-per-second` 50)와 입장 토큰 유효 시간(10분)으로는 3만 명분을 미리 받을 수 없다.
  - 운영 키로 서명하는 방식은 키 노출 위험이 있어 정하지 않았다.
- **`loadtest` 프로필**: 입장 속도·토큰 유효 시간 덮어쓰기와 Mock PG `local,loadtest`(ISE-71)가 필요하다.
- **결과 보기**: k6 결과를 Prometheus remote write로 Grafana에 넣을지 정한다. 정하기 전에는 결과 파일(요약 JSON, CSV)로 남긴다.
- **측정 환경 기록표**: [`load-test.md`](../design/infra/load-test.md) 7절 양식을 측정마다 채운다.
