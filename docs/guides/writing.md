# 문서 작성 가이드

문서, 코드 주석, 커밋·PR 본문, 에이전트가 남기는 기록에 모두 적용한다. 무엇을 어디에 쓰는지는 [문서 지도](../README.md)를 본다. 물류 관리 프로젝트(3조)의 같은 문서를 줄여서 옮겼다.

## 1. 사실 기반으로 쓴다
- 실제 코드와 실행 결과를 기준으로 쓴다. 추측으로 빈칸을 채우지 않는다.
- 확인하지 않은 내용은 "미확인"이라고 적는다. 원인을 찾지 못했으면 "원인: 미확인"으로 쓴다.
- "완료", "통과"라고 쓸 때는 실행한 명령과 결과를 함께 적는다.
- 버전마다 다른 내용은 근거(공식 문서 주소, 실행 결과)를 함께 적는다.
- 사실, 관찰, 추측, 결정을 한 문장에 섞지 않는다. 결정이면 누가 언제 정했는지 적는다.

## 2. 간결하게 쓴다
- 첫 문장에 결론을 쓴다. 설명은 "결론 → 이유 → 이 프로젝트에서는 → 더 깊이" 순서로 쓴다.
- 한 문장에는 한 가지만 쓴다. 문단은 세 문장 안쪽으로 쓴다.
- 같은 기준으로 여러 항목을 비교할 때만 표로 쓴다. 순서가 있는 절차는 번호 목록으로 쓴다. 항목이 둘이면 불릿 대신 문장으로 쓴다.
- 굵은 글씨는 꼭 놓치면 안 되는 곳에만 쓴다. 문단마다 굵은 머리말을 달지 않는다.
- 같은 내용을 두 곳에 쓰지 않는다. 기준 위치 한 곳에 쓰고 다른 곳은 링크한다.
- 수치는 단위와 함께 쓴다. "빠르다" 대신 "17초"처럼 쓴다.

## 3. 톤
- 한국어 평서체로 쓴다.
- AI 말투(과한 공감, 감탄, "좋은 질문입니다" 같은 서두, 장황한 요약)와 이모지를 쓰지 않는다.
- 문서만 읽어도 이해되게 쓴다. "위에서 말한", "아까" 같은 대화 맥락에 기대지 않는다.
- 정의문("~는 ~이다")을 늘어놓지 않는다. 이 폴더에 무엇을 두는지, 언제 쓰는지로 쓴다.

## 4. 문서가 커질 때
- 한 파일이 300줄을 넘기거나 주제가 둘 이상 섞이면 주제별 파일로 나누고 상위 `README.md`에 목차를 둔다.
- 결정 기록은 한 결정에 한 파일이다.
- 지난 내용은 지우지 않고 상태를 바꾼다. 결정이 바뀌면 이전 ADR에 `대체됨`을 표시한다.
