# 공연 목록 조회는 어떤 순서로 데이터를 모으고, 화면은 그 응답을 어떻게 쓰나

## 질문
공연 목록 조회(ISE-99)는 공연을 id 내림차순으로 한 페이지 읽고, 공연 id를 뽑아 회차를 시작 시각 오름차순으로 읽어 Map에 담는다. 이 흐름이 맞나? 여러 공연의 회차가 한 목록에 섞이지 않나? 화면에서 어떻게 쓰길래 이런 모양으로 보내나?

## 답

### 1. 흐름 (`ConcertQueryService.getConcerts`)
1. `concertRepository.findPage(page, size)`: id 내림차순으로 한 페이지를 읽는다. 정렬과 자르기는 DB가 한다(`ORDER BY id DESC LIMIT size OFFSET page*size`).
2. `concertRepository.count()`: 전체 공연 수를 센다. 화면이 페이지 번호를 몇 개 그릴지 정하는 데 쓴다.
3. stream으로 공연 id만 뽑는다. 정렬은 하지 않는다.
4. `findUpcomingByConcertIds(ids, now)`: 그 공연들의 회차 중 **아직 시작하지 않은 것만**(`startsAt > now`) 시작 시각 오름차순으로 한 번에 읽는다. 정렬은 DB가 한다.
5. 회차를 돌면서 `putIfAbsent(공연 id, 회차)`로 공연마다 첫 회차 하나만 남긴다.
6. 응답은 공연 목록 순서(id 내림차순)대로 만들고, 각 공연의 다음 회차를 Map에서 꺼내 붙인다.

### 2. 회차가 섞이는데 왜 맞나
4번 결과는 공연 id가 섞여 있다. 공연 구분 없이 시작 시각 하나로만 정렬했기 때문이다.

```
페이지 공연: 10, 9, 8
회차 조회 결과 (startsAt 오름차순, 공연이 섞여 있다)
  공연 10  11/05
  공연 8   11/07
  공연 10  11/09   <- 공연 10은 이미 Map에 있어서 무시
  공연 8   11/20   <- 무시
  (공연 9는 남은 회차 없음)
```

전체가 시작 시각 오름차순이면, 어느 공연이든 **그 공연이 처음 등장한 줄이 그 공연의 가장 빠른 회차**다. 그래서 섞여 있어도 `putIfAbsent`(키가 없을 때만 넣는다)로 첫 줄만 남기면 된다.

```
Map: {10 → 11/05 회차, 8 → 11/07 회차}
```

- `HashMap`에는 순서가 없지만 상관없다. 순서는 1번의 공연 목록이 정하고, Map은 공연 id로 꺼내기만 한다.
- 9번 공연은 Map에 없어서 `get`이 null이고, 응답에서 `nextStartsAt`·`nextOpenAt`이 null이 된다.

### 3. 왜 공연마다 따로 조회하지 않나
공연 20개마다 회차 쿼리를 하나씩 보내면 1 + 20번 쿼리가 나간다(N+1). 공연 id를 모아 `IN`으로 한 번에 읽으면 쿼리가 3번(공연 페이지, count, 회차)으로 고정된다.

### 4. 화면은 아직 없다
- SA 2-4: MVP 시연은 화면 없이 API 호출로 하고, 화면은 MVP 이후에 붙인다.
- SA 6-8: 최소 화면은 AI 도구로 만든다(담당 안준현). 흐름은 로그인 → 공연 상세(카운트다운) → 대기열 → 좌석 배치도 → 결제 → 결과·내 예매다.
- SA 11장이 정한 목록 응답은 `{content: [{concertId, title, nextStartsAt, nextOpenAt}], page, size, totalElements}`다.

그래서 아래 화면은 SA 응답 필드로 짐작한 것이다.

```
 공연 목록                                      [1] 2 3 >
 ┌──────────────────────────────────────────────┐
 │ 이선좌 콘서트 2026                              │
 │ 다음 공연 11/20(금) 19:00 · 예매 오픈 11/01 20:00 │  <- nextStartsAt, nextOpenAt
 ├──────────────────────────────────────────────┤
 │ 가을 앙코르                                     │
 │ 예정된 공연 없음                                 │  <- 둘 다 null
 └──────────────────────────────────────────────┘
```

- 목록은 "무슨 공연이 있고, 가장 가까운 공연·예매가 언제인가"만 보여 준다. 회차 전체와 판매 상태는 상세 화면(`GET /concerts/{id}`)이 맡는다.
- `totalElements`와 `size`로 페이지 수를 계산한다(예: 45개 ÷ 20 = 3페이지).
