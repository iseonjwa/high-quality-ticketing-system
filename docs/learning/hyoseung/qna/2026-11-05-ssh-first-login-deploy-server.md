# 배포 서버에 SSH로 처음 들어갈 때 무슨 일이 일어났나

## 질문

`ssh ubuntu@52.63.10.174`로 배포 서버에 들어갔다. 이건 왜 한 것이고, 그동안 무슨 일이 일어났나.

## 답

### 왜 했나

준현이 배포 서버(11/6 리허설까지 켜 두고 11/7~12 중지)에 팀원 공개 키를 등록했다. 서버가 꺼지기 전에 내 키로 실제로 들어가지는지 확인하려고 한 것이다. 들어가면 로그(`docker logs`)와 자원 사용(`docker stats`)을 직접 볼 수 있고, 관리 화면(Grafana 등)은 SSH 터널로 연다.

### 일어난 일 세 가지

1. **서버가 진짜인지 확인 (호스트 키)**
   - `The authenticity of host ... can't be established`와 `ED25519 key fingerprint is SHA256:SyU3...`는 서버가 자기 신분증(호스트 키)을 내민 것이다.
   - 처음 접속이라 내 컴퓨터에 이 서버의 기록이 없어서 물었다. `yes`를 하면 `~/.ssh/known_hosts`에 저장한다(`Permanently added`).
   - 다음부터는 저장한 값과 비교한다. 같은 주소인데 신분증이 바뀌면 경고하고 접속을 막는다. 누군가 중간에서 서버인 척하는 것(중간자 공격)을 막는 장치다.
   - 엄밀히는 처음 `yes` 전에 지문을 서버 관리자(준현)에게 받은 값과 비교해야 한다.
2. **내가 누구인지 증명 (공개 키 인증)**
   - 서버의 `~/.ssh/authorized_keys`에 내 공개 키(자물쇠)가 있다. 내 컴퓨터는 개인 키(열쇠, `~/.ssh/id_ed25519`)로 서명해 그 자물쇠에 맞는 열쇠를 가졌음을 증명한다. 개인 키 자체는 보내지 않는다.
   - 기본 위치의 키라 `-i`를 생략해도 됐고, 비밀번호를 묻지 않았다.
   - 서버 보안그룹은 등록된 IP에서만 22번 포트를 연다. IP가 바뀌면 키가 맞아도 접속이 안 된다.
3. **서버 셸에 들어감**
   - 프롬프트가 `ubuntu@ip-172-31-4-93:~$`로 바뀌었다. 이제 입력하는 명령은 내 노트북이 아니라 서버에서 실행된다.
   - `172.31.4.93`은 VPC 안에서만 쓰는 사설 주소다. 부하 발생기 EC2가 Gateway를 부를 때 쓰는 `BASE_URL=http://172.31.4.93:8080`이 이 주소다. `52.63.10.174`는 밖에서 들어오는 공인 주소다.

### 큰 그림과 아이디·비밀번호 비유

- 배포 서버는 AWS에서 빌린 컴퓨터(EC2) 한 대다. 우리 서비스 컨테이너 20개가 전부 여기서 돈다(`docker stats`로 확인).
- 문이 두 겹이다. 바깥문은 보안그룹(허용한 IP만 22번 포트로 들어옴), 안쪽 문은 SSH 키(등록된 공개 키에 맞는 개인 키를 가진 사람만 로그인).
- `id_ed25519.pub`의 pub은 public(공개)이다. 남에게 줘도 되는 자물쇠다. `id_ed25519`는 private(개인) 키, 열쇠다. 절대 보내지 않는다.
- 비유로는 `ubuntu`가 아이디, 개인 키가 비밀번호 역할이다. 다만 비밀번호와 달리 개인 키는 서버로 전송되지 않고 서명으로만 증명한다. IP는 자격 증명이 아니라 출입 허용 명단이다.
- 2026-11-05 확인한 서버의 reservation-service 메모리 상한은 1.125GiB였다. ISE-79 측정의 "배포 메모리" 조건(컨테이너 1,152MB)과 같다.

### 서버에서 지킬 것 (준현 공지)

- 해도 되는 것: `docker ps`, `docker logs`, `docker stats`
- 하지 않는 것: `docker compose down -v`, `docker volume rm`, 직접 배포·`git checkout`·`compose up`, `.env` 열기, `authorized_keys` 수정, k6 실행. 컨테이너 재시작은 채널에 먼저 알린다.
- 나갈 때는 `exit`.
