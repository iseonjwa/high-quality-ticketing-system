# 부하 테스트는 앞 단계까지 한 묶음으로 돌리나, 한 API만 돌리나

## 질문

부하 테스트는 특정 기능을 하려고 앞 단계까지 한 묶음으로 실행하는 것이 맞나. 그런데 사전 작업이 없는 API는 그것만 테스트하나.

## 답

둘 다 쓴다. 사전 작업이 없는 것은 공연 상세(공개 API)다. 좌석 조회는 access 토큰과 입장 토큰이 필요하다.

| | 구간 단독 | 흐름 전체 |
|---|---|---|
| 하는 일 | 한 API에만 부하. 앞 단계는 측정 밖에서 준비 | 조회 → 대기열 → 토큰 → 좌석 → 선점 → 결제를 순서대로 |
| 알 수 있는 것 | 그 API 혼자의 한도 | 서비스 전체가 버티나, 어디서 먼저 막히나 |
| 우리 팀 | B1, Q1, K1, PAY1 등 | O1 |

- 단독이 필요한 이유: 흐름 전체에서는 앞 구간이 막히면 뒤 구간에 요청이 가지 않는다. 좌석 조회가 막힌 K1에서 선점 개선이 "0건 → 0건"으로 보였다(`open-peak-load-plan.md`). 구간별 한도를 따로 재고, 개선을 합친 뒤 O1로 최종 확인한다(같은 문서 4절 순서).
- 앞 단계 준비 방법: (1) `setup()`에서 실제 흐름으로 받는다. 측정 전에 한 번 돌고 결과에 섞이지 않는다. 사용자를 많이 만들기 어렵다. (2) 토큰을 직접 서명한다(최권우 방식, local 전용).
- ISE-189는 좌석 조회 한 건의 비용을 줄이는 일이라 효과도 좌석 조회 단독으로 잰다.
