# 부하 테스트는 무엇을 보려는 것이고, k6 대시보드는 무엇인가

## 질문

1. 대시보드를 끄자마자 요약표가 나왔다. 대시보드는 무엇인가.
2. 부하 테스트는 실패하는 지점까지 많이 보내는 것이 목적인가.

## 답

### k6 web dashboard

- Grafana의 k6 확장(`xk6-dashboard`)이 k6 v0.49부터 기본 기능이 됐다. 별도 프로그램이 아니라 k6 프로세스 안의 작은 웹 서버다.
- `K6_WEB_DASHBOARD=true`면 5665 포트에 페이지를 열고 측정 수치를 흘려보낸다.
- 브라우저가 붙어 있는 동안 k6가 끝나지 않는다. 2026-11-06 RATE=50 실행에서 탭을 닫자 요약표가 나왔다.

### 부하 테스트의 종류

| 종류 | 묻는 것 | 우리 프로젝트 |
|---|---|---|
| 부하 | 예상 트래픽에서 목표(p95 등)를 지키나 | 구간별 예상치(좌석 조회 초당 50~150건) |
| 스트레스 | 어디까지 버티나, 넘으면 어떻게 무너지나 | 좌석 조회는 초당 10명에서 무너짐(최권우 P0'') |
| 스파이크 | 갑자기 몰릴 때 버티나 | 티켓 오픈 순간 |
| 장시간(soak) | 오래 돌리면 새거나 느려지나 | 범위 밖 |

- 실패 지점을 찾는 목적은 그 지점에서 먼저 바닥나는 자원(병목)을 찾는 것이다. 좌석 조회는 DB가 아니라 메모리·GC가 먼저 바닥나 P4a로 고칠 곳이 정해졌다.
- 흐름: 목표 확인 → 한계 찾기 → 원인 찾기 → 개선 → 같은 조건으로 다시 재기.

### 공연 상세 측정 (local, k6 v2.3.0)

| RATE | 실제 /s | 실패 | p95 | VU 최대 |
|---|---|---|---|---|
| 10 | 10.03 | 0% | 9.53ms | 1 |
| 50 | 50.02 | 0% | 7.15ms | 1 |

속도를 올렸는데 p95가 줄었다. 앞선 실행으로 JVM이 데워지고 연결이 재사용됐기 때문으로 본다(해석). 측정 전 워밍업을 두는 이유다.
