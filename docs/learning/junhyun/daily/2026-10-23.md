## 배운 것
- **서비스 경계는 정합성 범위로 먼저 정한다**: "한 좌석은 한 번만 팔린다"를 한 트랜잭션에서 지키려고 좌석·예매·발권을 한 서비스에 둔다 — [qna/2026-10-23-ticketing-service-boundaries.md](../qna/2026-10-23-ticketing-service-boundaries.md)
- **분리 근거는 공유 인프라까지 따져야 성립한다**: Queue를 떼도 Redis·Gateway를 공유하고 입장 토큰 발급이 임계 경로에 있어 장애 격리는 되지 않는다. 성립하는 근거는 독립 확장과 입장 관문이다 — 같은 노트, [sa-review/01](../../../sa-review/01-sa-1st-review.md)
- **대기열은 메시지 큐가 아니라 Redis Sorted Set으로 만든다**: 순번 조회(`ZRANK`), 중복 진입 방지, 중간 이탈(`ZREM`)이 필요하다. RabbitMQ는 발제 필수가 아니다 — [qna/2026-10-23-waiting-queue-redis-vs-rabbitmq.md](../qna/2026-10-23-waiting-queue-redis-vs-rabbitmq.md)
- **알림 서비스는 보내는 주체가 둘 이상일 때 뗀다**: 이벤트 구독형이라 결합이 적고, 알림 장애가 거래로 번지지 않는다 — [qna/2026-10-23-notification-service-scope.md](../qna/2026-10-23-notification-service-scope.md)
- **PG 타임아웃은 실패가 아니라 "결과 모름"이다**: 국내 PG는 read-timeout이면 망취소, 토스는 멱등키 재시도와 주문번호 조회로 정리한다 — [sa-review/02](../../../sa-review/02-pg-timeout-handling.md)
- **Kafka 파티션 순서를 정합성 수단으로 쓰지 않는다**: 회차 ID 키는 인기 회차가 한 파티션에 몰리고, 좌석 ID 키는 여러 좌석을 한 번에 잡는 요청의 원자성이 깨진다. 정합성은 Redis·DB가 지키고 키는 userId로 분산한다 — [sa-review/03](../../../sa-review/03-seat-hold-kafka-design.md)
- **Outbox는 DB 쓰기가 있는 곳에만 맞는다**: 접수 API는 DB에 쓰지 않으므로 발신 유실은 `acks=all`과 send 결과 확인으로 막는다 — 같은 문서
