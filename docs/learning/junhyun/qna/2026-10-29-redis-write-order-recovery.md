# Redis에서 두 곳을 지울 때 순서가 왜 중요한가 (대기열 만료 정리 사례)

## 질문
PR #91 리뷰 결과 중 "정리 Lua가 `issued`를 지운 뒤 `waiting` ZREM 전에 에러가 나면, 옛 seq만 남아 `READY`가 다시 나가고 새 토큰이 발급된다. 결정 6이 막으려던 틈이 정리 경로에서 다시 열린다"가 무슨 뜻인가. Lua, ZREM이 무엇이고 어떤 상황인지 쉽게 설명해 달라.

## 짧은 답
상태를 두 곳에 나눠 저장하면, 둘을 고치는 도중에 멈출 경우를 대비해 순서를 정해야 한다. 이 설계에서 `issued`(이미 토큰을 받았다는 기록)는 "`waiting`의 옛 번호표를 믿지 말라"는 표시 역할을 한다. 그래서 발급할 때는 `issued`를 먼저 쓰고, 지울 때는 `issued`를 마지막에 지워야 중간에 멈춰도 안전하다. 만료 정리 경로는 이 순서가 정해져 있지 않다는 것이 리뷰 지적이다.

## 자세히
### 용어
- `waiting`: 줄 명단. Redis Sorted Set이고 번호표(seq)가 점수다.
- `issued`: 입장 토큰을 받은 사람의 기록부(발급 시각 포함).
- `admitted`: 입장해도 되는 마지막 번호표를 나타내는 숫자.
- ZREM: Sorted Set에서 멤버를 지우는 명령.
- Lua 스크립트: Redis 안에서 명령 여러 개를 묶어 중간에 다른 요청이 끼어들지 못하게 실행하는 작은 프로그램. 자세한 내용은 [Redis Lua 노트](2026-10-26-redis-lua-script.md).

### 판정 규칙
1. `issued`에 유효한 기록이 있으면 이미 토큰을 받은 사람이다(같은 토큰을 다시 준다).
2. 아니고 seq ≤ `admitted`이면 `READY`다(토큰을 받을 수 있다).

### 발급 순서 (결정 6)
`issued` 기록 → `waiting` 제거 순서다. 중간에 멈추면 두 곳에 모두 남는데, 항상 `issued`를 먼저 보므로 다음 요청에서 스스로 정리된다. 반대 순서였다면 중간에 멈출 때 어디에도 이름이 없어 입장 자격이 사라진다.

### 만료 정리의 문제 (리뷰 M1)
토큰이 만료되면 정리 Lua가 `issued`와 `waiting`에서 이름을 지운다. 순서가 정해져 있지 않아 `issued`를 먼저 지우고 `waiting` ZREM 전에 에러가 나면:
- `waiting`에 옛 seq(≤ `admitted`)만 남고 `issued` 기록은 없다.
- 순번 조회가 규칙 2에 따라 `READY`를 준다.
- 토큰 API가 새 발급 시각으로 새 토큰을 발급한다.
- 만료된 사람은 줄 맨 뒤부터 다시 서야 하는데 공짜로 새 토큰을 받는 새치기가 된다.

수정안은 지우는 순서를 `waiting` → `issued`로 하는 것이다. 중간에 멈춰도 `issued`가 남아 있어 "이미 받았던 사람"으로 판정되고, 다음 정리에서 마저 지워진다.

### 현실적인 확률
Redis는 클라이언트 연결이 끊겨도 스크립트를 끝까지 실행한다. 런타임 에러가 나면 이미 한 쓰기를 되돌리지는 않는다. 중간에 멈추는 실제 조건은 Lua 코드 버그로 인한 런타임 에러다. 그래서 자주 터지는 장애보다는, 순서를 지켜 버그의 피해를 작게 만드는 방어 설계에 가깝다.

### 일반 원칙
- 두 곳을 함께 바꿔야 하면 "중간에 멈췄을 때 어느 쪽이 남아야 안전한가"를 먼저 정한다.
- 생성할 때는 안전장치(차단 표시)를 먼저 쓰고, 삭제할 때는 안전장치를 마지막에 지운다.
- 이 설명은 리뷰어 에이전트의 서술에 기반하며, 정확한 키와 자료구조는 ADR 0031, SA MASTER 12-8 원문으로 확인해야 한다.

## 이 프로젝트에서는
- PR #91의 ADR 0031 결정 6(발급 순서), 결정 7(만료 처리), SA 12-8의 진입 ③·토큰 발급 만료 분기·1초 정리가 해당한다.

## 면접 포인트
- 두 저장소(또는 두 키)를 함께 갱신할 때 부분 실패를 어떻게 다루는가? → 순서를 정해 중간 상태가 안전하게 복구되도록 하고, 가능하면 하나의 원자적 단위(Lua, 트랜잭션)로 묶는다.
- Redis Lua는 원자적인데 왜 순서까지 신경 써야 하나? → 스크립트 안에서 런타임 에러가 나면 이미 실행한 명령은 되돌려지지 않는다(롤백 없음).
