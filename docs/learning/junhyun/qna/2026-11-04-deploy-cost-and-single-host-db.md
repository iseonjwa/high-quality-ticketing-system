# 배포 EC2 요금은 얼마이고, DB까지 한 인스턴스에 띄우는 설계인가

## 질문
배포 서버(16GB급)와 Jenkins 서버를 만들기 전에 요금을 계산해 달라. 그리고 지금 DB도 하나의 인스턴스에서 띄우는 설계인가.

## 짧은 답
- 두 서버를 계속 켜 두면 하루 약 6.8달러, M4 마감(11/16)까지 12일이면 약 82달러다. 요금은 크레딧에서 먼저 빠진다.
- 그렇다. SA 9-1대로 배포 EC2 한 대의 docker compose 안에서 앱 8개와 PostgreSQL 3개, Redis, Kafka, 관측 도구까지 컨테이너로 함께 띄운다. 데이터는 그 EC2 디스크(EBS)의 docker 볼륨에 있다.

## 자세히

### 1. 요금 계산 (2026-11-04, 아시아 태평양(시드니), 온디맨드 Linux)
값은 AWS 공식 가격 데이터(EC2 온디맨드, EBS)에서 읽었다. 공인 IPv4는 모든 리전에서 주소 하나에 시간당 0.005달러다.

| 항목 | 단가 | 하루 | 한 달(730시간) |
|---|---|---|---|
| 배포 서버 `m7i-flex.xlarge`(4 vCPU, 16GiB) | 시간당 0.2394달러 | 5.75달러 | 174.8달러 |
| Jenkins 서버 `t3.small`(2 vCPU, 2GiB) | 시간당 0.0264달러 | 0.63달러 | 19.3달러 |
| 공인 IPv4 2개(배포 탄력적 IP, Jenkins) | 개당 시간당 0.005달러 | 0.24달러 | 7.3달러 |
| EBS gp3 60GiB(40 + 20) | GiB당 월 0.096달러 | 0.19달러 | 5.8달러 |
| 합계 | 시간당 약 0.284달러 | 약 6.81달러 | 약 207달러 |

- 같은 16GiB의 다른 유형: `m6i.xlarge` 시간당 0.24달러, `m7i.xlarge` 0.252달러, `t3.xlarge` 0.2112달러.
- `t3.xlarge`가 가장 싸다(12일 약 74달러). 다만 CPU 크레딧으로 기준 성능(vCPU당 40%)을 넘겨 쓰는 버스트형이다. 부하 측정처럼 CPU를 오래 쓰면 추가 요금이 붙거나 측정값이 흔들린다. 그래서 측정까지 할 배포 서버는 `m7i-flex.xlarge`를 고른다.
- 8GiB급 `m7i-flex.large`는 시간당 0.1197달러로 절반이지만, 컨테이너 상한 합계(약 12GB)가 들어가지 않는다.
- 아끼는 법: 시연·측정이 없는 시간에 배포 서버를 멈춘다. 하루 12시간만 켜면 12일 약 47달러다. 멈춰도 EBS와 공인 IPv4는 과금된다. 인스턴스를 "종료"하면 디스크(EBS)가 같이 지워져 DB 데이터가 사라지므로 "중지"를 쓴다.
- 인터넷으로 나가는 데이터는 매달 100GB까지 무료라 시연 트래픽은 무시할 만하다. GHCR에서 이미지를 받는 것은 들어오는 트래픽이라 무료다.
- Paid plan의 지출 한도를 걸면 한도를 넘었을 때 프로젝트가 멈춘다. 시연 중에 멈추지 않게 예상치(12일 약 82달러)보다 넉넉히 잡는다.

### 2. DB를 한 인스턴스에 두는 설계
- 근거: SA 9-1(EC2 한 대 docker compose), SA 9-3(메모리 예산, 단일 EC2 한계). 10/26 피드백 답변에서 "프로젝트 범위에서는 컨테이너 분리까지만 한다"고 정했다.
- 서비스마다 DB는 따로다(user, reservation, payment 각자의 PostgreSQL 컨테이너). 서비스 경계는 지키고, 같은 호스트에 함께 띄울 뿐이다.

| | 한 인스턴스(지금) | 매니지드 서비스로 분리(운영이라면) |
|---|---|---|
| 구성 | 앱·PostgreSQL·Redis·Kafka가 모두 배포 EC2의 컨테이너 | RDS(PostgreSQL), ElastiCache(Redis), MSK(Kafka) |
| 비용 | 인스턴스 하나 | 서비스마다 추가 요금 |
| 장애 | 인스턴스가 죽으면 전체가 멈춘다 | DB는 다중 AZ로 버틴다 |
| 백업 | 직접 해야 한다(지금 없음) | 자동 백업·시점 복구 |
| 자원 | 앱과 DB가 CPU·메모리를 나눠 써서 부하 측정 값에 영향 | 서로 영향이 적다 |

- 데이터 위치: docker 볼륨이 배포 EC2의 EBS에 있다. 인스턴스를 중지·시작해도 남고, 종료하면 사라진다. 시연 데이터는 시드 스크립트(ISE-177)로 다시 만들 수 있어서 백업을 두지 않았다.

## 이 프로젝트에서는
- 배포 서버 `m7i-flex.xlarge` + Jenkins `t3.small`로 만든다(`docs/design/infra/deployment.md` 5절 서버 준비 순서).
- 리허설(11/6)과 시연이 끝나면 배포 서버를 중지해 비용을 줄인다. 프로젝트가 끝나면 인스턴스·EBS·탄력적 IP를 지운다(탄력적 IP는 인스턴스에 연결하지 않아도 과금된다).

## 면접 포인트
- 단일 호스트에 DB까지 두는 것은 비용과 범위를 위한 선택이고, 대가는 단일 장애 지점·자원 경쟁·백업 부재다. 운영으로 가면 상태를 가진 구성 요소(DB·캐시·브로커)부터 매니지드 서비스로 뺀다.
- 버스트형 인스턴스(t 계열)는 평소엔 싸지만 기준 성능을 넘겨 오래 쓰면 크레딧 비용이 생기고 성능이 흔들려, 부하 측정 서버에는 고정 성능 인스턴스를 쓴다.
