# EC2에 탄력적 IP(Elastic IP)는 어떻게 할당하나

## 질문
EC2에 탄력적 IP 어떻게 할당해?

## 짧은 답
탄력적 IP는 "주소를 먼저 받고(할당), 인스턴스에 붙이는(연결)" 두 단계다. 콘솔에서 EC2 → 네트워크 및 보안 → 탄력적 IP → "탄력적 IP 주소 할당"을 누르고, 만든 주소를 선택해 "탄력적 IP 주소 연결"에서 인스턴스를 고른다. 인스턴스를 멈췄다 켜도 공인 IP가 바뀌지 않는 것이 목적이다.

## 자세히

**콘솔**
1. 리전을 인스턴스와 같은 곳으로 맞춘다(탄력적 IP는 리전 단위다. 이 프로젝트는 시드니 `ap-southeast-2`).
2. EC2 → 탄력적 IP → "탄력적 IP 주소 할당" → 기본값(Amazon의 IPv4 주소 풀) → 할당.
3. 방금 만든 주소를 선택 → 작업 → "탄력적 IP 주소 연결" → 리소스 유형 인스턴스, 대상 인스턴스 선택, 프라이빗 IP는 기본값 → 연결.
4. 인스턴스 상세의 "퍼블릭 IPv4 주소"가 그 주소로 바뀐 것을 확인한다.

연결 화면의 "프라이빗 IP 주소"는 인스턴스를 고르면 자동으로 채워지는 기본 프라이빗 IP를 그대로 둔다. "재연결 허용"은 이미 다른 곳에 연결된 주소를 옮길 때만 체크한다.

**CLI**
```bash
aws ec2 allocate-address --domain vpc --region ap-southeast-2
# 출력의 AllocationId(eipalloc-...)를 쓴다
aws ec2 associate-address --instance-id i-xxxxxxxx --allocation-id eipalloc-xxxxxxxx --region ap-southeast-2
```

**주의할 점**
- 연결하면 기존 자동 공인 IP는 풀려서 사라지고, 접속 주소가 탄력적 IP로 바뀐다. SSH 접속 중이면 끊기니 새 주소로 다시 접속한다.
- 요금: 2024년부터 AWS는 공인 IPv4 주소마다 시간당 요금을 받는다(탄력적 IP가 인스턴스에 연결돼 있어도 부과, 연결 안 된 주소도 부과). 프리 티어 대상 여부와 현재 단가는 청구 문서에서 확인한다.
- 쓰지 않으면 반드시 "탄력적 IP 주소 해제"를 한다. 해제하지 않으면 요금이 계속 나온다.
- 한 리전에 기본 5개까지 할당할 수 있다(상한 증가 요청 가능).
- 인스턴스를 종료(삭제)해도 탄력적 IP는 자동으로 해제되지 않는다. 직접 해제한다.

## 이 프로젝트에서는
- 배포 EC2에는 서버 준비 순서 1단계에서 탄력적 IP를 붙인다고 정했다(`docs/design/infra/deployment.md` "서버 준비 순서"). 주소가 바뀌지 않아야 SSH, 접속 안내, 시연 주소가 흔들리지 않는다.
- Jenkins가 배포 서버에 붙을 때는 `DEPLOY_HOST`에 **사설 IP**를 쓴다. 보안 그룹이 "Jenkins 보안 그룹에서 오는 22"만 허용하는데, 그 규칙은 VPC 안 사설 IP로 온 연결에만 맞기 때문이다. 탄력적 IP(공인)는 사람 접속과 외부 공개용이고, 사설 IP는 인스턴스를 멈췄다 켜도 바뀌지 않는다.
- Jenkins EC2는 UI를 SSH 터널로만 열기 때문에 팀원이 접속 주소를 안정적으로 쓰려면 탄력적 IP를 붙이는 편이 편하다. 요금을 아끼려면 선택 사항이다.

## 면접 포인트
- 탄력적 IP가 필요한 이유: 인스턴스를 중지·시작하면 자동 공인 IP가 바뀌므로, DNS나 방화벽 허용 목록처럼 주소가 고정이어야 하는 곳에 쓴다. (재시작만 하면 같은 IP이고, 중지 후 시작에서 바뀐다.)
- 보통 운영에서는 탄력적 IP를 직접 노출하기보다 로드밸런서와 DNS를 앞에 두고, 인스턴스 간 통신은 사설 IP로 한다.
