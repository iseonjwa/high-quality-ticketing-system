# 외부에서 IP로 프론트가 안 열린다는데 왜이고, HTTPS는 무료로 달 수 있나

## 질문
- 외부에서 IP 주소로 프론트에 접속이 안 된다던데?
- https를 무료로 달아 주는 서비스는 없나?

## 짧은 답
- **지금은 서버 문제가 아니다.**
  - 2026-11-05 15:33 확인 결과, 80번은 누구에게나 열려 있다.
  - 15:00~15:28에 외부 IP 세 곳이 화면과 API를 정상으로 받았다.
- 안 된 사람은 다음 셋 중 하나일 가능성이 크다.
  1. 서버가 멈춰 있던 때에 접속했다.
  2. 브라우저가 `https://`로 열었다.
  3. 배포 중 잠깐 접속했다.
- 주소는 반드시 `http://52.63.10.174/`로 연다. 아직 인증서가 없어 https(443)는 열리지 않는다.
- **HTTPS는 무료로 달 수 있다.** Let's Encrypt가 2026-01-15부터 IP 주소 인증서를 정식으로 발급한다(유효 약 6일, 자동 갱신). 도메인 없이 `https://52.63.10.174/`가 된다. 리허설 뒤에 하기로 했다.

## 자세히

### 1. 확인한 것 (읽기만 함)
| 확인 | 결과 |
|---|---|
| 팀원 목록에 없는 IP(Jenkins 서버 공인 IP)에서 `http://52.63.10.174/` | 200. 80은 보안 그룹에서 전체에 열려 있다 |
| 같은 곳에서 `https://52.63.10.174/` | 연결 안 됨. 443은 열려 있지 않고, 서버에도 인증서가 없다 |
| 배포 서버 nginx 접근 기록(최근 3시간) | 외부 IP 세 곳이 15:00~15:28에 화면·API를 200·201로 받았다 |
| 같은 기록의 502·503 | 14:55~14:56, 배포로 Gateway가 다시 뜨는 동안만 있었다 |

### 2. 안 된 사람의 원인 후보
1. **서버가 멈춰 있던 때**: 11/4 17:10쯤부터 11/5 14:09까지 AWS 지출 한도로 서버가 멈춰 있었다. 이때는 누구도 접속할 수 없다.
2. **https로 연 경우**
   - Chrome "항상 보안 연결 사용"을 켰거나 주소를 `https://`로 적거나 복사하면, 443으로 가서 연결 오류나 시간 초과가 난다.
   - 주소창에 `http://`를 직접 적는다.
3. **배포 중**: 배포하는 1~2분 동안 API가 502·503을 줄 수 있다. 잠시 뒤 새로고침한다.

가리려면 안 된 사람에게 세 가지를 받는다: 시각, 입력한 주소 전체, 오류 화면.

### 3. HTTPS를 무료로 다는 방법
| 방법 | 도메인 | 특징 |
|---|---|---|
| **Let's Encrypt IP 인증서**(추천) | 필요 없음 | 2026-01-15 정식. 유효 160시간(약 6일)이라 certbot 같은 ACME 클라이언트로 자동 갱신해야 한다(shortlived 프로필). 발급 확인은 HTTP(80)로 한다 |
| 무료 도메인 + Let's Encrypt | DuckDNS 같은 무료 서브도메인 | 일반 인증서(90일)를 쓴다. 이름 주소가 생기지만 무료 도메인 서비스에 하나 더 기댄다 |
| Cloudflare Tunnel | 고정 주소에는 Cloudflare에 연결한 도메인이 필요하다 | 서버 포트를 열지 않고 Cloudflare를 거친다. 도메인 없는 빠른 터널은 주소가 바뀌는 임시용이다 |

이 프로젝트에서 Let's Encrypt IP 인증서를 붙일 때 바꿀 것:
- 배포 서버에 certbot을 설치하고 shortlived 프로필로 `52.63.10.174` 인증서를 받는다. 자동 갱신 뒤 nginx를 다시 읽게 하는 훅을 둔다.
- 프론트 nginx
  - 발급 확인 경로(`/.well-known/acme-challenge/`)를 연다.
  - 443 설정과 인증서 파일을 배포에서만 붙인다(`compose.deploy.yml`). 로컬에는 인증서가 없으므로 기본 설정은 그대로 둔다.
- 보안 그룹에서 443을 전체에 연다.
- `http://`는 당분간 그대로 둔다. 이미 공유한 주소가 깨지지 않게 하려는 것이다.
- 시연 모드 Grafana 링크도 함께 본다.
  - 링크는 화면을 연 주소의 scheme을 따른다(`defaultGrafanaUrl`, 2026-11-05 변경). 화면이 https가 되면 링크도 `https://<IP>:3000`이 된다.
  - 그런데 Grafana 3000은 HTTP다. 그래서 Grafana도 https 아래(예: nginx `/grafana/`)로 옮기거나, 링크의 scheme을 http로 고정해야 한다.

### 4. 결정
- 사용자 결정(2026-11-05): HTTPS는 리허설(11/6) 뒤 서버를 다시 켜는 11/13 전후에 따로 한다. 리허설 전날 서버 설정을 여러 곳 바꾸는 위험을 피하려는 것이다.
- 그때까지는 팀원 안내 문서(`docs/guides/deploy-server-access.md`)에 "반드시 http로 연다"를 적어 둔다.

## 면접 포인트
- "접속이 안 된다"는 보고는 먼저 서버 쪽 사실로 가린다. 바깥 다른 IP에서 직접 요청해 보고, 웹 서버 접근 기록으로 그 사람의 요청이 서버까지 왔는지 본다. 기록에 없으면 네트워크·브라우저 쪽 문제다.
- 브라우저는 https를 우선하는 쪽으로 바뀌고 있다. 인증서 없는 서비스는 주소에 `http://`를 분명히 적어 안내해야 한다.
- 인증서는 무료로 자동화할 수 있다(ACME). 유효 기간이 짧을수록 자동 갱신이 필수가 된다.
