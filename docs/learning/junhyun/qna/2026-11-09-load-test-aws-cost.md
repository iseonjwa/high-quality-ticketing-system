# 배포 서버에 부하 측정을 하면 AWS 요금이 더 나오나

## 질문
배포 서버에 부하 테스트를 하면 요금이 추가로 더 많이 나올까? (같은 서브넷에 k6 발생기 EC2 `c6i.xlarge`를 띄운 뒤에 한 질문)

## 짧은 답
- 배포 서버 요금은 부하와 상관없이 그대로다. 온디맨드 EC2는 켜져 있는 시간으로만 과금하고, `m7i.xlarge`는 성능 고정형이라 CPU를 100% 써도 값이 같다.
- 늘어나는 것은 발생기를 켜 둔 시간(시간당 약 0.222달러)과, 원래 꺼 두려던 기간에 측정 때문에 서버를 켜 둔 시간이다.
- 부하 트래픽 자체에는 요금이 거의 붙지 않는다. 같은 가용 영역 안에서 사설 IP로 오가는 트래픽은 무료이기 때문이다.
- 조건이 하나 있다. 공인 IP로 쏘거나 노트북에서 인터넷 너머로 쏘면 전송 요금이 붙는다. 응답이 큰 K1에서는 측정 한 번에 1~6달러까지 커진다.

## 자세히

### 어떤 요금이 무엇에 따라 붙나
AWS 요금은 대부분 "얼마나 오래 켜 두었나"나 "얼마나 많이 잡아 두었나"로 계산한다. "얼마나 바쁘게 썼나"로 붙는 요금은 일부 서비스에만 있다.

| 항목 | 과금 기준 | 부하 측정으로 늘어나나 |
|---|---|---|
| 배포 서버 `m7i.xlarge` | 켜진 시간(시드니 시간당 0.252달러) | 안 늘어난다. 성능 고정형이라 CPU 사용률과 무관하다 |
| Jenkins `t3.small` | 켜진 시간 | 안 늘어난다. 측정 트래픽을 받지 않고, 크레딧 표준 모드라 초과 사용 요금이 없다 |
| 디스크 gp3 | 잡아 둔 용량(GiB당 월 0.096달러) | 안 늘어난다. gp3는 기본 3,000 IOPS와 125MB/s가 값에 들어 있고 I/O 건수로 과금하지 않는다 |
| 공인 IPv4 | 주소 하나에 시간당 0.005달러 | 안 늘어난다(발생기 주소 하나가 켜진 동안 더해질 뿐이다) |
| 같은 가용 영역의 사설 IP 통신 | 무료 | 0 |
| 같은 리전에서 공인 IP나 다른 가용 영역으로 통신 | GB당 0.01달러, 보내는 쪽과 받는 쪽 양방향 | 사설 IP를 쓰면 해당 없음 |
| 인터넷으로 나가는 전송 | 월 100GB 무료, 그 뒤 GB당 약 0.114달러(시드니) | 결과 파일 내려받기 정도라 무료 범위 안 |
| 발생기 `c6i.xlarge` | 켜진 시간(시간당 약 0.222달러) | 이것이 측정으로 새로 생기는 요금이다 |

T 계열(버스트형)은 다르다. 기준 CPU를 넘겨 쓰면 크레딧을 쓰고, unlimited 모드에서는 크레딧이 모자란 만큼 추가 요금이 붙는다. 배포 서버를 버스트형으로 두지 않은 이유 중 하나다([배포 요금 노트](2026-11-04-deploy-cost-and-single-host-db.md) 1절).

### 주소를 잘못 쓰면 생기는 요금
K1 좌석 선점 측정은 좌석 조회 응답이 약 830KB다. 초당 100건을 10분 돌리면 응답만 약 50GB다(830KB × 100 × 600초).

| 어디서 어느 주소로 쏘나 | 50GB의 전송 요금 |
|---|---|
| 같은 서브넷 발생기 → 배포 서버 사설 IP `172.31.4.93` | 0 |
| 같은 서브넷 발생기 → 배포 서버 공인 IP `52.63.10.174` | 약 1달러(0.01달러 × 50GB × 양방향) |
| 다른 가용 영역 발생기 → 사설 IP | 약 1달러(같은 계산) |
| 노트북 → 공인 IP(인터넷 너머) | 월 무료 100GB를 측정 두 번이면 다 쓰고, 그 뒤 회당 약 5.7달러 |

같은 서브넷에 있어도 공인 IP로 부르면 트래픽이 인터넷 게이트웨이를 거쳐 돌아오므로 리전 내 전송 요금이 붙는다. 보안 그룹의 "소스 = 발생기 보안 그룹" 규칙도 사설 IP로 들어온 트래픽에만 맞는다. 그래서 k6의 `BASE_URL`과 `PROM_RW_URL`은 사설 IP로 쓴다.

### 이 결론이 바뀌는 경우
지금 구조는 EC2 한 대에 DB·Redis·Kafka까지 컨테이너로 올린 단일 서버다(ADR 0047). 처리량에 따라 과금하는 구성 요소가 없어서 부하가 요금으로 이어지지 않는다. 아래를 넣으면 부하가 요금이 된다.
- NAT 게이트웨이: 처리한 GB당 과금
- 로드 밸런서(ALB): 처리량 단위(LCU)로 과금
- Aurora Standard: I/O 요청 건수로 과금
- CloudWatch Logs: 받아들인 로그 GB당 과금

매니지드 서비스로 나누는 것을 검토할 때는 측정 트래픽이 어느 요금에 걸리는지도 같이 본다.

### 요금이 아니라 장애로 오는 것
디스크는 정해진 40GiB라 꽉 차도 요금이 늘지 않는다. 대신 측정 중에 DB 행, Kafka 로그, Loki 로그, Prometheus 시계열(k6 remote write 포함)이 쌓여 디스크가 차면 서비스가 멈춘다. 큰 측정 전후로 `df -h`를 본다.

## 이 프로젝트에서는
- 발생기 위치와 전송 요금: `docs/design/infra/load-test.md` 2-1절(같은 가용 영역이면 사설 IP 통신 무료, 다르면 GB당 0.01달러 양방향).
- k6 주소: `loadtest/k6/README.md` "배포 서버 측정"의 `BASE_URL=http://172.31.4.93:8080`, `PROM_RW_URL=http://<배포 서버 사설 IP>:9090/api/v1/write`.
- 2026-11-09에 발생기(`c6i.xlarge`, 사설 172.31.13.231)를 배포 서버와 같은 서브넷 `subnet-07b3d9d0e31a7d35d`에 만들었고, 사설 IP로 Gateway 8080에 닿는 것을 확인했다.
- 서버 운영 일정과 요금 합계: [배포 요금 노트](2026-11-04-deploy-cost-and-single-host-db.md) 1-1·1-2절.

## 면접 포인트
- **부하 테스트를 클라우드에서 할 때 비용은 어떻게 관리했나?** 발생기를 대상과 같은 가용 영역에 두고 사설 IP로 불러 전송 요금을 0으로 만들었다. 발생기는 측정할 때만 켜고, 성능 고정형 인스턴스를 써서 부하가 요금으로 바뀌지 않게 했다.
- **같은 VPC 안인데 왜 공인 IP를 쓰면 안 되나?** 공인 IP로 부르면 같은 리전 안이어도 GB당 양방향 요금이 붙고, 보안 그룹의 보안 그룹 참조 규칙도 맞지 않는다.
