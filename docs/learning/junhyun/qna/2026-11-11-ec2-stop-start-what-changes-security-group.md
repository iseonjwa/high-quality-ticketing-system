# EC2를 껐다 켜면 무엇이 바뀌고, 보안 그룹을 고쳐야 하나

## 질문
Jenkins 서버를 껐다 켰더니 인스턴스 IP가 바뀌었다. 이것을 반영하려면 보안 그룹을 어떻게 고쳐야 하나? (처음에는 "인스턴스 ID가 바뀌었다"고 물었다가 공인 IP라고 바로잡았다. 둘을 헷갈리기 쉬워 ID 쪽도 같이 정리한다)

## 짧은 답
- 중지 → 시작으로는 인스턴스 ID가 바뀌지 않는다. ID가 바뀌는 것은 인스턴스를 종료(Terminate)하고 새로 만든 경우뿐이다.
- 껐다 켜면 바뀌는 것은 자동 할당 공인 IP(와 그 IP로 만든 퍼블릭 DNS 이름)다. 사설 IP와 붙어 있는 보안 그룹은 그대로다.
- 보안 그룹 규칙의 소스는 IP 대역, 보안 그룹, 접두사 목록 중 하나이고 인스턴스 ID는 쓰지 않는다. 이 프로젝트의 배포 서버 22번 규칙은 소스가 Jenkins 보안 그룹이라, Jenkins를 껐다 켜도 고칠 것이 없다.
- 고칠 것은 공인 IP를 적어 둔 곳이다. 팀 접속 안내, SSH 터널 명령, 팀 공지가 여기에 해당한다.

## 자세히

### 중지·시작과 종료의 차이
| 항목 | 중지 → 시작 | 종료 → 새로 만들기 |
|---|---|---|
| 인스턴스 ID(`i-...`) | 그대로 | 새 ID |
| 사설 IP | 그대로(기본 네트워크 인터페이스가 인스턴스에 붙어 있다) | 새 IP |
| 자동 할당 공인 IP | 바뀐다(중지할 때 반납하고 시작할 때 새로 받는다) | 새 IP |
| 탄력적 IP | 그대로 | 다시 연결해야 한다 |
| 퍼블릭 DNS 이름(`ec2-a-b-c-d...`) | 공인 IP를 따라 바뀐다 | 새 이름 |
| EBS 루트 디스크의 데이터 | 그대로 | 기본 설정이면 지워진다 |
| 붙은 보안 그룹 | 그대로 | 만들 때 다시 고른다 |
| SSH 호스트 키 | 그대로 | 새 키 |
| 물리 호스트 | 바뀔 수 있다 | 새 호스트 |

콘솔의 "인스턴스 상태 → 재부팅"은 운영체제만 다시 켜는 것이라 공인 IP도 바뀌지 않는다.

퍼블릭 DNS 이름은 공인 IP 숫자로 만들어져서, 껐다 켜면 이것도 바뀐다. 이 이름을 인스턴스 식별자로 착각하기 쉽다. 인스턴스 ID는 콘솔 목록의 "인스턴스 ID" 열에 있는 `i-`로 시작하는 값이다.

### 보안 그룹 규칙이 가리키는 것
보안 그룹 규칙의 소스(인바운드)나 대상(아웃바운드)에는 다음 셋만 들어간다.
- IP 대역(CIDR): `61.39.229.214/32`처럼 주소를 직접 적는다. 그 주소가 바뀌면 규칙도 고쳐야 한다.
- 보안 그룹: "이 보안 그룹이 붙은 인스턴스에서 오는 트래픽"이라는 뜻이다. 인스턴스를 다시 만들어도 같은 보안 그룹만 붙이면 규칙을 고칠 필요가 없다. 단, 사설 IP로 들어온 트래픽에만 맞는다.
- 접두사 목록: 여러 IP 대역을 묶은 목록이다.

인스턴스 ID를 소스로 고르는 칸은 없다. 그래서 "인스턴스 ID가 바뀌어서 보안 그룹을 고친다"는 경우는 생기지 않는다. 보안 그룹을 소스로 쓰면 껐다 켜거나 다시 만들 때 손이 덜 간다.

### 껐다 켠 뒤 확인할 것
1. 콘솔에서 인스턴스 ID를 확인한다. 전과 같으면 중지·시작이다.
2. 새 공인 IP를 받아 팀 접속 안내와 공지를 고친다.
3. 처음 새 IP로 SSH 접속하면 "처음 보는 호스트"라는 확인 질문이 나온다. 호스트 키는 그대로라 경고(키 불일치)는 아니다.
4. 서비스가 다시 떴는지 본다. Docker 컨테이너에 `restart: unless-stopped`가 있으면 서버가 켜질 때 같이 뜬다.

## 이 프로젝트에서는
- 배포 서버 보안 그룹 `iseonjwa-deploy-sg`의 22번 규칙 중 Jenkins용은 소스가 보안 그룹 `iseonjwa-jenkins-sg`다. Jenkins는 배포 서버를 사설 IP(`DEPLOY_HOST`)로 부르므로, Jenkins를 껐다 켜도 이 규칙과 Jenkins 설정은 그대로다([배포 요금 노트](2026-11-04-deploy-cost-and-single-host-db.md) 1-1절).
- Jenkins는 탄력적 IP가 없어 켤 때마다 공인 IP가 바뀐다. 그 값은 `docs/guides/deploy-server-access.md` 1절 표에 적혀 있어 매번 고친다.
- 발생기 EC2도 같다. 배포 서버 8080·9090 규칙의 소스가 `iseonjwa-loadgen-sg`라 발생기를 껐다 켜도 고칠 필요가 없다.
- 반대로 Jenkins를 종료하고 새로 만들었다면, 새 인스턴스에 `iseonjwa-jenkins-sg`를 붙이는 것으로 보안 그룹은 해결된다. 하지만 디스크의 Jenkins 설정(`/opt/jenkins/jenkins.env`, `deploy_ssh_key`, 컨테이너)은 처음부터 다시 만들어야 한다.

## 면접 포인트
- **EC2를 중지했다 시작하면 무엇이 바뀌나?** 자동 할당 공인 IP와 그 DNS 이름이 바뀐다. 인스턴스 ID, 사설 IP, EBS 데이터, 보안 그룹은 그대로다. 고정 주소가 필요하면 탄력적 IP를 붙인다.
- **서버끼리 허용 규칙은 왜 IP 대신 보안 그룹으로 거나?** IP는 인스턴스를 다시 만들거나 늘릴 때 바뀐다. 보안 그룹을 소스로 걸면 "이 역할의 서버들"을 허용하는 뜻이 돼서, 서버가 바뀌어도 규칙을 고치지 않는다.
