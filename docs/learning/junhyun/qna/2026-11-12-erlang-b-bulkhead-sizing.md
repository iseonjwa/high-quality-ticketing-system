# 대기 없는 동시 수 제한의 크기를 어떻게 정하는가(리틀의 법칙과 Erlang B)

## 질문
결제 개선 방안을 하나씩 적용할 때마다 설계와 이론 문서를 남기기로 했다(11/12). 이 노트는 ISE-236·ISE-238(자동결제 전용 PG 허가 그룹과 일반 결제 허가 수)의 이론이다. 다루는 물음은 "대기 없는 동시 수 제한의 크기를 어떻게 정하는가"다.

## 짧은 답
- **리틀의 법칙**으로 평균 동시 수를 구한다: 동시 수 L = 초당 도착 λ × 한 건이 머무는 시간 W. 허가 수는 이 평균보다 커야 한다.
- 평균만 맞추면 부족하다. 요청은 무작위로 도착해 순간 몰림이 있고, 대기 없는 제한은 그 순간 몰림을 **거절**한다. **Erlang B**가 이 거절 확률을 준다.
- 허가 수는 처리량의 상한이면서 장애 때 PG 호출에 묶이는 스레드 수의 상한이다. 그래서 필요한 거절 확률에서 정하고 더 올리지 않는다.
- 일반 결제와 자동결제는 허가 그룹을 나눠(격벽) 서로의 자리를 빼앗지 않게 한다.

## 자세히

### 리틀의 법칙
시스템 안에 평균적으로 머무는 수 L은 도착률 λ와 머무는 시간 W의 곱이다. L = λ × W. 분포와 무관하게 성립한다.
- 승인 한 건이 허가를 쥐는 시간 W ≈ TX1 + PG 응답 ≈ 0.315초(PG 300ms 기준), 초당 도착 30건이면 L = 30 × 0.315 ≈ 9.5다. 허가가 10이면 평균으로는 아슬아슬하다.
- 이 L을 **제공 부하(얼랑, a)**라 부른다. 단위는 "동시에 점유되는 자리 수의 평균"이다.

### Erlang B: 대기 없는 손실 시스템의 거절 확률
도착이 포아송(무작위)이고 서비스 시간이 평균 W이며 자리가 n개이고 자리가 없으면 즉시 거절(대기 없음)인 시스템에서, 도착이 거절될 확률은 Erlang B 공식이다.

B(n, a) = (aⁿ / n!) / Σₖ₌₀ⁿ (aᵏ / k!)

큰 n에서 팩토리얼이 넘치므로 점화식으로 계산한다.

```python
def erlang_b(a, n):
    b = 1.0                      # B(0, a) = 1
    for k in range(1, n + 1):
        b = a * b / (k + a * b)  # B(k, a) = a*B(k-1, a) / (k + a*B(k-1, a))
    return b
```

### 이 프로젝트의 손실 표(계산값)
허가를 쥐는 시간 0.315초 기준이다. 측정이 아니라 계산값이다.

| 초당 도착 | 제공 부하 a | 허가 10 | 허가 17 | 허가 20 | 허가 24 | 허가 27 | 허가 30 |
|---|---|---|---|---|---|---|---|
| 30건 | 9.45 | 18.9% | 0.85% | 0.10% | - | - | - |
| 50건 | 15.75 | - | 13.4% | 5.9% | 1.3% | 0.28% | 0.05% |

평균(9.45)이 허가(10)보다 작은데도 18.9%가 거절된다. 평균이 아니라 순간 몰림이 거절을 만든다는 뜻이다. 초당 50건(대기열 입장 속도)을 거절 1% 아래로 받으려면 허가가 24~27은 필요하다. 그래서 일반 결제는 30으로 올린다.

### Erlang C와의 차이
- **Erlang B**: 대기 없음. 자리가 없으면 거절한다. 허가를 못 얻으면 즉시 503을 주는 우리 구조다.
- **Erlang C**: 대기 있음(무제한 큐). 거절은 없고 **기다릴 확률**과 대기 시간을 준다. 큐가 무한히 길어질 수 있어 사용자가 기다리는 API에는 맞지 않고, 스레드를 쥔 채 기다리면 장애 때 스레드가 고갈된다.
이 프로젝트가 허가 대기를 0으로 둔 이유와 이어진다(자리를 기다리는 요청이 스레드를 쥐고 응답이 늦어진다).

### 포아송 가정과 k6의 일정 도착
Erlang B는 도착이 포아송(무작위, 몰림 있음)이라고 가정한다. k6의 constant-arrival-rate 같은 일정 간격 도착은 몰림이 없어 같은 허가 수에서 거절이 **더 낮게** 나온다. 실제로 같은 조건(요청 80/초, 허가를 쥐는 시간 0.315초, a = 25.2)을 계산하면 허가 10은 62.5%(측정 59.5%로 가깝다), 허가 30은 5.5%인데 측정은 0.2%였다. 허가가 꽉 찰수록 일정 도착이 낙관적으로 나온다. 실제 트래픽은 측정보다 몰릴 수 있으므로 여유를 두고 값을 정한다.

### 허가 수는 장애 때 묶이는 스레드 수이기도 하다
PG가 느려지면 허가를 쥔 요청 스레드가 PG 응답을 기다린다. 허가 수는 그 스레드 수의 최대값이다. 허가를 크게 잡을수록 처리량은 오르지만 장애 때 묶이는 스레드와 `UNKNOWN`(결과 모름) 결제도 허가 수에 비례해 늘어난다. 처리량과 장애 영향이 한 숫자에 걸려 있어서 필요한 처리량에서 값을 정한다.

### 그룹을 나누는 이유(격벽)
선박의 격벽처럼, 한 구획이 물에 잠겨도 다른 구획은 버티게 자원을 나눈다. 일반 결제와 추첨 자동결제가 한 그룹 `pg-approve`를 나눠 쓰면 추첨 당첨 결제가 몰릴 때 일반 사용자의 승인이 거절되고, 반대로 일반 결제가 몰리면 자동결제가 밀린다. 자동결제 전용 `pg-billing`(동시 3)을 나누면 각자 자기 자리만 쓴다. 대가는 그룹마다 자리를 따로 잡아 두므로 전체 자리 활용률은 낮아진다는 점이다. 이 프로젝트에서는 PG를 동시에 부르는 최대 호출이 일반 30 + 자동결제 3 + 복구 2 = 35가 된다.

## 이 프로젝트에서는
- 11/12 배포 측정에서 허가 10은 PG 300ms에서 한도가 초당 31건이었고, 30으로 올리면 91.5건, 요청 80건/초 거절은 59.5% → 0.2%였다(`docs/design/infra/open-peak-scenarios.md` 3절).
- 결정: 일반 결제 `pg-approve` 30(PG가 느린 경우 측정 뒤 24~30에서 확정, ISE-246), 자동결제 `pg-billing` 3, 대기 0. 설계는 `docs/design/payment/pg-integration.md` 5절이다.
- 자동결제 허가 3은 소비자 동시성(3)과 같게 둔 값이다. 소비자 하나가 PG 응답을 기다리는 동안 허가 하나를 쥐므로 소비자 수 이상이 필요하다.

## 면접 포인트
- "동시 수 제한을 어떻게 정했나"에 리틀의 법칙으로 평균을, Erlang B로 순간 몰림의 거절 확률을 계산했다고 답한다. 평균만 맞추면 18.9%가 거절되는 예를 든다.
- 대기를 두지 않은 이유(Erlang C, 스레드 고갈)와, 허가 수가 장애 때 묶이는 스레드의 상한이라는 점을 함께 말한다.
- 계산은 포아송 가정이고 부하 도구의 일정 도착 측정은 더 낙관적이라는 한계를 말한다.
- 격벽으로 일반 결제와 자동결제를 나눈 이유와 비용(자리 활용률)을 설명한다.
