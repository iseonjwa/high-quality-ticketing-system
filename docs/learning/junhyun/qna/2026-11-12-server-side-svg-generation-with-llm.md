# 이미지 생성 API 없이 서버가 LLM(Claude API)으로 그림을 만들 수 있나

## 질문
발권 이벤트 부적 시안(티켓 모양, 9:16)을 AI가 SVG로 그렸다. 이 정도면 이미지 생성 API 없이, 서버가 이미 가진 Claude API 키로 사람마다 펫을 만들 수 있지 않나.

## 짧은 답
만들 수 있다. SVG는 그림을 글자(XML)로 적은 것이라 글을 만드는 LLM이 그대로 쓸 수 있고, 이미지 생성 모델은 필요 없다. assistant-service가 Claude API로 펫 SVG를 받아 검사·저장하고, 화면은 그 펫을 티켓 틀에 끼워 PNG로 만든다. 다만 서버가 그때그때 만들면 사람이 보고 고치는 단계가 없다. 그래서 네 가지를 따로 챙겨야 한다. 품질이 들쭉날쭉할 수 있다. 같은 사람에게 같은 펫을 주려면 한 번 만들어 저장해야 한다. LLM이 쓴 SVG는 그대로 그리면 XSS 통로가 된다. 실패하면 미리 그린 펫으로 돌아가야 한다.

## 자세히

### 왜 이미지 생성 API가 필요 없나
그림 파일은 두 종류다.

| | 래스터(PNG, JPG) | 벡터(SVG) |
|---|---|---|
| 담는 것 | 점(픽셀)마다의 색 | 도형 명령(`<circle>`, `<path d="M…">`)과 색 |
| 만드는 도구 | 이미지 생성 모델(확산 모델 등) | 글을 쓰는 무엇이든. 사람, 코드, LLM |
| 잘하는 그림 | 사진풍, 질감, 복잡한 빛 | 굵은 외곽선, 단색 면, 단순한 캐릭터와 아이콘 |

LLM은 글자를 출력하므로 SVG 문서를 쓸 수 있다. 굵은 외곽선과 단색 면으로 된 귀여운 캐릭터는 벡터로 그리기 좋은 그림이다. 반대로 사진처럼 보이는 펫은 이 방법으로 만들 수 없다.

### 시안을 만든 과정과 서버 호출은 다르다
시안은 한 번에 나오지 않았다. AI가 SVG를 쓰고, 헤드리스 Chrome으로 PNG를 찍어 직접 본 뒤 두 군데를 고쳤다. 절취선 홈 둘레 그림자가 원으로 튀어나와 보였고, 펫이 안은 티켓의 `ADMIT` 글자를 앞발이 가렸다. 서버 호출은 요청 한 번에 응답 한 번이고, 그사이에 그림을 보는 사람이 없다. 그래서 런타임 생성은 "가끔 이상한 그림이 나와도 되는가"를 먼저 정해야 하고, 쓰기 전에 실제로 여러 장 뽑아 품질을 재 봐야 한다.

### 흐름
```
예매 상세 처음 열기(확정 예매)
  └─ 프론트 → assistant-service: 내 펫 만들어 줘(로그인 사용자, userId 기준 한 번만)
        └─ 이미 있으면 그대로 돌려줌(멱등)
        └─ 없으면 Claude API 호출 → SVG 받기 → 허용 목록 검사 → 저장 → 추측 불가능한 부적 ID 발급
QR(부적 ID 포함)을 폰으로 찍기
  └─ 부적 화면 → 부적 ID로 펫 SVG 읽기(읽기만, 로그인 없음)
  └─ 티켓 틀 + 닉네임 + 전투력 + 응원 문장 + 펫 → canvas → 1080×1920 PNG
실패(시한 초과, 429, 거절, 검사 탈락) → 미리 그린 펫
```
예매 상세를 처음 열 때 만들기 시작하면, 사용자가 QR을 찍을 때쯤에는 대개 끝나 있어 기다림이 보이지 않는다.

### 비용보다 한도와 시한이 문제다
비용은 작다. 시안의 펫 부분은 2,835바이트다. SVG는 숫자와 기호가 많아 1토큰을 3~4바이트로 잡으면 출력이 약 700~950토큰이다(`count_tokens`로 잰 값이 아닌 추정이다). 입력(지시문과 예시 SVG)을 약 2천 토큰으로 잡고 2026-11-03 기준 단가로 계산하면 이렇다.

| 모델 | 단가(입력/출력, 100만 토큰당) | 펫 1장 | 1천 장 |
|---|---|---|---|
| Claude Haiku 5.5(문의 위젯이 쓰는 모델) | $0.10 / $0.50 | 약 $0.0007 | 약 $0.7 |
| Claude Sonnet 5.5 | $2 / $10 | 약 $0.014 | 약 $14 |

생각(thinking) 토큰도 출력으로 과금되므로 실제 값은 이보다 조금 클 수 있다.

문제는 지금 설정이 문의 위젯용이라는 점이다. `max-tokens: 1024`면 펫 SVG와 생각 토큰을 합쳐 한도에 걸릴 수 있고, 잘린 SVG는 닫는 태그가 없어 그려지지 않는다. `timeout: 8s` 안에 1천 토큰 가까운 출력이 끝난다는 보장도 없다. `max-concurrent: 4`와 `daily-limit: 1000`을 문의 위젯과 같이 쓰면 이벤트 요청이 문의 답을 막을 수 있다. 펫 생성에는 한도·시한·동시 수를 따로 둔다.

### 같은 사람에게 같은 펫
LLM은 같은 요청에도 매번 다른 답을 낸다. "자신만의 펫"이 되려면 userId를 키로 한 번 만들어 DB에 저장하고, 다시 요청하면 저장한 것을 돌려준다(멱등). 저장하는 순간 펫은 서버 데이터가 되므로, 폰이 로그인 없이 보려면 추측할 수 없는 부적 ID로 읽기만 하는 길을 연다. 생성은 로그인한 사용자만 계정당 한 번이라 남용으로 비용이 커지지 않는다.

### LLM이 쓴 SVG는 믿지 않는 입력이다
- **XSS**: SVG 안에는 `<script>`, `onload` 같은 이벤트 속성, HTML을 품는 `<foreignObject>`, 외부 주소를 부르는 `href`가 들어갈 수 있다. LLM이 일부러 넣지 않더라도, 사용자가 프롬프트에 끼어들 길이 있으면 넣게 만들 수 있다. 서버에서 허용 목록(`g`, `path`, `circle`, `ellipse`, `rect`, `line`, `polygon`, 그라데이션 요소와 좌표·색 속성)만 남겨 다시 직렬화하고, 화면에서는 `<img>`로 넣는다. `<img>`로 연 SVG는 스크립트를 실행하지 않는다.
- **XXE**: Java에서 받은 SVG를 XML로 파싱할 때 DTD와 외부 엔티티를 끈다. 켜 두면 `<!ENTITY x SYSTEM "file:///etc/passwd">` 같은 선언으로 서버 파일을 읽게 할 수 있다.
- **프롬프트 주입**: 닉네임을 프롬프트에 넣지 않는다. 닉네임과 전투력은 우리 틀이 글자로 넣고, LLM에는 펫 종류·색 같은 정해진 값만 준다.
- 크기 상한(예: 20KB)과 `viewBox` 고정으로 틀 밖으로 나가는 그림을 막는다.

### 고르는 방법
1. 지금 모델(Haiku 5.5)로 펫 10장 정도를 뽑는다. 시안의 토끼 SVG를 예시로 붙여 외곽선 굵기·색·비율을 맞추게 한다.
2. 모두 렌더해 사람이 본다. 쓸 만한 비율이 높으면 런타임 생성으로 가고, 미리 그린 펫을 실패 대비로 둔다.
3. 들쭉날쭉하면 개발할 때 AI로 펫 묶음을 미리 그려 검토한 뒤 정적 파일로 두고, 서버는 시드로 고르기만 한다. 서버 변경이 없고 결과가 늘 같다.

## 이 프로젝트에서는
- 서버: `assistant-service`가 Claude API를 이미 쓴다. 설정은 `config-repo/assistant-service.yml`(`model: claude-haiku-5-5`, `max-tokens: 1024`, `timeout: 8s`, `max-concurrent: 4`, `daily-limit: 1000`)과 같은 기본값을 둔 `AssistantProperties.java`에 있다. 키는 서버 환경 변수에만 있고 프론트로 나가지 않는다.
- 이슈는 ISE-257이다. 런타임 생성으로 바꾸면 assistant-service API·저장소·검사기가 범위에 들어온다.
- 결과(11/12): 시험 생성 없이 미리 그려 두는 쪽을 골랐다. 펫 부품 1,200 조합과 배정 규칙은 `frontend/src/pages/charm/charmPets.ts`·`charmTicket.ts`에 있고, 서버 변경은 없다.

## 면접 포인트
- LLM 출력을 HTML이나 SVG로 그대로 그리면 무엇이 위험한가: 저장형 XSS와 같다. 믿지 않는 입력으로 보고 허용 목록으로 걸러 다시 직렬화하며, `<img>` 격리와 CSP를 더한다.
- 같은 요청에 다른 답이 나오는 LLM 결과를 사용자마다 일정하게 보이려면: 한 번 만들어 저장하고 사용자 키로 멱등하게 돌려준다.
- 외부 LLM 호출이 실패하면: 시한, 별도 한도, 대체 경로(미리 그린 결과)를 둬 핵심 기능과 이벤트 기능의 장애를 떼어 놓는다.
