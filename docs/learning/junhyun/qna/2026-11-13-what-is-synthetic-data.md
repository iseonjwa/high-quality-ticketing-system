# Synthetic Data가 뭐고, 부하 테스트에서 왜 필요한가

## 질문
"Synthetic Data가 뭐야?" 발제 필수 항목 "가상 사용자 기반의 부하 테스트 시나리오 생성(Synthetic Data)"을 되살리기로 하면서 나온 질문이다. herdr 옆 패널의 설명 세션이 먼저 답했고(그 답은 사용자 요청으로 Notion "발제 관련" 페이지에도 올라갔다), 이 노트는 그 답에 ISE-262에서 실제로 만든 것을 더해 정리했다.

## 짧은 답
- 실제로 모은 데이터가 아니라 새로 만든 데이터다. 다만 실제와 통계적 성질(분포, 비율, 값 사이의 관계)이 비슷하게 만든다. 아무 값이나 넣은 가짜 데이터와는 그 점이 다르다.
- 부하 테스트에서 맞춰야 하는 것은 요청 값이 아니라 **사용자 행동**이다. 누가 언제 들어오고, 무엇을 몇 번 누르고, 실패하면 어떻게 하는지다. CSV 한 행이 사용자 한 명의 행동 대본이 된다.
- 서버는 평균이 아니라 쏠림에서 무너진다. 모두가 같은 규칙으로 움직이는 부하로는 오픈 직후의 뾰족한 도착, 인기 구역 충돌, 연타, 선점 뒤 이탈이 덜 보인다.

## 자세히

### 일반적인 뜻과 쓰는 곳
- 테스트: 운영 데이터를 쓸 수 없거나 아직 없을 때 운영과 비슷한 모양의 데이터로 시험한다.
- 개인정보 대체: 실제 고객 이름·전화번호 대신 성질만 같은 데이터를 만든다.
- ML 학습: 드문 사례가 부족할 때 데이터를 늘린다.

### 부하 테스트에서 균일 난수와 무엇이 다른가
기존 O1(`loadtest/k6/scenarios/o1-open-peak.js`)에도 난수는 있다. 진입을 오픈 뒤 10초 안에 고르게 흩고, 1석·2석을 반반, 70%가 좌석 응답 앞쪽 10%에서 고르고, 10%가 선점 뒤 떠난다. 문제는 모든 사용자가 같은 규칙을 따른다는 것이다.

| 항목 | 균일 난수 O1 | 페르소나 기반 Synthetic O1 |
|---|---|---|
| 사용자 구성 | 한 종류 | 8종(퇴근 후 PC 팬, 친구와 2매, 새로고침 연타, 퇴근길 모바일, 오픈 뒤 일반 관심층, VIP 고집 팬, 여러 기기, 구경만)이 비율대로 |
| 진입 시각 | 10초 안에 고르게 | 대부분 오픈 직후 몇 초에 몰리고, 일부는 오픈 10분 뒤까지 드문드문 |
| 좌석 | 응답 앞쪽 10%에서 70% | 유형마다 노리는 등급(VIP·R·S·아무 곳), 1~4석 |
| 409 뒤 | 같은 규칙으로 2번 다시 | 유형마다 횟수와 행동(같은 등급, 아무 곳, 포기) |
| 요청 빈도 | 사람마다 같음 | 연타형은 진입을 여러 번 보냄 |
| 데이터 위치 | 코드 안 상수 | CSV(사용자 한 명이 한 행), 시드 고정 |

### LLM은 어디까지 맡기나
- LLM이 맡는 것: 도메인 지식이 필요한 초안. 어떤 유형이 몇 %이고 어떻게 움직이는지를 페르소나와 분포(JSON), 표본 몇 행(CSV)으로 받는다. 프롬프트와 응답 원문을 그대로 남긴다(발제 산출물).
- 코드가 맡는 것: 수천 명 분량의 실제 CSV. LLM에게 수천 행을 직접 쓰게 하지 않는 이유는 재현성(같은 프롬프트에도 답이 매번 다르다), 제약 위반(1인 4매 초과, 없는 구역), 산술 실수(비율 합이 1이 아님), 긴 출력의 품질 저하다.
- 검증 스크립트가 맡는 것: LLM 출력과 생성 CSV가 형식·범위·비율을 지키는지 기계로 확인한다.

### 발제가 요구하는 산출물
1. LLM에 쓴 프롬프트 원문
2. 생성된 Synthetic Data(CSV)
3. 일반 부하 테스트 결과와 Synthetic Data 기반 결과의 비교

## 이 프로젝트에서는
- 1·2번은 ISE-262(PR #583)에서 만들었다. 프롬프트 `loadtest/synthetic/o1-prompt.md`, 응답 원문 `o1-response.md`, 분포 `o1-personas.json`, 3,000명 CSV `loadtest/k6/data/o1-synthetic-3000.csv`(시드 20261113). 설계는 `docs/design/infra/synthetic-data.md`.
- LLM(Claude Opus 5.5, 도구를 끈 `claude -p`)은 표본 40행을 난수 생성기 없이 썼다고 스스로 밝혔다. 그래서 측정용 CSV는 LLM이 정한 분포로 `generate.py`가 만들었다.
- 생성한 3,000명은 LLM이 응답에서 계산한 성질과 맞았다. VIP를 노리는 사용자 42.2%(LLM 계산 약 42%), 진입 요청 수가 사용자 수의 1.59배(약 1.6배).
- 3번 비교 측정은 ISE-264로 남겼다. 같은 서버·같은 3,000명으로 균일 O1과 Synthetic O1을 돌려 구간별 p95, 선점 409 비율, 결과 분포를 비교한다.

## 면접 포인트
- **Synthetic Data를 어떻게 만들었나?** 티켓 오픈 사용자를 유형으로 나누고, LLM에게 유형과 행동 분포 초안을 받아 원문을 남겼다. 수천 명 분량은 시드를 고정한 코드로 만들고 검증 스크립트로 확인했다.
- **LLM이 만든 데이터를 믿을 수 있나?** 그대로 믿지 않았다. LLM은 분포 초안만 맡고, 생성은 코드, 확인은 검증 스크립트가 했다. 분포의 수치가 추정이라는 점도 LLM이 스스로 밝혔고 문서에 한계로 적었다.
