# 추첨 배분 설계로 이 프로젝트에서 무엇을 얻어 갈 수 있나

## 질문
이번 프로젝트에서 추첨 설계로 얻어 갈 수 있는 포인트는 무엇인가.

## 짧은 답
추첨은 티켓팅의 "실시간 선착순" 문제와 반대 성격의 문제다. 요청을 모아 두었다가 한 번에 처리하는 **배치형 흐름**이라서, 선점(동시성)과 다른 기술 주제를 얻는다.
1. 몰리는 요청을 받아 두는 비동기 접수(Kafka)와 1인 1응모 보장(멱등·유니크)
2. 결과를 나중에 검증할 수 있는 공정성(시드 기록, 재실행 방지)
3. 당첨 → 배정 → 자동결제 → 실패 시 예비자 승계로 이어지는 여러 단계 흐름의 정합성(SAGA, 보상)
4. 사용자가 없는 상태에서 결제하는 빌링키 자동결제와, 대량 결제를 Kafka로 처리할 때의 중복·유실 방지
5. "왜 이 기능을 넣었나"를 비즈니스 가치(공정성, 판매율, 피크 분산)로 설명하는 기획 경험

## 자세히

### 1. 비동기 접수와 1인 1응모
- 응모는 결과가 바로 필요 없고 마감 직전에 몰린다. 그래서 API는 받아 두기만 하고(202) Kafka 소비자가 처리한다(SA 4-3, 결정 기록 #39, AI 검증 #4에서 "동기 처리" 권고를 거부한 근거).
- 1인 1회차 1응모는 DB 유니크 제약으로 막는다. 같은 요청이 두 번 와도(재전송, Kafka 중복 소비) 결과가 같아야 하므로 멱등성을 설계하게 된다.
- 얻는 것: "언제 동기, 언제 비동기인가"를 결과 필요 시점으로 판단한 근거. 선점(동기)과 대비해 설명할 수 있다.

### 2. 공정성과 재현 가능성
- 추첨 시드를 기록하면 같은 입력으로 같은 결과를 다시 계산할 수 있다. "조작하지 않았다"를 사후에 증명하는 장치다.
- 추첨을 두 번 실행하면 결과가 바뀌므로 재실행 방지(상태 전이 한 번, 조건부 UPDATE)가 필요하다.
- 얻는 것: 감사 가능성(auditability) 설계. 면접에서 "공정성을 어떻게 보장했나"에 기술 장치로 답할 수 있다.

### 3. 여러 단계 흐름의 정합성 (SAGA)
- 당첨 → 좌석 배정 → 자동결제 요청(`payment.command`) → 결과 수신(`payment.result`) → 성공이면 발권, 실패면 좌석을 같은 조건 예비자에게 승계 → 승계 마감 후 남은 좌석은 일반 예매로.
- 서비스 경계를 넘는 흐름이라 한 트랜잭션으로 묶을 수 없다. 단계마다 상태를 남기고, 실패하면 보상(좌석 반환, 승계)한다.
- 위험: 승계 중 같은 좌석이 두 사람에게 배정되는 경우. 좌석 배정을 조건부 UPDATE로 하고, 결제 결과 이벤트는 처리 이력으로 중복을 거른다.
- 얻는 것: Choreography SAGA를 일반 예매(선점 → 결제)에 이어 한 번 더, 더 긴 흐름으로 설계한 경험.

### 4. 빌링키 자동결제와 대량 처리
- 당첨자는 결제 화면에 없다. 응모 때 등록한 빌링키로 서버가 대신 결제한다. 가승인 대신 빌링키를 고른 이유(가승인은 금액이 묶이고 유효 기간이 있다)를 설명할 수 있어야 한다.
- 당첨자 수천 명의 결제를 Kafka로 보낼 때: 결제 요청 멱등키(같은 당첨 건은 한 번만 결제), Outbox로 발행 유실 방지, 처리 이력으로 중복 수신 방지, 실패는 재시도 후 DLQ.
- 결제 쪽(빌링키 등록·자동결제 처리)과 추첨 쪽(배정·승계)의 경계를 정하는 일이 협업 포인트다.
- 얻는 것: 이벤트 신뢰성 공통 모듈(Outbox·processed_event·DLQ)을 실제 대량 흐름에 쓰고 측정할 수 있다.

### 5. 기획 관점
- 추첨은 차별화 기능(Should)이다. 광클·매크로 대신 공정한 기회, 실패 좌석 즉시 승계로 판매율 유지, 응모 기간으로 수요가 분산되어 오픈 피크가 줄어든다(SA 4-3).
- 얻는 것: 기능을 "기술이 재미있어서"가 아니라 사용자·판매자 가치와 시스템 부하 관점에서 정당화하는 연습.

## 면접 포인트
- "추첨에서 가장 어려웠던 점은?": 당첨 → 자동결제 → 실패 시 승계가 서비스 경계를 넘어 한 트랜잭션으로 묶이지 않는다는 점. 단계별 상태와 보상, 조건부 UPDATE로 중복 배정을 막았다.
- "공정성은 어떻게 보장했나?": 추첨 시드를 기록해 같은 입력으로 결과를 다시 계산할 수 있게 하고, 추첨을 한 번만 실행하도록 상태 전이를 막았다.
- "응모를 왜 비동기로 받았나?": 결과가 바로 필요 없고 마감 직전에 몰리기 때문이다. 선점처럼 즉시 결과가 필요한 곳은 동기로 두었다.
