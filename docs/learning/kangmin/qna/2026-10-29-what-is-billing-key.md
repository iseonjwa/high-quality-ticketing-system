# 빌링키란 무엇이고 추첨 자동결제에 왜 쓰나

## 질문
빌링키가 뭐야

## 짧은 답
- 빌링키는 사용자가 한 번 카드 인증을 하면 PG가 발급해 주는 **"이 카드로 나중에 결제해도 된다"는 대체 식별자**다. 카드 번호 대신 이 값으로 결제를 요청한다.
- 가맹점(우리 서버)은 카드 번호를 저장하지 않고 빌링키만 저장한다. 사용자가 화면에 없어도 서버가 결제할 수 있어 구독·정기결제·자동결제에 쓴다.
- 추첨에서는 응모할 때 빌링키를 받아 두고, 당첨되면 사용자 개입 없이 서버가 결제한다(SA F5-4·F5-5, F6-4).

## 자세히

### 일반 결제와의 차이
| | 일반 결제 | 빌링키 결제 |
|---|---|---|
| 사용자 개입 | 결제할 때마다 결제창에서 인증 | 처음 등록할 때 한 번 |
| 서버가 받는 것 | 결제 한 건의 승인 결과 | 재사용 가능한 빌링키 |
| 결제 시점 | 사용자가 결제 버튼을 누를 때 | 서버가 원할 때(당첨 직후 등) |
| 쓰는 곳 | 쇼핑, 일반 예매 | 구독, 정기결제, 추첨 자동결제 |

### 흐름 (토스페이먼츠 기준, 일반적인 구조)
1. **등록**: 사용자가 카드 등록 창에서 카드 정보를 넣고 본인 인증을 한다. 카드 번호는 PG만 받는다.
2. **발급**: PG가 인증 결과를 돌려주고, 서버가 이것으로 빌링키 발급을 요청해 빌링키를 받는다. 이때 우리 쪽 사용자 식별값(토스는 `customerKey`)이 함께 묶인다.
3. **저장**: 서버는 빌링키를 암호화해 저장한다.
4. **결제**: 필요할 때 서버가 빌링키, 금액, 주문번호로 PG에 승인을 요청한다. 사용자는 화면에 없다.
5. **해지**: 사용자가 카드를 지우면 빌링키를 무효로 만든다.

토스의 구체적인 API 이름과 파라미터는 이 노트를 쓰면서 공식 문서로 확인하지 않았다. M4에서 토스 어댑터를 만들 때 확인한다.

### 왜 민감한가
빌링키는 카드 번호는 아니지만 **이것만 있으면 그 카드로 결제가 된다.** 그래서 다음을 지킨다.
- 암호화해 저장한다(SA 12-4 `billing_key_enc`).
- 결제 서비스 밖으로 내보내지 않는다. 다른 서비스는 "등록 여부"와 화면용 `card_last4`만 안다.
- 빌링키는 우리 가맹점 키와 짝을 이뤄야 쓸 수 있어서, 유출돼도 다른 가맹점에서 바로 쓰이지는 않는다. 그래도 우리 서버에서는 결제가 된다.

### 추첨에서 빌링키를 고른 이유 (가승인과 비교)
SA 4-3은 "자동결제 방식은 빌링키(잠정), 가승인은 쓰지 않는다"고 정했다(결정 기록 `#43`).

| 방식 | 내용 | 추첨에 쓰면 |
|---|---|---|
| 가승인(오소리) | 응모할 때 금액만큼 카드 한도를 미리 잡아 두고, 당첨되면 확정, 낙첨되면 취소 | 응모자 30,000명 모두의 한도를 며칠씩 묶는다. 낙첨 28,000건을 취소해야 하고, 가승인 유효기간도 신경 써야 한다 |
| 빌링키 | 응모할 때 결제 수단만 등록하고, 당첨자만 결제 | 당첨자 2,000명만 결제한다. 대신 결제 시점에 한도 부족·카드 해지로 실패할 수 있어 승계 처리가 필요하다 |

빌링키를 택한 대가가 바로 "결제 실패 처리(U9)"와 "자동결제 폭주(측정 시나리오 2)"다.

## 이 프로젝트에서는
- 테이블: SA 12-4 `billing_keys`(payment DB). `user_id`, `billing_key_enc`, `card_last4`, `status`(ACTIVE·REVOKED), 사용자당 ACTIVE 1개
- API: `POST /api/v1/payments/billing-keys`(결제 담당, M4)
- 결제 요청: 추첨이 당첨자 예매를 만들고 `payment.command`에 `BillingPaymentRequested`를 발행 → 결제가 빌링키로 승인
- 응모 에러: `BILLING_KEY_REQUIRED`(409)
- 경계 합의 항목: [2026-10-29-lottery-payment-agreement-items.md](2026-10-29-lottery-payment-agreement-items.md) 2절

## 면접 포인트
- "카드 정보를 저장했나?" → 저장하지 않았다. PG가 발급한 빌링키만 암호화해 결제 서비스에 두고, 다른 서비스에는 등록 여부만 알렸다
- "왜 가승인이 아니라 빌링키인가?" → 응모자 전원의 한도를 묶지 않고 당첨자만 결제하기 위해서다. 대신 결제 시점 실패를 예비자 승계로 처리했다
