# Java의 var는 자료형인가

## 질문
자료형 `var`는 무엇인가. 타입을 직접 적지 않고 `var`로 쓰는 이유는 무엇인가.

## 짧은 답
`var`는 자료형이 아니라 지역 변수 타입 추론 문법이다(Java 10). 컴파일러가 오른쪽 값을 보고 타입을 정하고, 그 뒤로 타입은 고정된다. 그래서 JavaScript의 `var`처럼 다른 타입을 다시 넣을 수 없고, 실행 성능도 타입을 직접 적었을 때와 차이가 없다.

## 자세히

### 동작
```java
var now = clock.instant();   // Instant
var ids = new ArrayList<Long>(); // ArrayList<Long>

now = "문자열";               // 컴파일 오류. now는 Instant다
```

### 쓸 수 있는 곳
| 위치 | 가능 여부 |
|---|---|
| 초기값이 있는 지역 변수 | 가능 |
| 향상된 for, 일반 for의 변수 | 가능 |
| try-with-resources 변수 | 가능 |
| 필드, 메서드 매개변수, 반환 타입 | 불가 |
| 초기값 없음(`var x;`) | 불가 |
| `var x = null;` | 불가. 타입을 알 수 없다 |
| 람다, 메서드 참조, 배열 초기화(`var a = {1, 2};`) | 불가. 대상 타입이 필요하다 |

### 선택지 비교
| 선택지 | 장점 | 대가 |
|---|---|---|
| 타입을 직접 적기 | 코드만 봐도 타입이 보인다 | 제네릭처럼 긴 타입이면 줄이 길어진다 |
| `var` | 중복이 줄고 변수 이름과 흐름에 눈이 간다 | 오른쪽만으로 타입이 안 보이면 IDE 없이 읽기 어렵다 |

### 왜 쓰는가
핵심 이유는 같은 타입을 두 번 읽지 않고 변수 이름과 업무 흐름에 집중하기 위해서다.

```java
ArrayList<Long> ids = new ArrayList<Long>();
var ids = new ArrayList<Long>();

Map<Long, List<ReservationSeat>> seatsByReservation = groupSeats(reservations);
var seatsByReservation = groupSeats(reservations);
```

| 이유 | 설명 |
|---|---|
| 중복 제거 | `new`나 정적 팩터리로 오른쪽에 타입이 보이면 왼쪽 타입은 같은 정보의 반복이다 |
| 흐름 강조 | 변수 선언의 왼쪽이 가지런해지고 이름이 먼저 읽힌다 |
| 변경 범위 축소 | 메서드 반환 타입이 바뀌어도 사용법이 같으면 지역 변수 선언을 고치지 않아도 된다. 다만 사용법이 달라지면 컴파일 오류가 난다 |

이점의 전제는 타입을 몰라도 읽히는 것이다. `var sold = scheduleSeats.sellHeldSeats(...)`처럼 메서드 이름만으로 반환 타입을 짐작해야 하면 읽는 사람은 IDE를 봐야 하고, GitHub 리뷰 화면에서는 더 불편하다. 타입 정보가 읽는 데 필요하면 직접 적는다.

### 주의할 점
- `var list = new ArrayList<Integer>()`의 타입은 `List`가 아니라 `ArrayList<Integer>`다.
- `var list = new ArrayList<>()`는 `ArrayList<Object>`가 된다.
- `var`는 키워드가 아니라 예약된 타입 이름이다. 변수 이름으로는 쓸 수 있지만 클래스 이름으로는 쓸 수 없다.

## 이 프로젝트에서는
- `PaymentResultService`의 `var now = clock.instant();`, `scheduleSeatIds`의 `var ids = new ArrayList<Long>();`처럼 쓴다.
- `docs/guides/code-style.md` 1절은 `var`를 일괄 금지하거나 사용 자체를 목표로 삼지 않고, 문맥에서 이해하기 쉬운지로 고르게 한다.

### var를 모두 명시 타입으로 바꾸면 어떤가 (2026-11-05 추가 질문)
일괄 변경은 하지 않고, 오른쪽만으로 타입이 보이지 않아 오해할 수 있는 곳만 바꾼다. 일괄 변경은 `code-style.md` 1절과 맞지 않고, `new ArrayList<DrawEntrant>()`처럼 타입이 이미 보이는 줄에는 중복만 늘린다.

```java
var seatCount = lotteryRepository.lockForSuccession(lotteryId);
Optional<Integer> seatCount = lotteryRepository.lockForSuccession(lotteryId);
```

이름은 숫자처럼 읽히지만 실제 타입은 `Optional<Integer>`다. `insertedId`(`Optional<Long>`)와 `LotteryFinishService`의 `lottery`(`Optional<Lottery>`)도 같은 경우다. 요청 DTO는 메서드 매개변수로 받는 경우가 많고 매개변수에는 `var`를 쓸 수 없으므로 이미 타입이 적혀 있다.

## 면접 포인트
- `var`를 쓰면 동적 타입이 되는가: 아니다. 컴파일 시점에 타입이 정해지는 정적 타입이고, 바이트코드에도 추론된 타입이 들어간다.
- 언제 쓰지 않는가: `var result = service.process();`처럼 오른쪽만으로 타입을 알기 어려울 때다.
