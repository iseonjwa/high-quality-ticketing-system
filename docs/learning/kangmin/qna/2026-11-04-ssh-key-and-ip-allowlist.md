# 배포 서버 접속에 왜 SSH 공개 키와 내 IP를 모두 알려 줘야 하는가

## 질문
배포 서버 접속 준비로 `ssh-keygen`으로 만든 공개 키와 `checkip.amazonaws.com`으로 확인한 IP를 달라는 요청을 설명해 달라.

## 짧은 답
서버에 들어가려면 문을 두 개 통과해야 한다. 보안그룹은 "어디서 오는 연결인가"를 IP로 거르고, SSH는 "누구인가"를 키로 확인한다. 그래서 IP와 공개 키가 모두 필요하다. 공개 키는 공유해도 되지만 `.pub`이 없는 개인 키는 누구에게도 주면 안 된다. IP가 바뀌면 키는 그대로 두고 허용 IP만 새로 등록하면 된다.

## 자세히

### 두 개의 문
| 문 | 확인하는 것 | 필요한 정보 | 막혔을 때 흔한 증상 |
|---|---|---|---|
| AWS 보안그룹 | 출발지 IP | 내 공인 IP | 연결 시간 초과 |
| 서버의 SSH | 키 소유 | 내 공개 키 | `Permission denied (publickey)` |

둘을 함께 쓰는 이유는 한쪽이 뚫려도 다른 쪽이 남기 때문이다. 키가 유출되어도 허용 IP 밖에서는 연결이 닿지 않고, 같은 IP에 있어도 키가 없으면 로그인할 수 없다.

### 공개 키와 개인 키
| 파일 | 위치 | 공유 |
|---|---|---|
| `id_ed25519.pub` (공개 키) | 내 PC, 서버의 `~/.ssh/authorized_keys` | 가능 |
| `id_ed25519` (개인 키) | 내 PC에만 | 금지 |

접속할 때 서버가 공개 키로 확인할 수 있는 문제를 내고, 클라이언트가 개인 키로 서명해 답한다. 개인 키 자체는 네트워크로 나가지 않는다. 비밀번호 방식과 달리 서버가 털려도 공개 키만으로는 로그인할 수 없다.

### 왜 ed25519인가
| 선택지 | 특징 |
|---|---|
| ed25519 | 키와 서명이 짧고 빠르며 현재 일반적으로 권장된다 |
| RSA | 오래된 서버와의 호환성이 넓지만 충분한 길이를 쓰면 키가 길다 |

### IP는 왜 바뀌면 다시 알려야 하나
보안그룹은 등록된 IP만 통과시킨다. 집 인터넷의 공인 IP는 바뀔 수 있고 카페나 학원에서는 IP가 다르다. 이때 다시 알릴 것은 IP뿐이다. 키는 PC에 묶여 있으므로 PC를 바꾸지 않는 한 그대로 쓴다.

### Windows PowerShell에서 주의할 점
Windows PowerShell 5.1의 `curl`은 `Invoke-WebRequest`의 별칭이라 `-s` 옵션이 다르게 해석될 수 있다. `curl.exe`로 실행하면 실제 curl이 돈다.

## 이 프로젝트에서는
- SA 9-2와 ADR 0028 기준으로 SSH는 팀원 IP와 키 인증으로 제한한다.
- Grafana 같은 관리 화면은 공개하지 않고 SSH 터널로 연다(ADR 0045). 그래서 이 접속 준비는 시연 때 관리 화면을 보는 데도 쓰인다.

## 면접 포인트
- 서버 SSH 접근을 어떻게 제한했는가: 보안그룹으로 출발지 IP를 줄이고, 키 인증으로 사용자를 확인했다. 관리 화면은 공개하지 않고 SSH 터널로만 접근한다.
- 공개 키 인증이 비밀번호보다 나은 이유는 무엇인가: 비밀값이 네트워크로 나가지 않고, 서버에는 공개 키만 남으며, 무차별 대입 공격에 강하다.
