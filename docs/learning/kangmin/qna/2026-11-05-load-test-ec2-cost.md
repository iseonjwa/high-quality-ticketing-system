# m7i-flex.xlarge를 잠깐 띄워 통합·부하 테스트를 하면 비용이 걱정할 수준인가

## 질문
오후 2시에 AWS 서버를 잠깐 띄워 통합 테스트와 부하 측정을 하려 한다. 사양은 `m7i-flex.xlarge`다. 서버 비용이 걱정되는데 어떻게 보는가.

## 짧은 답
시간 단위 요금은 걱정할 수준이 아니다. 4시간에 약 1.4달러다. 끄는 것을 잊는 경우와 준비 없이 켜 두는 시간이 더 큰 비용이다. 비용보다 `m7i-flex`의 CPU 특성과 트레이스 샘플링처럼 측정값에 영향을 주는 조건을 먼저 정해야 한다.

## 자세히

### 1. 비용 (시드니 온디맨드 Linux)

| 항목 | 시간당 | 출처 |
|---|---|---|
| 배포 서버 `m7i-flex.xlarge` | 0.2394달러 | 2026-11-04 AWS 공식 가격 데이터(`docs/learning/junhyun/qna/2026-11-04-deploy-cost-and-single-host-db.md`) |
| 발생기 `c6i.large` | 0.111달러 | 2026-11-05 비공식 집계 사이트, 공식 가격과 대조 못 함 |
| 발생기 공인 IPv4 | 0.005달러 | 위 학습 노트 |

| 켜 둔 시간 | 배포 서버 | 발생기 | 합계 |
|---|---|---|---|
| 4시간 | 0.96달러 | 0.46달러 | 1.42달러 |
| 8시간 | 1.92달러 | 0.93달러 | 2.84달러 |
| 24시간(끄는 것을 잊음) | 5.75달러 | 2.78달러 | 8.53달러 |
| 7일(끄는 것을 잊음) | 40.22달러 | 19.49달러 | 59.71달러 |

배포 서버의 EBS와 탄력적 IP는 중지 중에도 과금되므로 위 표에 넣지 않았다. 실제 누적 지출은 AWS 콘솔에서 봐야 하고 여기서는 확인하지 못했다.

### 2. 인스턴스 선택

| 선택지 | 시간당 | 측정 관점 |
|---|---|---|
| `t3.xlarge` | 0.2112달러 | CPU 크레딧을 쓰는 버스트형이라 오래 부하를 주면 측정값이 흔들린다 |
| `m7i-flex.xlarge` | 0.2394달러 | 기준 성능은 vCPU당 40%이고, AWS는 대부분의 시간에 전체 성능까지 올라간다고만 설명한다 |
| `m7i.xlarge` | 0.252달러 | flex 차이 없이 고정 성능 계열이다 |

`m7i.xlarge`로 바꾸면 4시간에 약 0.05달러가 더 든다. 값을 발표나 기록의 근거로 쓸 측정이면 이 차이는 살 만하다. 인스턴스를 중지한 상태에서 유형을 바꿀 수 있고, 메모리는 16GiB로 같다. 다만 `m7i-flex.xlarge`는 팀이 정한 유형이므로 바꾸면 측정 환경 기록표와 담당자에게 알려야 한다. flex가 포화 측정에서 실제로 얼마나 떨어지는지는 측정해 보지 않았다.

이어서 물은 것: `m7i-flex.xlarge`는 동일한 측정 환경을 만드는 데 불리한가, 상관없는가.

불리하다. `m7i-flex`는 vCPU당 40%를 넘는 성능을 항상 보장하지 않으므로, CPU를 오래 높게 쓰는 측정에서 실행마다 같은 조건이라고 말하기 어렵다. 다만 실제로 값이 얼마나 달라지는지는 재지 않았다. 대략적인 동작 확인에는 문제가 없고, 전후 비교나 포화점 측정에는 고정 성능 계열이 낫다. 비교할 값은 같은 인스턴스 유형에서 재고, 어느 유형이든 같은 시나리오를 반복해 편차를 함께 기록한다.

### 3. 측정값에 영향을 주는 조건
- 배포 compose의 트레이스 샘플링은 1.0이고 `loadtest` 프로필은 0.01이다. 어느 값으로 측정할지 먼저 정한다(`docs/design/infra/deployment.md`).
- k6를 배포 서버에서 함께 돌리면 CPU를 나눠 써서 값이 왜곡된다. 발생기를 따로 띄운다(`docs/design/infra/load-test.md` 2절).
- ADR 0047은 11/7~11/12에 매니지드 서비스 분리를 검토한다. 분리하면 측정 대상 구성이 바뀌므로 그 전에 잰 값은 예비 측정으로 표시한다.

### 4. 다섯 명이 부하 테스트를 할 때

이어서 물은 것: 다섯 명이 부하 테스트를 하면 비용이나 측정에 영향이 있는가.

영향은 사람 수보다 서버 구성과 실행 시점이 만든다. 단가는 위 1절 값을 쓴다.

| 방식 | 시간당 | 4시간 | 측정 영향 |
|---|---|---|---|
| 배포 서버 1대 + 발생기 1대, 순서대로 실행 | 0.3554달러 | 1.42달러 | 실행 사이에 데이터를 초기화하면 결과를 나눠 볼 수 있다 |
| 배포 서버 1대 + 발생기 5대, 동시 실행 | 0.8194달러 | 3.28달러 | 부하가 합쳐지고 데이터를 공유해 개인별 결과로 해석할 수 없다 |
| 배포 서버 5대 + 발생기 5대 | 1.777달러 | 7.11달러 | 서로 간섭하지 않지만 다섯 벌을 준비해야 하고 장비 간 편차가 생길 수 있다 |

순서대로 실행하면 전체 시간이 길어진 만큼만 비용이 늘어난다. 동시에 잴 때는 측정 경계가 사라지므로 "동시 사용 부하"를 하나의 시나리오로 재는 경우가 아니면 피한다. 시간대를 나눠 실행자, 커밋, 시나리오, 시작·종료 시각을 기록하면 Grafana에서 구간을 구분할 수 있다. 측정 중 재배포도 값을 바꾸므로 멈춘다. 다섯 벌 방식의 EC2 vCPU 할당량은 확인하지 못했다.

## 이 프로젝트에서는
- 배포 서버는 끝나면 "중지"한다. "종료"는 EBS와 함께 DB 데이터를 지운다. 발생기는 임시 서버라 "종료"한다.
- 측정 데이터가 11/6 리허설에 남지 않게 끝난 뒤 시드 상태를 확인한다.

## 면접 포인트
- 부하 측정 환경의 비용은 단가보다 방치 시간이 좌우한다.
- 측정값을 내세우려면 장비 유형, 샘플링 비율, 발생기 분리 같은 조건을 값과 함께 기록해야 한다.
