# 추첨에서 관측하고 측정해야 할 요소는 무엇인가

## 질문
추첨에서 관측하고 측정해야 할 요소가 무엇인가.

## 짧은 답
- 관측은 운영 중 이상을 알아채는 것이고, 측정은 부하를 걸어 설계 판단의 근거를 얻는 것이다.
- 관측 대상은 흐름 단계별 지연·실패와, 좌석 초과 배정이나 결제 중복처럼 0이어야 하는 불변식이다.
- 측정 대상은 응모 몰림, 자동결제 폭주, 일반 예매 간섭의 세 시나리오다(ADR 0036).
- 처음에는 지표 4개뿐이었고, 같은 날 ISE-94에서 지표·대시보드·경보를 더했다. 추첨용 k6 시나리오는 아직 없다.

## 자세히

### 단계별 관측·측정 항목

| 단계 | 항목 | 기준 `[가정]` |
|---|---|---|
| 응모 | API p95, 처리량, 5xx와 409의 비율, 커넥션 대기 | p95 300ms 이하 |
| 추첨 | 실행 시간, 실패 횟수, 연속 실패 | 10초 이하 |
| 배정 | 당첨자 전원 배정 완료 시간, 배정 실패 수 | 기준 미정 |
| 자동결제 | 추첨부터 결제 완료까지의 시간, 승인 지연, 실패 사유, 허가 거절 | 10분 안에 95% |
| 승계 | 승계 수, 승계 지연, 예비자 소진 | 추첨 후 30분 안 |
| 종결 | 종결 지연, 남은 추첨석 | 추첨 후 60분 안 |
| 간섭 | 다른 회차의 선점 p95 변화, 일반 결제 503 비율, 커넥션 대기, CPU | 선점 p95 증가 20% 이하 |

### 0이어야 하는 불변식

| 불변식 | 확인 방법 |
|---|---|
| 배정 매수가 추첨석을 넘지 않는다 | `WON`·`PAID` 수량 합과 `seat_count` 비교 |
| 한 사용자의 중복 응모가 없다 | 유니크 제약과 SQL |
| 한 예매의 승인 결제가 하나다 | 예매·결제 대사 |
| 결제 결과가 응모에 반영된다 | `LOTTERY_RESULT_NOT_APPLIED` 로그 |
| 종결된 추첨에 추첨석이 남지 않는다 | `lottery.seats.remaining`과 상태 대조 |
| 메시지가 DLQ에 쌓이지 않는다 | `dead.letter.open.count` |

### 측정 시나리오

| # | 시나리오 | 판단하는 결정 | 조건 |
|---|---|---|---|
| 1 | 응모 마감 직전 초당 100건에서 포화점까지 | D3: 동기 INSERT 유지 또는 접수형 전환 | 응모자 30,000명 |
| 2 | 당첨 2,000건 자동결제와 다른 회차 일반 결제의 겹침 | D6: `pg-approve` 공유 유지 또는 전용 그룹 | 기준선과 개선안 비교 |
| 3 | 다른 회차 선점 부하 중 추첨·자동결제 실행 | D8·D10: 속도 상한, 시간 분리, lottery 분리 | 부하 있을 때와 없을 때 비교 |

시나리오 1의 "컨슈머 랙"은 접수형 전제의 지표다. 현재 구현은 동기 INSERT라 접수형과 비교할 때만 의미가 있다.

### 추천 순서
1. 추첨 지표를 먼저 더하고 Grafana 패널을 만든다. 지표 없이 측정하면 원인을 나눌 수 없다.
2. 시나리오 1을 로컬에서 먼저 확인한다.
3. 시나리오 2·3은 배포 서버와 발생기로 측정한다.

## 이 프로젝트에서는
- 기준과 시나리오: `docs/design/lottery/numbers-and-measurement.md`, `docs/decisions/0036-lottery-direction-measurement.md`
- 작업 이슈: ISE-94
- 지표 목록: `docs/design/lottery/numbers-and-measurement.md` 4절
- `reservation-service/k6`의 스크립트는 좌석 선점(K1)용이다.
- 추첨 실행 시간은 3만 행 기준 약 0.5초와 약 4.5초의 두 갈래로 측정됐고 원인은 확인하지 못했다.

## 면접 포인트
- 추첨처럼 몰림이 약해 보이는 기능에서 무엇을 측정했는가: 추첨 직후 자동결제가 PG 자원을 채워 다른 회차 일반 결제를 막는 문제처럼, 사후 처리의 간섭을 측정했다.
- 평균 대신 무엇을 보는가: 사용자 체감은 p95·p99로 보고, 정합성은 비율이 아니라 0이어야 하는 불변식으로 본다.
