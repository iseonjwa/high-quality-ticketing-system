# AWS 배포에 나오는 용어를 하나씩 풀면 무엇이고, 이 프로젝트에서는 어디에 쓰이는가

## 질문
(AWS 배포 구조 설명을 들은 뒤) 용어 하나씩 상세 설명해 달라.

## 짧은 답
용어는 세 묶음이다. **네트워크·장비**(리전부터 보안 그룹까지), **접속**(SSH, 터널), **배포 도구**(Actions, 이미지, GHCR, Jenkins, compose). 각 용어를 "무엇인가 → 왜 있나 → 이 프로젝트에서 → 헷갈리는 점" 순서로 푼다. 숫자·동작 중 이 저장소 문서로 확인하지 못한 것은 "확인 못 함"으로 적었다.

## 1. 네트워크·장비

### 리전 (Region)
- **무엇**: AWS 데이터센터가 모인 지리적 지역이다. 서울(`ap-northeast-2`), 시드니(`ap-southeast-2`)처럼 이름이 붙는다.
- **왜**: 사용자와 가까운 곳에 두면 지연이 작다. 리전끼리는 서로 독립이라 한 리전이 멈춰도 다른 리전은 돈다. 요금도 리전마다 다르다.
- **이 프로젝트**: 시드니. AWS 새 가입 방식이라 리전이 시드니로 고정됐다(`deployment.md` 1절). 그래서 한국에서 접속하면 지연이 서울보다 크다. 다만 부하 측정은 같은 리전 안 발생기에서 하므로 이 지연이 측정값에 섞이지 않는다.
- **헷갈리는 점**: EC2, VPC 같은 자원은 리전마다 따로다. 콘솔 오른쪽 위 리전이 다르면 서버가 "사라진" 것처럼 보인다.

### 가용 영역 (Availability Zone, AZ)
- **무엇**: 리전 안에서 전원·네트워크가 분리된 데이터센터 묶음이다. 리전 이름 뒤에 a, b, c를 붙인다(`ap-southeast-2a`).
- **왜**: 한 AZ에 화재·정전이 나도 다른 AZ는 산다. 진짜 고가용성은 서버를 여러 AZ에 나눠 둔다.
- **이 프로젝트**: 모든 서버가 `ap-southeast-2a` 하나에 있다. 단일 EC2라 AZ 장애에는 대비하지 않는다(ADR 0047이 감수한 점). 발생기를 같은 AZ에 두는 이유는 같은 AZ 안 사설 IP 통신이 무료이고 지연이 가장 작아서다. AZ가 다르면 전송량만큼 요금이 붙는다(요율은 확인 못 함).

### VPC (Virtual Private Cloud)
- **무엇**: AWS 안에 만든 나만의 가상 사설망이다. IP 대역(CIDR, 예: `172.31.0.0/16`)을 하나 갖는다.
- **왜**: 같은 AWS 건물에 다른 회사 서버도 있으니, 내 서버끼리만 통하는 울타리가 필요하다.
- **이 프로젝트**: `vpc-08032543fc446b5c7`. 서버 사설 IP가 `172.31.x.x`인 것으로 보아 계정에 처음부터 있는 기본 VPC로 보인다(확인 못 함).
- **헷갈리는 점**: VPC 안에 있다고 인터넷과 끊긴 것은 아니다. 인터넷으로 나가는 길(인터넷 게이트웨이)이 연결돼 있는지는 서브넷의 라우팅이 정한다.

### 서브넷 (Subnet)
- **무엇**: VPC의 IP 대역을 잘게 나눈 구역이다. 서브넷 하나는 AZ 하나에 속한다.
- **왜**: 인터넷에 열 서버(퍼블릭 서브넷)와 내부에만 둘 서버(프라이빗 서브넷, 예: DB)를 나눈다. 퍼블릭인지는 라우팅 표에 인터넷 게이트웨이로 가는 길이 있는지로 갈린다.
- **이 프로젝트**: 배포·Jenkins·발생기가 같은 서브넷 `subnet-07b3d9d0e31a7d35d`에 있다. DB도 배포 서버 안 컨테이너라 프라이빗 서브넷을 따로 두지 않았다. RDS로 분리하면(ADR 0047 결정 3) DB를 프라이빗 서브넷에 두는 설계가 생긴다.

### EC2 (Elastic Compute Cloud)
- **무엇**: AWS가 빌려주는 가상 서버다. 실행 중인 서버 하나를 인스턴스라고 부른다.
- **왜**: 실제 컴퓨터를 사지 않고 필요한 사양을 시간 단위로 빌린다.
- **인스턴스 유형 읽는 법**: `m7i-flex.xlarge`는 `m`(범용) + `7`(세대) + `i`(인텔) + `-flex`(기본 성능을 낮추고 값을 깎은 변형) + `xlarge`(크기). 이 프로젝트 값은 4 vCPU, 약 16GiB다. `c6i`의 `c`는 연산 최적화, `t3`의 `t`는 CPU 크레딧을 쌓아 쓰는 버스트형이다.
- **AMI**: 인스턴스를 만들 때 고르는 OS 이미지다. 이 프로젝트는 Ubuntu 24.04(x86)다.
- **이 프로젝트**: 배포 `m7i-flex.xlarge`, Jenkins `t3.small`, 측정 때만 발생기 `c6i.xlarge`.
- **헷갈리는 점**: `flex`와 `t` 계열은 CPU를 오래 높게 쓰면 성능이 일정하지 않을 수 있다. 측정값의 조건으로 함께 적는 이유다(11/5 비용 노트).

### EBS (Elastic Block Store)
- **무엇**: EC2에 붙는 네트워크 디스크다. `gp3`는 범용 SSD 유형이다.
- **왜**: 인스턴스를 껐다 켜도 데이터가 남아야 한다.
- **이 프로젝트**: 배포 서버 gp3 40GB. PostgreSQL·Kafka 데이터가 Docker 볼륨으로 이 디스크에 있다. 백업은 없다(ADR 0047).
- **헷갈리는 점**: 중지(Stop)하면 EBS가 남고 디스크 요금은 계속 나간다. 종료(Terminate)하면 루트 디스크는 기본 설정상 함께 지워진다. 배포 서버를 "종료"하면 DB가 사라진다.

### 사설 IP와 공인 IP, 탄력적 IP
- **사설 IP**: VPC 안에서만 통하는 주소(`172.31.4.93`). 서브넷 대역에서 받고, 중지·시작해도 그대로다.
- **공인 IP**: 인터넷에서 찾아오는 주소. 자동 할당 공인 IP는 중지·시작하면 바뀐다.
- **탄력적 IP**: 계정에 묶어 두는 고정 공인 IP. 서버를 껐다 켜도 같은 주소라 팀원 접속 설정과 시연 URL이 안 바뀐다.
- **이 프로젝트**: 배포 서버에 탄력적 IP 하나. Jenkins는 배포 서버의 **사설 IP**로 SSH한다. 배포 서버 보안 그룹의 "Jenkins 보안 그룹에서 오는 22" 규칙은 VPC 안 사설 IP로 온 연결에만 맞기 때문이다(`deployment.md`).
- **헷갈리는 점**: 공인 IPv4 주소는 쓰는 동안 시간당 요금이 붙는다(11/5 노트: 시간당 0.005달러).

### 보안 그룹 (Security Group)
- **무엇**: 인스턴스 앞에 붙는 방화벽 규칙 묶음이다. "어떤 포트로, 누가(소스) 들어올 수 있나"를 허용 규칙으로만 적는다.
- **인바운드·아웃바운드**: 들어오는 연결과 서버가 먼저 여는 나가는 연결을 따로 정한다.
- **상태 저장(stateful)**: 허용된 요청의 응답은 규칙 없이도 돌아간다. 들어온 SSH의 응답은 아웃바운드 규칙이 없어도 나간다.
- **소스로 보안 그룹 지정**: IP 대신 "이 보안 그룹이 붙은 서버들"을 허용할 수 있다. 발생기를 다시 만들어 IP가 바뀌어도 규칙을 안 고친다.
- **이 프로젝트**: 배포 서버는 80 전체, 22 팀원 IP와 Jenkins 보안 그룹, 3000(Grafana) 팀원 IP, 8080은 측정 중 발생기 보안 그룹만. 첫 배포 때 아웃바운드 규칙이 없어 서버가 GitHub·GHCR로 못 나갔다(TS-33). 상태 저장이라 들어온 SSH는 됐기 때문에 원인을 찾기 어려웠다.

## 2. 접속

### SSH
- **무엇**: 원격 서버에 암호화된 연결로 들어가 명령을 치는 방법이다. 기본 포트 22.
- **키 인증**: 내 PC에 개인 키, 서버 `~/.ssh/authorized_keys`에 공개 키를 둔다. 개인 키를 가진 사람만 들어간다. 비밀번호 로그인보다 안전하다.
- **이 프로젝트**: 팀원은 자기 공개 키를 서버 담당에게 주고, 집 IP를 보안 그룹 22 규칙에 등록한다. IP가 바뀌면 접속이 막힌다.

### SSH 터널 (로컬 포트 포워딩)
- **무엇**: SSH 연결 안에 다른 포트의 통신을 실어 나르는 방법이다. `ssh -L 9090:127.0.0.1:9090 서버`는 "내 PC의 9090으로 온 요청을 서버 안의 9090으로 보내라"는 뜻이다.
- **왜**: Prometheus 같은 관리 화면을 인터넷에 열지 않고도 내 브라우저에서 `localhost:9090`으로 본다. 보안 그룹은 22만 열면 된다.
- **이 프로젝트**: Prometheus·Alertmanager·Zipkin·Kafka-UI, Jenkins 화면을 터널로 본다(`deploy-server-access.md`). 터널을 켜 둔 터미널을 닫으면 화면도 끊긴다.

## 3. 배포 도구

### 컨테이너 이미지와 태그
- **이미지**: 앱 실행에 필요한 것(JAR, JDK, 설정)을 한 덩어리로 묶은 실행 묶음이다. 컨테이너는 이미지를 실행한 상태다.
- **태그**: 이미지 버전 이름이다(`ghcr.io/iseonjwa/reservation-service:<커밋 SHA>`).
- **이 프로젝트**: 태그를 40자 커밋 SHA 하나로만 붙인다. `latest`처럼 가리키는 대상이 바뀌는 태그를 쓰면 서버에 무엇이 떠 있는지 알 수 없다.

### 컨테이너 레지스트리, GHCR
- **무엇**: 이미지를 올리고 받는 저장소다. Docker Hub, AWS ECR, GitHub의 GHCR(`ghcr.io`)이 있다.
- **이 프로젝트**: GHCR. GitHub Actions가 자동으로 주는 `GITHUB_TOKEN`으로 올려 개인 토큰을 비밀값으로 둘 필요가 없다.

### GitHub Actions
- **무엇**: GitHub에 붙은 CI 서비스다. `.github/workflows/*.yml`에 "언제(push, PR) 무엇을(테스트, 빌드)"을 적으면 GitHub 서버에서 돈다.
- **이 프로젝트**: `build.yml`이 PR마다 테스트, `images.yml`이 main에 들어오면 이미지 8개를 빌드해 GHCR에 올린다. `records-check`도 여기서 돈다.

### Jenkins
- **무엇**: 직접 띄우는 자동화 서버다. 배포 절차를 `Jenkinsfile`(파이프라인)로 적는다. 비밀값은 Jenkins Credentials에 둔다.
- **이 프로젝트**: Jenkins EC2(`t3.small`)가 배포만 맡는다. SSH 키와 슬랙 웹훅 주소가 Credentials에 있다.

### 폴링과 웹훅
- **폴링**: 내가 주기적으로 "새 것 있어?"라고 묻는다. 늦게 알지만 바깥에서 나를 부를 필요가 없다.
- **웹훅**: 일이 생기면 상대가 나를 부른다. 바로 알지만 내 주소가 바깥에 열려 있어야 한다.
- **이 프로젝트**: Jenkins가 main을 2분마다 폴링한다. Jenkins를 인터넷에 열지 않으려는 선택이다. 그래서 측정 중 main에 머지하면 2분 안에 서버가 바뀐다.

### docker compose
- **무엇**: 여러 컨테이너(앱, DB, Kafka 등)를 YAML 하나로 정의하고 함께 띄우는 도구다.
- **덮어쓰기 파일**: `-f compose.yml -f compose.deploy.yml`처럼 여러 파일을 겹치면 뒤 파일이 앞 파일을 덮는다. 이 프로젝트는 배포용 이미지 주소·메모리 상한만 `compose.deploy.yml`에 둔다.
- **`pull`**: 레지스트리에서 이미지를 받는다. **`up -d`**: 컨테이너를 만들고 백그라운드로 띄운다. 이미지나 설정이 바뀐 컨테이너만 다시 만든다.
- **헬스체크**: compose의 `healthcheck`가 컨테이너 준비 여부를 검사하고, `depends_on: condition: service_healthy`는 그 준비가 끝난 뒤 다음 컨테이너를 띄운다(`compose.yml`).

### 스모크 테스트와 되돌림(롤백)
- **스모크 테스트**: 배포 직후 "최소한 켜지기는 했나"를 보는 가벼운 확인이다. 이 프로젝트는 Gateway 헬스, 가입·로그인, 공연 목록이다.
- **되돌림**: 헬스나 스모크가 실패하면 직전에 성공한 SHA 태그로 다시 배포한다. 태그를 SHA로 고정했기 때문에 가능하다.

### .env와 비밀값
- **무엇**: 비밀번호·서명 키·웹훅 주소를 코드 밖 파일(`.env`)에 두고 환경 변수로 넘긴다.
- **이 프로젝트**: 서버 `.env`와 Jenkins Credentials에만 있고 저장소에는 자리표시자만 둔다(AGENTS.md 대전제 8).
- **k6와의 관계**: JWT 서명 키는 "이 키를 가진 쪽이 유효한 토큰을 만들 수 있다"는 뜻이다. 그래서 서버 서명 키를 발생기에 넘기는 안은 키가 서버 밖으로 나간다는 대가가 있다.

## 이 프로젝트에서는
- 11/9 서버 기동 → 재배포·시드 → 장애 주입 순서에서 이 용어들이 모두 나온다. 서버를 켜는 것(EC2·EBS·탄력적 IP), 접속(SSH·보안 그룹 22), 화면 보기(Grafana 3000·SSH 터널), 재배포(Actions·GHCR·Jenkins·compose).

## 면접 포인트
- 보안 그룹은 상태 저장 방화벽이라 "들어오는 SSH는 되는데 서버에서 나가는 연결만 안 된다"면 아웃바운드 규칙부터 본다(TS-33).
- 관리 화면을 SSH 터널로 보면 보안 그룹에 22 하나만 열어도 된다.
- 폴링과 웹훅은 "바로 아는 것"과 "내 서버를 바깥에 여는 것"을 맞바꾸는 선택이다.
