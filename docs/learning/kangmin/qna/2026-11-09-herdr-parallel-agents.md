# herdr로 에이전트 여러 개를 한 저장소에서 동시에 굴리려면 무엇을 지켜야 하나

## 질문
herdr로 여러 에이전트를 동시에 굴리며 병렬 작업하려 한다. 사용 방법은?

## 짧은 답
- herdr는 코딩 에이전트용 터미널 멀티플렉서다(tmux와 비슷하다). 구조는 세션(백그라운드 서버) → 워크스페이스(프로젝트) → 탭(화면 배치) → 페인(실제 터미널)이다. 페인 안의 `claude`·`codex`를 알아보고 상태(working, blocked, done, idle)를 사이드바에 보여 준다.
- 설치는 확인했다. 버전 0.9.5이고 Claude 연동 훅(v11)은 설치돼 있다. Codex 연동은 설치돼 있지 않다.
- 병렬 작업의 핵심은 도구가 아니라 쓰기 충돌이다. 이 저장소는 `dev` 한 체크아웃에 고정하고 워크트리를 쓰지 않는다. 그래서 에이전트마다 고칠 파일 범위를 겹치지 않게 나눈다.

## 자세히

### 1. 기본 조작 (기본 키, prefix = Ctrl+B를 누르고 뗀 뒤 다음 키)
| 동작 | 키 |
|---|---|
| 오른쪽으로 나누기 | prefix, v |
| 아래로 나누기 | prefix, - |
| 페인 이동 | prefix, h/j/k/l |
| 페인 크게 보기 | prefix, z |
| 새 탭, 다음·이전 탭 | prefix, c / n / p |
| 알림 대상으로 가기 | prefix, o |
| 키 목록 | prefix, ? |
| 빠져나오기(계속 실행) | prefix, q |
| 전부 끄기 | `herdr server stop` |

마우스로도 다 된다.

### 2. 같은 체크아웃에서 충돌을 막는 규칙
| 규칙 | 이유 |
|---|---|
| 에이전트 하나가 고칠 파일 범위를 하나만 맡는다 | 두 에이전트가 같은 파일을 고치면 나중에 쓴 쪽이 덮는다 |
| 기록 색인(`docs/learning/kangmin/README.md`, `docs/ai-judgments/kangmin/README.md`)은 모두가 고친다. 고치기 직전에 다시 읽게 한다 | 색인 한 줄 추가가 가장 흔한 충돌 지점이다 |
| `git checkout`·`stash`·`reset`·커밋은 에이전트에게 맡기지 않는다 | 한 에이전트의 브랜치 전환이 다른 에이전트의 작업 파일을 바꾼다 |
| Gradle 빌드·테스트는 한 번에 하나만 돌린다 | `build/` 폴더와 Gradle 데몬을 같이 쓴다 |
| 서버 SSH 페인은 에이전트 없이 사람이 쓴다 | 측정은 한 번에 한 명이고 측정 모드는 계정 담당만 켠다 |

### 3. 고른 이유와 감수한 점
- 선택지: (A) 같은 체크아웃에서 파일 범위로 나누기, (B) 에이전트마다 워크트리 만들기(`herdr worktree create`).
- A를 고른 이유: 개인 규칙상 `dev` 고정, 워크트리를 만들지 않는다. 오늘 작업은 문서·k6 스크립트·Linear 답글이라 파일 범위가 자연스럽게 갈린다.
- 감수한 점: 색인 파일은 겹친다. 코드 두 곳을 동시에 크게 고치는 일은 이 방식에 맞지 않는다.
- 바꿀 조건: 같은 모듈의 Java 코드를 두 에이전트가 동시에 고쳐야 하면 B로 바꾼다. 예를 들어 추첨 조회 API와 ISE-207 구현이 겹칠 때다.

### 4. 지휘자 한 명 + 단위별 작업자 방식 (추가 질문)
- 질문: 메인 지휘자 하나가 작업자 에이전트를 단위마다 열고 닫으며 일을 시키고, 사람은 지휘자 화면만 보며 결정만 넣는 방식은 어떤가.
- 선택지
  | 안 | 방식 | 얻는 것 | 대가 |
  |---|---|---|---|
  | A | 사람이 herdr 페인마다 직접 지시 | 단순하다 | 사람이 모든 페인을 오가야 한다 |
  | B | 지휘자 Claude가 `herdr agent start`·`agent prompt --wait`·`pane close`로 작업자를 운영 | 사람은 화면 하나만 본다. 단위마다 새 맥락이라 작업자 결과가 섞이지 않는다 | 지휘자가 작업자 화면을 다 읽으면 지휘자 맥락이 빨리 찬다. 작업자 승인 대기는 사람이 답해야 한다 |
  | C | 한 Claude 세션 안의 서브에이전트(Agent 도구) | 설정이 없다 | 진행이 화면에 안 보이고 중간에 끼어들기 어렵다 |
- 추천: B. 조건은 세 가지다.
  - 작업자는 결과를 짧은 파일로 남기고, 지휘자는 그 파일만 읽는다.
  - 동시에 도는 작업자는 2개까지다.
  - 지휘자는 작업자의 승인 질문에 대신 답하지 않는다.
- 감수한 점: 작업자를 열 때마다 프로젝트 맥락을 다시 읽어 시간과 토큰이 든다.
- 바꿀 조건: 한 단위가 10분 안에 끝나는 작은 일만 남으면 A로 돌아간다. 지휘자를 두는 비용이 더 크기 때문이다.
- 운영 규칙과 작업판은 개인 파일 `docs/context/conductor.md`에 있다(git 제외).
