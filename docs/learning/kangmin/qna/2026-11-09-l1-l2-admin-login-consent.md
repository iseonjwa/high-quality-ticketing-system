# L1·L2 k6 스크립트의 관리자 로그인 문제를 풀 때 왜 계정 담당 동의가 필요한가

## 질문
L1·L2의 `adminLogin` 문제에 준현 동의가 필요한 이유는 무엇이고, 이 문제를 다루는 Linear 이슈가 있나.

## 짧은 답
- L1·L2는 `setup()`에서 `adminLogin()`으로 회차와 추첨을 직접 만든다(`l1-lottery-entry.js` 49~54행, `l2-lottery-billing.js` 45~57행). 그러려면 발생기에 관리자 비밀번호가 있어야 한다.
- ADR 0046 변경(2026-11-08, ISE-191, 결정자 안준현)이 "운영 키와 운영 관리자 비밀번호는 발생기에 두지 않는다"로 정했다. 이 규칙을 정한 사람이 계정 담당이다.
- 두 해결안 모두 계정 담당 영역에 닿는다. 그래서 동의가 필요하다.
- 2026-11-09 Linear 검색 기준으로 이 문제만 다루는 이슈는 없다. 가장 가까운 것은 ISE-191(측정 기반, 담당 안준현, contract)인데 본문에 관리자 로그인 항목이 없다.

## 자세히

| 안 | 내용 | 계정 담당 동의가 필요한 이유 |
|---|---|---|
| 1 (추천) | 서버에서 회차·추첨을 만들고 k6는 ID만 받는다. Q1~Q3의 `SCHEDULE_ID` 방식과 같다 | 서버의 회차·추첨 생성은 `seed-demo.sh`(ISE-177, 계정 담당 작성)가 배포 서버 `.env`의 관리자 계정으로 한다. 추첨 생성 기능을 더하려면 이 공유 스크립트를 고쳐야 하고, 측정용 회차·추첨이 시연 DB에 쌓인다 |
| 2 | 측정 동안만 쓰는 관리자 계정을 만들고 끝나면 지운다 | ADR 0046 규칙의 예외를 만든다. 규칙을 정한 사람의 동의 없이는 바꿀 수 없다(AGENTS.md "팀 합의를 개인 판단으로 덮어쓰지 않는다") |

- 1안은 규칙을 지키므로 동의의 무게가 가볍다. 공유 스크립트 변경을 알리는 수준(대전제 11번 `contract` 이슈)이다.
- 2안은 결정 자체를 바꾸므로 결정자의 동의와 ADR 변경 기록이 필요하다.
