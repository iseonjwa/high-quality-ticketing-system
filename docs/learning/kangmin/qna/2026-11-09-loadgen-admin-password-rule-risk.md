# "운영 관리자 비밀번호를 발생기에 두지 않는다" 규칙의 배경과, 서버 추첨 생성(1안)이 남기는 위험

## 질문
규칙이 나온 배경은 무엇이고, 1안(서버에서 추첨을 만들고 k6는 ID만 받음)이 결국 발생기에 비밀번호를 두는 것은 아닌가. 남는 위험은 없나.

## 짧은 답
- 배경: ADR 0046(11/3)이 "측정용 토큰 서명 때문에 운영 키를 측정 도구에 넣는 위험"을 감수 항목으로 적었고, 11/8 변경(ISE-191, 결정 안준현)이 측정 동안만 버리는 키를 쓰고 운영 키와 운영 관리자 비밀번호는 발생기에 두지 않기로 풀었다.
- 1안은 발생기에 비밀번호를 두지 않는다. `seed-demo.sh`는 배포 서버 안에서 서버의 `.env`를 읽어 로그인하고, 발생기에는 추첨 ID(숫자)만 간다.
- 다만 측정 모드 동안 발생기에 있는 측정 전용 서명 키로는 관리자 토큰(`role=ADMIN`)도 만들 수 있다. Gateway는 서명이 맞으면 `role` claim만 보고 관리자 API를 통과시킨다(`GatewayAuthenticationFilter` 76행). 이 위험은 1안과 상관없이 측정 모드 자체에 있다.

## 자세히

### 왜 비밀번호와 측정 키를 다르게 다루나

| | 운영 관리자 비밀번호 | 측정 전용 서명 키 |
|---|---|---|
| 수명 | 바꾸기 전까지 계속 유효 | `measure-mode.sh off` 때 버린다. 그 뒤 만든 토큰은 서버가 거부한다 |
| 쓰이는 곳 | 시연 화면 관리자 로그인, `seed-demo.sh`, 다른 서비스에 재사용됐을 수도 있음 | 측정하는 몇 시간 동안의 이 서버 하나 |
| 새면 | 측정이 끝난 뒤에도 관리자 권한이 남는다 | 측정 모드 동안만 권한이 있다 |

그래서 규칙은 "오래 사는 자격 증명은 발생기에 두지 않고, 짧게 사는 키만 둔다"는 뜻이다(최소 권한·짧은 수명).

### 1안에서 남는 위험

| 위험 | 크기 | 줄이는 방법 |
|---|---|---|
| 측정 모드 동안 측정 키로 관리자 토큰을 위조할 수 있다 | 측정 시간 동안만. 발생기 SSH는 팀원 IP만 열려 있다 | 측정 뒤 바로 `off`, 발생기 `.env` 삭제(가이드 5절). 1안이든 아니든 같다 |
| `seed-demo.sh`가 서버에서 관리자 로그인을 한다 | 서버 안에서만 일어난다. 비밀번호는 출력·인자·프로세스 목록에 남지 않게 이미 짜여 있다 | 기존 방식 유지 |
| 스크립트가 틀린 비밀번호로 반복 로그인하면 5회 실패 잠금(ADR 0007)으로 시연 관리자 계정이 잠긴다 | 낮음. `.env` 값을 그대로 쓴다 | 첫 실패에서 바로 끝나는 지금 구조 유지 |
| 측정용 공연·회차·추첨이 배포 DB에 쌓여 시연 화면에 보인다 | 시연 품질 문제 | 별도 공연 제목. ISE-216에서 AWS 담당 확인 |

### 확인 못 한 것
- 측정 키로 서명한 `role=ADMIN` 토큰이 실제로 관리자 API를 통과하는지는 실행해 보지 않았다. 코드상 Gateway가 `role`만 본다는 것까지 확인했다.
