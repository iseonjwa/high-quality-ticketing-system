# 응답 시간의 p50·p95·p99는 무슨 뜻이고, 왜 평균 대신 쓰나

## 질문
p50, p95, p99가 무슨 뜻인가.

## 짧은 답
- 백분위수(percentile)다. 응답 시간을 빠른 순으로 줄 세웠을 때 앞에서 50%·95%·99% 위치의 값이다.
- p95 = 16.6ms는 "요청 100개 중 95개는 16.6ms 안에 끝났고, 느린 5개는 그보다 오래 걸렸다"는 뜻이다.
- 평균은 느린 소수를 가린다. p95·p99는 느린 사용자가 겪는 시간(꼬리 지연, tail latency)을 보여 준다.

## 자세히

### 1. 예시: 요청 10개
응답 시간(ms)을 정렬: 5, 6, 6, 7, 7, 8, 8, 9, 10, 500

| 지표 | 값 | 뜻 |
|---|---|---|
| 평균 | 56.6 | 500ms 한 건이 끌어올려 대부분의 사용자 경험과 다르다 |
| p50(중앙값) | 7~8 | 보통 사용자 |
| p90 | 10 | 10명 중 9명은 이 안 |
| p99 | 500 근처 | 가장 느린 1%. 표본이 적으면 최댓값과 같아진다 |

### 2. 무엇을 볼 때 쓰나
| 지표 | 보는 것 | 이 프로젝트에서 |
|---|---|---|
| p50 | 평소 속도 | L1 800단계에서 7 → 58.9ms로 뛰면 전체가 밀린다는 신호 |
| p95 | 합격 기준에 주로 씀 | 응모 p95 300ms 이하, 선점 p95 증가 20% 이하(ADR 0036) |
| p99 | 장애 직전의 꼬리 | L1 400단계에서 p99만 두 배(56 → 119ms). 평균·p50은 그대로라 p99가 먼저 경고한다 |

### 3. 주의점
- 백분위수는 더하거나 평균 내지 않는다. 서비스 A p95 + 서비스 B p95는 전체 p95가 아니다.
- 실패 응답을 섞으면 왜곡된다. L1 전체 p95 51.2ms는 1ms대 503이 섞여 낮아진 값이고, 성공만 보면 141.1ms다.
- p99는 요청이 적으면 흔들린다. 요청 100건이면 p99는 사실상 최악 1건이다.
- k6는 `summaryTrendStats`로 어떤 백분위수를 출력할지 정한다(`l1-lottery-entry.js`는 avg·min·med·p95·p99·max).
