# 측정 모드(measure-mode.sh)는 왜 AWS 담당만 켜나

## 질문
측정 모드를 왜 AWS 담당만 켤 수 있나.

## 짧은 답
- 기술적으로 막혀 있는 것은 아니다. 팀원 모두 같은 `ubuntu` 계정(`sudo`, `docker` 권한)으로 들어가므로 누구나 실행은 할 수 있다(`deploy-server-access.md` 82행).
- 팀 규칙으로 정했다(ADR 0046 변경, 2026-11-08, ISE-191). 문서에는 "계정 주인만 쓴다"고 적혀 있고, 계정 주인과 AWS 담당은 같은 사람이다.
- 이유는 이 스크립트가 다른 명령과 달리 운영 서버 전체 상태와 비밀값을 건드리기 때문이다.

## 자세히

### 1. 이유 네 가지 (문서·스크립트로 확인)
| 이유 | 근거 |
|---|---|
| "서버에서 직접 `docker compose up` 하지 않는다" 규칙의 유일한 예외다. 배포는 main 머지 → Jenkins로만 하고, 손으로 바꾸면 기록(`.deploy/current`)과 실제 상태가 어긋난다. 예외를 한 사람에게 묶어 두면 누가 언제 바꿨는지 추적된다 | `deploy-server-access.md` 87행, `measure-mode.sh` 주석 |
| 비밀값을 다룬다. 서버 `.env`(운영 키·관리자 비밀번호) 옆에 측정 전용 키 `.env.measure`를 만들고, 그 키를 발생기로 옮긴다. 팀 규칙상 서버 `.env`는 열거나 복사하지 않는다 | `deploy-server-access.md` 88·146행, `loadgen.md` 153행 |
| 영향이 서버 전체에 미친다. 스택을 다시 띄우고, 서명 키가 바뀌어 모든 사용자의 로그인이 끊기며, 9090을 연다 | `measure-mode.sh` 주석, ADR 0046 |
| Jenkins와 같이 움직여야 한다. 측정 중 main 머지로 배포가 돌면 측정 모드가 풀리므로, 켜는 사람이 Jenkins 잡을 끄거나 머지를 멈춰야 한다. Jenkins와 AWS 콘솔을 관리하는 사람이 AWS 담당이다 | `deploy-server-access.md` 145·148행 |

### 2. 고른 이유와 감수한 점
- 선택지: (A) 측정자가 직접 켜고 끔, (B) 한 사람(AWS 담당)이 켜고 끔.
- B를 고른 이유: 운영 서버 상태와 비밀값을 바꾸는 사람을 한 명으로 두면 두 사람이 동시에 켜고 끄거나, 끄는 것을 잊거나, 키가 여러 사람 손을 거치는 일이 줄어든다.
- 감수한 점: 측정할 때마다 AWS 담당의 시간이 필요하다. AWS 담당이 바쁘면 측정이 밀린다.
- 바꿀 조건: 측정이 잦아져 AWS 담당이 병목이 되면, 측정자에게 위임하는 절차(켜기·끄기 체크리스트, 채널 알림)를 정하고 ADR 0046에 변경을 적는다.

### 3. 이번 작업과의 관계
- `seed-demo.sh lottery`는 측정 모드와 다르다. 스택을 다시 띄우지 않고 API만 부른다. 다만 서버 `.env`의 관리자 비밀번호를 스크립트가 읽으므로, 측정자가 직접 실행해도 되는지는 ISE-216에서 AWS 담당에게 따로 물었다(확인 항목 3).
