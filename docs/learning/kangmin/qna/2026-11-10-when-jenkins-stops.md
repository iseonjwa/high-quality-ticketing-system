# Jenkins 서버가 꺼질 일이 있나, 접속이 안 되면 꺼진 것인가

## 질문
11/10 영은님 측정이 끝난 뒤 상태를 점검했다. Jenkins 서버 `3.107.168.36:22`가 응답하지 않아 에이전트가 "꺼져 있을 가능성"이라고 했다. Jenkins가 꺼질 일이 있나?

## 짧은 답
- **스스로 꺼지지는 않는다.** 측정 모드 `on/off`는 Jenkins를 건드리지 않는다(`script/loadtest/measure-mode.sh`에 Jenkins 호출이 없다).
- **꺼지는 경우는 사람이 EC2를 멈출 때다.** 비용 일정(ADR 0047: 11/7~11/12 중지 계획)이나 지출 한도 때문에 멈춘다.
- **응답이 없다고 꺼졌다고 단정할 수 없다.** Jenkins EC2는 탄력적 IP가 없어서 멈췄다 켜면 공인 IP가 바뀐다. 문서의 `3.107.168.36`은 11/5 기준 주소다.

## 자세히

| 원인 | 근거 | 이번에 맞나 |
|---|---|---|
| EC2 중지(비용 일정) | ADR 0047에 11/7~11/12 중지 계획이 있다 | 계획과 달리 배포 서버는 11/9에 다시 켜져 있었다. 일정은 바뀌었다 |
| 재가동 뒤 공인 IP 변경 | `deploy-server-access.md` 1절 "서버를 끄고 켤 때마다 바뀜" | 가능성이 가장 크다 |
| 보안 그룹이 내 IP를 막음 | Jenkins SG는 22를 팀원 IP에만 연다 | 같은 IP로 배포 서버에는 들어갔으니 가능성은 낮다. Jenkins SG에도 등록됐는지는 확인하지 못했다 |

- 배포 기록 `.deploy/current`가 11/9 23:00에 머지된 `0e77953`이다. 배포는 Jenkins로만 하므로, 그 시각 이후 Jenkins가 켜져 있었다고 본다(Jenkins 빌드 기록은 확인하지 못했다).
- 공인 IP가 바뀌어도 배포는 끊기지 않는다. Jenkins는 배포 서버에 사설 IP(`172.31.4.93`)로 붙고, 사설 IP는 재가동해도 그대로다(`design/infra/deployment.md` 230행).
- 바뀌는 것은 사람이 쓰는 SSH·터널 주소뿐이다. 새 주소는 담당(준현)이나 AWS 콘솔에서 확인한다.

## 확인할 질문
- Jenkins EC2가 지금 running인가, 공인 IP는 무엇인가?
- Jenkins 마지막 빌드가 `0e77953`인가?
