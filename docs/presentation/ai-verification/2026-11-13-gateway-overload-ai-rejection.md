# 사례 가안 1. Gateway CPU 포화: AI 추천을 거부하고 실험으로 닫은 뒤 동시 처리 상한 64를 고름

가안이다. 판단자(강민)가 내용과 숫자를 확인한 뒤 확정한다. 숫자 출처는 [Gateway 과부하 발표 소스](../2026-11-12-gateway-overload-source.md) 장면 3·5, TS-57·TS-59다.

## 1. 해결하려던 작업
배포 서버 4차 측정에서 초당 2,500건부터 서버 CPU가 99%가 되고 성공 처리량이 약 2,300~2,470/s에서 멈췄다. 차단기 실험을 겸한 5차(0a)에서는 초당 1,500건에서 CPU 93%, 2,000건에서 99%가 됐고 굿풋(200ms 안에 끝난 성공 요청 수/초)은 약 1,469/s에서 멈췄다. 5차에서 Gateway는 메모리 한도(768MiB)를 넘어 세 번 강제 종료(OOM)됐다.

## 2. Claude Code 활용 방식
Claude Code 세션을 역할별로 나눴다. 메인 세션은 다음 장치 추천과 6차 128 제안 검토, 구현 세션은 필터 설계안(상한 500), 5차 실험 세션은 측정과 상한 64 근거를 맡았다. AI는 처음부터 "맨 앞에서 유입을 제한하라"고 추천했다.

판단 기록의 "AI 활용 방식" 칸에 남은 질문은 차례로 셋이다. 장비 CPU가 한도에 닿기 전에 차단기가 열려야 하지 않느냐고 물었고, 차단기가 열리지 않자 다음 장치를 무엇으로 할지 물었다. 고른 장치의 설계(필터 위치, 세는 단위, 상한값, 거절 응답, 예외 경로, 지표)는 구현 전에 받았다.

## 3. 채택·수정·기각 이유
| 순서 | AI 제안 | 판단 | 이유 |
|---|---|---|---|
| 1 | 맨 앞 유입 제한부터 | **거부**, 차단기 실험을 먼저 | 기존 장치(auth-redis 차단기)를 예민하게 하면 포화 전에 열리는지 숫자로 먼저 확인하려 했다 |
| 2 | (실험 결과를 보고) 동시 처리 수 상한 | 수용 | 느린 호출 기준을 20ms까지 낮춰도 느린 호출 비율이 최대 24%(열림 기준 80%)라 차단기가 열리지 않았다. 기다림이 차단기가 재는 구간 밖에 있었다 |
| 3 | 상한 500(구현 세션 설계안) | 실험 세션 안 64 수용 | 500은 리틀의 법칙에 p95를 넣은 값이다. 실험 세션이 식의 전제대로 평균 응답으로 계산하면 60~67이었다(AI 두 세션의 계산이 갈렸고 식의 전제에 맞는 쪽을 고름) |
| 4 | 6차에서 128로 올리기 | **거부**(6차 세션의 128), 메인 세션의 64 유지 추천 수용 | 굿풋 차이 1.5%가 같은 값 반복 측정 차이(5%) 안이고, p95는 128이 약 두 배였다 |

## 4. 빌드·테스트·API 검증 결과
- 같은 날 초당 2,000건 비교(배포는 다름): 상한 없음 굿풋 1,469/s·p95 435ms(5차 0a) → 상한 64 굿풋 1,696/s·p95 87ms(6차). 6차는 메모리 증설(M1, 1,024MiB)을 함께 넣은 상태라 Gateway 메모리가 511~540MiB로 평탄했고 OOM은 0회였다. 5차의 OOM 3회는 웜업과 3,000/s에서 났다.
- 대조군: 상한 500은 굿풋 1,304/s·p95 571ms로 상한 없음과 비슷했다. 상한 128은 1,721/s·162ms.
- `./gradlew :gateway:test` 107개 → 118개 모두 통과. 변이 6개(반납 제거, 거절 때 되돌리기 제거, `defer` 제거 두 곳, 경계 `>`를 `>=`로, 운영자 경로 예외 제거)를 모두 잡았다.

## 5. 팀이 직접 내린 MSA 설계 판단
팀이 정한 전제는 모든 서비스를 EC2 한 대에 띄우는 배포다(ADR 0047). 그 전제 위에서 강민은 Gateway를 맨 앞 부하 차단 지점으로 정했다. 넘치는 요청은 503 + `Retry-After` + `GATEWAY_OVERLOADED`로 바로 거절하고, 이 계약과 프런트 안내 문구를 같은 PR(`#488`)에 넣었다. 그 PR 리뷰 포인트에서 대기열 화면 쪽에서 다르게 보여야 하면 알려 달라고 팀에 의견을 요청했다.

## 핵심 메시지
AI가 결과적으로 맞았더라도 숫자로 닫았고, 실패한 실험이 다음 장치의 위치를 정했다.

## 예상 질문
- **회차마다 한 번씩 쟀는데 64를 확정할 수 있나?** 64와 128의 반복 측정은 아직 없다. 128을 거부한 근거가 반복 측정 차이(5%)라는 점을 같이 말한다.
