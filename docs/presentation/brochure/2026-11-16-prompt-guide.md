# 브로셔 작업을 AI에게 시키는 법 (프롬프트 컨설팅)

- 날짜: 2026-11-16
- 질문: "너였다면 너한테 어떻게 일을 시키겠어?"
- 짧은 답: **목표·독자·완료 기준을 먼저 고정하고, 사실 → 디자인 → 조립을 단계로 나누고, 단계마다 다른 에이전트가 냉철하게 심사하게 한다.** 한 번에 "예쁘게 다 만들어 줘"는 결과가 그럴듯해 보여도 숫자와 서사가 무너진다.

## 1. 좋은 지시의 일곱 가지 요소

| 요소 | 왜 필요한가 | 이번 브로셔에서 쓸 문장 예 |
|---|---|---|
| 목표와 독자 | 무엇을 "잘했다"로 볼지 정해진다 | "외부 심사위원이 3초 안에 '공정한 콘서트 예매, 숫자로 증명'을 읽게 한다" |
| 사실의 출처(정본) | 그럴듯한 숫자를 만들어 내는 것을 막는다 | "숫자는 `census/` 원장에 있는 것만 쓴다. 없으면 '확인 필요'로 남긴다" |
| 범위와 하지 말 것 | 다른 파일을 건드리거나 과장하는 것을 막는다 | "이 폴더 밖은 읽기만. 반올림·새 숫자·영문 문구 금지" |
| 산출물 계약 | 결과를 합치고 비교할 수 있다 | "표 열: id·주장·숫자·조건·근거 경로. 파일 하나에 쓴다" |
| 완료 기준 | 언제 멈출지 정한다 | "카드 크기(270×145)에서 헤드라인이 읽히고, 모든 숫자에 조건이 붙으면 끝" |
| 확인 지점 | 방향이 틀렸을 때 일찍 멈춘다 | "시안 2개를 보여 주고 고르게 한 뒤 다음 단계" |
| 심사 고리 | 만든 사람이 못 보는 빈틈을 찾는다 | "만든 에이전트와 다른 에이전트가 채점표로 심사하고, 점수 미달이면 고쳐 다시 심사" |

## 2. 역할 나누기 (모델별)

| 역할 | 모델 | 맡는 일 | 맡기지 않는 일 |
|---|---|---|---|
| 지휘(메인 세션) | Opus 5.5 | 결정 정리, 지시서 작성, 결과 합치기, 최종 책임 | 직접 그림 그리기 |
| 조사 | Sonnet 5.5 | 파일 전수 읽기, 사실 카드 만들기 | 해석·과장 |
| 그림 시안 | Fable 5.2와 Sonnet 5.5(같은 지시로 비교) | 디자인 규칙대로 SVG 그림 | 숫자 바꾸기 |
| **심사위원** | 만든 쪽과 다른 모델(그림은 Opus 5.5, 글은 Fable 5.2 등)로 새로 띄움 | 채점표로 냉정하게 점수와 문제 목록 | 직접 고치기(고치는 건 만든 쪽) |
| 사실 검수 | Sonnet 5.5 | 원문 대조, 배수 재계산 | 디자인 평가 |

심사위원을 만든 쪽과 다른 에이전트로 두는 이유: 같은 맥락에서 만든 에이전트는 자기 결과의 전제를 그대로 믿는다. 새 맥락의 심사위원에게는 **결과물과 원문만** 주고 작성자의 설명은 주지 않는다.

## 3. 심사위원 채점표 (모든 단계에 같이 씀)

| 기준 | 질문 | 만점 |
|---|---|---|
| 3초 이해 | 카드·이미지 크기에서 무슨 서비스이고 무엇이 강점인지 읽히나 | 5 |
| 숫자의 힘 | 개선이 "몇 배·몇 %·0건"으로 크게 보이나, 작은 숫자가 앞에 있지 않나 | 5 |
| 정직성 | 모든 숫자에 조건(부하·회수·장비)이 있고, 다른 조건끼리 잇지 않았나, 원문보다 강하지 않나 | 5 |
| 서사 | 고민 → 실패 → 측정 → 개선 → 남은 한계가 이어지나 | 5 |
| 차별성 | 같은 주제(10기 2조 SafeTicket, 8기 TIKITAKA)와 구별되나 | 5 |
| 완성도 | 글자 잘림·겹침, 색·글꼴 통일, 템플릿 안내문·내부 약어 잔존 | 5 |
| 심사 질문 대비 | 심사위원이 물을 질문 3개를 예상하고, 브로셔에 답의 근거가 있나 | 5 |

- 통과선: 모든 기준 4점 이상, 정직성은 5점. 미달이면 문제 목록을 만든 쪽에 넘겨 고치고 다시 심사(최대 3회).
- 심사위원 출력: 점수 표, 문제 표(심각한 순, 위치·지금·왜 문제·고칠 방향), "가장 먼저 고칠 3개".

## 4. 바로 쓸 수 있는 지시 견본

### 4-1. 전수조사(이미 돌리는 중)
```text
너는 브로셔 사실 원장을 만드는 조사 담당이다. 범위: <경로 목록>. 범위의 모든 파일을 연다(표본 금지).
산출물: docs/presentation/brochure/census/<영역>.md 하나. 표 열은 id | 서비스 | 주장 | 숫자(전 → 후) | 배수(계산식) | 조건 | 성격 | 근거(경로:줄) | 시각 자료 | 서사 장면.
숫자는 원문 그대로, 원문의 "계산값/추정/확인 못 함" 표시도 옮긴다. 모순은 행을 나눈다.
끝에 하이라이트 Top 15, 메모리 숫자, 서사 소재, 그림 목록, 못 읽은 파일을 쓴다. 다른 파일은 고치지 않는다. 한국어로 쓴다.
```

### 4-2. 그림 시안(모델 둘에 같은 문장)
```text
너는 브로셔 그림 담당이다. 만들 그림: <이름>(크기 <W×H>). 디자인 규칙: docs/presentation/brochure/design-kit.md를 그대로 따른다.
넣을 숫자와 조건(바꾸지 말 것): <원장 id와 값 그대로 붙여 넣기>. 근거 화면: <경로>.
목표: 갤러리 카드 크기(270×145)로 줄여도 큰 숫자와 헤드라인이 읽힌다. 핵심 요소는 가운데 띠 안.
금지: 숫자 반올림·새 숫자·영문 문구·브랜드 로고 흉내. SVG와 PNG(2배)를 <경로>에 쓰고, 카드 크기 미리보기도 함께 만든다.
끝나면 잘림·겹침이 없는지 스스로 열어 보고 보고한다. 한국어로 쓴다.
```

### 4-3. 심사위원
```text
너는 부트캠프 최종 발표회의 외부 심사위원이다. 현업 백엔드 시니어와 채용 담당의 눈으로, 냉정하게 본다. 칭찬은 필요 없다.
심사 대상: <파일·그림 경로>. 원문 근거: docs/presentation/brochure/census/*.md(사실 원장).
작성자의 설명은 주지 않는다. 결과물과 원장만 보고 판단한다.
채점표: docs/presentation/brochure/2026-11-16-prompt-guide.md 3절. 기준마다 점수와 근거.
출력: 점수 표, 문제 표(심각한 순: 위치 | 지금 | 왜 문제 | 고칠 방향), 가장 먼저 고칠 3개, 심사위원으로서 물을 질문 3개.
파일은 고치지 않는다. 한국어로 쓴다.
```

### 4-4. 사용자가 메인 세션에 줄 추가 지시 예
- "이번 단계 완료 기준은 ○○. 넘기 전에 심사 점수표를 보여 줘."
- "시안은 둘 다 카드 크기로 나란히 보여 주고, 각 시안의 심사 점수를 같이 붙여."
- "숫자를 새로 쓰면 원장 id를 괄호로 달아. id 없는 숫자는 쓰지 마."
- "막히거나 원장에 없는 숫자가 필요하면 멈추고 물어."

## 5. 피해야 할 지시
| 피할 것 | 왜 | 대신 |
|---|---|---|
| "최대한 멋지게, 알아서" | 기준이 없어 매번 다른 결과, 과장이 섞임 | 채점표와 완료 기준을 준다 |
| 만든 에이전트에게 스스로 검수시키기 | 자기 전제를 못 의심함 | 새 맥락의 심사위원 |
| 숫자를 지시문에 다시 타이핑 | 옮겨 적다 틀림 | 원장 id로 가리키고 값은 복사 |
| 한 번에 전 과정을 맡기기 | 중간에 틀어져도 끝까지 감 | 단계마다 확인 지점 |
