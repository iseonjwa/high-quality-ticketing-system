## 3. 서비스별 카드 묶음 (하위 페이지 소재)

각 묶음 순서: 썸네일(대표 1 + 보조 2) → 서사 타임라인 → 감수한 것·알려진 문제·한계 → 쓸 그림 → 예상 심사 질문 3개. 타임라인은 "가정 → 시도 → 측정 → 판단" 순서다. 날짜는 KST 기준 일자만 적었고 UTC 표기가 필요한 곳은 UTC로 적었다.

### 3-1. Gateway

**썸네일**
- 대표: **같은 서버로 제때 끝낸 요청 +30%**(굿풋 1,304 → 1,696/s, 성공 응답 p95 571 → 87ms는 작게. 각주: 같은 단계 성공률 89.04 → 85.17%, 상한 거절 1,678 → 8,715). 조건: 같은 날·같은 배포, 회차당 1회, 4 vCPU 서버 1대

**감수·문제·한계**: 최대 1초 낡은 값. Gateway 응답 캐시(ISE-285 2단계)는 `serverTime` 분리 합의 전이라 미적용. 효과 숫자 없음.
**쓸 그림**: 없음(신규: 요청 구성 막대 — 공연 상세 73.8%·순번 조회 7.2%·좌석 조회 4.1%·확정 조회 4.1%·선점 4.0%·입장 토큰 2.6%·진입 2.5%·결제 1.7%, `scale-comparison.md:38-48`).
**예상 질문**: (1) 가장 많은 요청을 캐시했는데 효과가 없나? → 미측정, 병목 순간엔 없었다는 점이 발견. (2) 1초 낡은 값 문제? → 판매 상태·서버 시각은 매 요청 계산. (3) 왜 늦게 발견했나? → AI가 짠 O1 시나리오가 진입을 흩었음(강민 회고).
