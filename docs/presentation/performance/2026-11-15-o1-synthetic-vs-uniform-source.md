# Synthetic 사용자 대 균일 사용자: 같은 서버에서 무엇이 달라졌나 (발표 소스, 2026-11-15)

ISE-264 본 측정 결과다. 해석과 판정은 [`synthetic-data.md`](../../design/infra/synthetic-data.md) 6절이 정본이고, 이 파일은 발표용 장면과 원자료 출력을 모은다. 숫자는 2026-11-15 배포 서버 측정 출력에서만 옮겼다.

- 조건: 배포 서버 `m7i.xlarge`(4 vCPU) main `e109c11c`, 측정 모드, Mock PG 승인 지연 300ms. 발생기 EC2 4 vCPU, k6 1.0.0, 코드 `88f14d86` + O1 결제 본문 `pgProvider: 'MOCK'` 한 줄(PR `#632`와 같은 줄). 사용자 3,000명, VU 300, 오픈 전 약 595초 + 뒤 900초, 회차마다 새 15,000석
- 실행: 균일 `o1-open-peak-20261115-094204`(회차 122), Synthetic `o1-open-peak-20261115-100830`(회차 123), A0 `a0-assignment-baseline-20261115-103557·103558·103600`(회차 124~126). 버린 실행: 회차 120(결제 400)
- 반복: O1은 각 1회. 반복 변동은 A0 3회(처리량 992~1,163건/초)로만 안다

## 장면 1. 같은 3,000명, 다른 결과

- 무엇을 증명하나: 사용자 행동만 바꿔도 같은 서버의 결과가 크게 달라진다. 균일 부하만으로 낸 숫자는 실제 오픈을 대표하지 못한다.

| 지표 | 균일 | Synthetic |
|---|---|---|
| 확정 사용자 | 1,973(65.8%) | 2,547(84.9%) |
| 선점 409 비율 | 48.1% | 11.7% |
| 선점 p95 | 192.4ms | 36.9ms |
| 확정 대기 p95 | 3.9s | 1.0s |
| `queue_enter` 초당 최대 | 353 | 2,792 |

- 발표자 메모: 균일은 모두 같은 순간 ANY 좌석을 노려 첫 1분 409가 1,906건(Synthetic 364건)이다. Synthetic은 등급·도착·결정 속도가 갈려 경쟁이 나뉜다(추정).

## 장면 2. LLM 예측 네 가지 중 셋은 맞고 하나는 보이지 않았다

| 예측 | 실제 | 판정 |
|---|---|---|
| 오픈 직후 진입이 더 몰린다 | `queue_enter` 초당 최대 2,792 대 353 | 맞음 |
| 409가 VIP에 몰린다 | VIP 19.5% 대 전체 11.7% | 맞음 |
| 5분 뒤 두 번째 파도 | 1분당 선점 201: 240~300초 30, 300~360초 27, 360~420초 28 | 파도 없음(조건 문구는 2분 합 55 > 30이라 맞음) |
| 오픈 전 상세 조회 정점이 높다 | 263 대 231 | 맞음 |

- 무엇을 증명하나: 미리 적은 판정 조건으로 예측을 검증했다. 조건 문구가 맞아도 구간 길이가 다르면 결론이 달라진다는 점도 그대로 보인다.

## 장면 3. 안전망 64가 막은 것

- 무엇을 증명하나: 모든 503은 Gateway 동시 처리 상한 64와 auth-redis bulkhead 거절이고, 서버 오류는 0이다. 건수가 지표와 정확히 맞는다.

| 실행 | k6 503 | 상한 거절 증가 | bulkhead 거절 |
|---|---|---|---|
| 균일 | 1,150 | 1,150 | 0 |
| Synthetic | 1,603 | 1,555 | 48(오픈 직후 1분) |
| A0 3회 | 1,599 | 1,598 | 1 |

- 발표자 메모: A0는 100 VU가 동시에 선점해 절반이 거절됐다(성공률 41~51%). A0 처리량 1,019건/초(대표값)는 상한이 걸린 값이다. 균일은 좌석 조회·선점에서 거절돼 바로 포기(`error` 291), Synthetic은 대기열 진입에서 거절돼 재시도로 흡수(`error` 8).
