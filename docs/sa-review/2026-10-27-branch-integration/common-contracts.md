## 응답·예외·HTTP·trace

사실: 준현·권우·효승 모두 성공 `status/message/data/traceId`, 실패 `status/code/message/errors/traceId` 구조를 제공한다. 준현은 클래스 수준 ALWAYS로 null 필드를 유지하며 실패 errors만 NON_NULL로 제외한다. 권우·효승은 errors를 NON_EMPTY로 제외한다. 따라서 일반 실패에서 errors가 없는 결과는 같지만 빈 검증 목록의 직렬화는 다르다. [준현 직렬화](https://github.com/iseonjwa/high-quality-ticketing-system/blob/45874b7904d98b667aad0737500aa3631bdda3e1/common-response/src/main/java/iseonjwa/common/response/FailureResponse.java#L7), [권우 직렬화](https://github.com/iseonjwa/high-quality-ticketing-system/blob/60994695c70fcb4e0c8c2ec11128fd7bb868de33/common/src/main/java/com/highquality/common/response/ErrorResponse.java#L12), [효승 직렬화](https://github.com/iseonjwa/high-quality-ticketing-system/blob/acb862788e80ec602837afee8954baa1be528c02/common-response/src/main/java/com/iseonjwa/common/response/ErrorResponse.java#L11).

사실: 권우·효승의 성공 record는 전역 Jackson null 제외 설정에 대한 ALWAYS 보호가 없다. 현재 서비스 설정에서 필드 누락이 발생하는지는 이 조사에서 재현하지 않았다. 준현의 성공 팩토리는 2xx/204를 검사하지만 record 생성자 직접 호출까지 제한하지는 않는다. 성공 DTO 팩토리 세 종류 모두 ResponseEntity HTTP 상태를 자동으로 설정하지 않는다. [준현 팩토리](https://github.com/iseonjwa/high-quality-ticketing-system/blob/45874b7904d98b667aad0737500aa3631bdda3e1/common-response/src/main/java/iseonjwa/common/response/SuccessResponse.java#L6), [권우 팩토리](https://github.com/iseonjwa/high-quality-ticketing-system/blob/60994695c70fcb4e0c8c2ec11128fd7bb868de33/common/src/main/java/com/highquality/common/response/ApiResponse.java#L8), [효승 팩토리](https://github.com/iseonjwa/high-quality-ticketing-system/blob/acb862788e80ec602837afee8954baa1be528c02/common-response/src/main/java/com/iseonjwa/common/response/SuccessResponse.java#L9).

사실: 준현은 MVC 부모 처리기의 상태·헤더를 보존하고 `/api/v1/`의 매핑 전 404/405만 별도 advice로 연결한다. 테스트 소스에 Allow 헤더 보존과 외부 컨트롤러 비개입 사례가 있다. 권우는 405 응답을 새로 만들며 예외의 Allow 헤더를 옮기지 않는다. 415 등의 별도 handler가 없는 MVC 예외는 코드상 Exception fallback의 500 대상이다. 이 마지막 경로는 런타임 재현하지 않았다. [상태·헤더 유지](https://github.com/iseonjwa/high-quality-ticketing-system/blob/45874b7904d98b667aad0737500aa3631bdda3e1/common-web/src/main/java/iseonjwa/common/web/CommonExceptionHandler.java#L55), [라우팅 범위](https://github.com/iseonjwa/high-quality-ticketing-system/blob/45874b7904d98b667aad0737500aa3631bdda3e1/common-web/src/main/java/iseonjwa/common/web/CommonRoutingExceptionHandler.java#L23), [Allow 테스트](https://github.com/iseonjwa/high-quality-ticketing-system/blob/45874b7904d98b667aad0737500aa3631bdda3e1/common-web/src/test/java/iseonjwa/common/web/CommonWebTest.java#L70), [권우 405·fallback](https://github.com/iseonjwa/high-quality-ticketing-system/blob/60994695c70fcb4e0c8c2ec11128fd7bb868de33/common/src/main/java/com/highquality/common/web/GlobalExceptionHandler.java#L57).

[효승 검증 처리](https://github.com/iseonjwa/high-quality-ticketing-system/blob/acb862788e80ec602837afee8954baa1be528c02/common-web/src/main/java/com/iseonjwa/common/web/GlobalExceptionHandler.java#L53), [검증 본문 상태](https://github.com/iseonjwa/high-quality-ticketing-system/blob/acb862788e80ec602837afee8954baa1be528c02/common-response/src/main/java/com/iseonjwa/common/response/ErrorResponse.java#L35), [준현 검증 처리](https://github.com/iseonjwa/high-quality-ticketing-system/blob/45874b7904d98b667aad0737500aa3631bdda3e1/common-web/src/main/java/iseonjwa/common/web/CommonExceptionHandler.java#L32).

[권우 MDC](https://github.com/iseonjwa/high-quality-ticketing-system/blob/60994695c70fcb4e0c8c2ec11128fd7bb868de33/common/src/main/java/com/highquality/common/response/TraceIds.java#L5), [준현 MDC](https://github.com/iseonjwa/high-quality-ticketing-system/blob/45874b7904d98b667aad0737500aa3631bdda3e1/common-web/src/main/java/iseonjwa/common/web/CommonExceptionHandler.java#L25), [효승 trace 주입](https://github.com/iseonjwa/high-quality-ticketing-system/blob/acb862788e80ec602837afee8954baa1be528c02/common-web/src/main/java/com/iseonjwa/common/web/TraceIdResponseAdvice.java#L30).

## 사용자 컨텍스트·역할·토큰 공통 API

사실: 준현 GatewayIdentityFilter는 두 헤더가 모두 없으면 통과하고, 헤더가 있으면 양수 Long ID와 USER/ADMIN 역할을 함께 검증한다. 검증 뒤 `currentUserId/currentUserRole` 속성으로 전달한다. 토큰 서명 검증 기능은 이 MVC 필터에 없다. RequireRole은 속성 누락 401, 역할 불일치 403, 메서드 선언 우선이다. 이 구성은 Gateway가 외부 사용자 헤더를 제거하고 내부 서비스 직접 접근을 막는 신뢰 경계와 함께 써야 한다. [신원 필터](https://github.com/iseonjwa/high-quality-ticketing-system/blob/45874b7904d98b667aad0737500aa3631bdda3e1/common-web/src/main/java/iseonjwa/common/web/GatewayIdentityFilter.java#L25), [역할 인터셉터](https://github.com/iseonjwa/high-quality-ticketing-system/blob/45874b7904d98b667aad0737500aa3631bdda3e1/common-web/src/main/java/iseonjwa/common/web/RequireRoleInterceptor.java#L16).

사실: 효승 HeaderAuditorAware는 원시 X-User-Id를 Long으로 바꾸고 잘못된 문자열이면 empty를 반환한다. 역할·양수 검증은 하지 않는다. 권우 common에는 이와 같은 사용자 컨텍스트·공통 인가 API가 없다. API 사용 비교는 공통 모듈 tree로 확인했다. [효승 감사 사용자 해석](https://github.com/iseonjwa/high-quality-ticketing-system/blob/acb862788e80ec602837afee8954baa1be528c02/common/src/main/java/com/iseonjwa/common/audit/HeaderAuditorAware.java#L20).

사실: 준현 TokenDecoders는 HS256, 32바이트 이상 키, issuer·만료·audience·토큰 종류·역할·양수 sub·jti/iat/exp 존재를 검증한다. access/refresh 키가 다르다는 검사는 이 공통 팩토리가 아니라 User의 JwtTokens 생성자에 있다. 공통 검증과 토큰 발급/세션 저장 정책을 구분해야 한다. 다른 네 브랜치의 공통 모듈에는 대응 토큰 API가 없다. [공통 JWT 검증](https://github.com/iseonjwa/high-quality-ticketing-system/blob/45874b7904d98b667aad0737500aa3631bdda3e1/common-auth/src/main/java/iseonjwa/common/auth/TokenDecoders.java#L24), [키 분리 검사](https://github.com/iseonjwa/high-quality-ticketing-system/blob/45874b7904d98b667aad0737500aa3631bdda3e1/user-service/src/main/java/iseonjwa/user/infrastructure/security/JwtTokens.java#L36).

추천: 사용자 컨텍스트·역할 인가·공통 토큰 decoder는 준현 구현을 기준으로 둔다. 감사 코드가 원시 HTTP 헤더를 다시 읽게 하지 않는다. 소유자/업무 권한은 각 서비스 Application 규칙이며 RequireRole만으로 대체하지 않는다.

## JPA 감사·논리 삭제·ID

사실: 준현·효승 모두 여섯 감사 컬럼과 Instant/Long을 제공하며 BaseEntity에 PK·version·전역 삭제 필터를 강제하지 않는다. 준현 User는 IDENTITY PK를 개별 선언한다. 권우 common에는 BaseEntity가 없다. ## 실행한 검증과 한계

- `git ls-tree -r --name-only <고정 SHA>`와 `git show <SHA>:<path>`, `git grep -n -i 'outbox\|processed_event' <다섯 SHA> -- '*src/main*'`로 공통 파일·선언·실행 코드 유무를 비교했다. current checkout으로 다른 브랜치 줄 번호를 대체하지 않았다.
- 권우 SHA를 `git archive`로 `/tmp/ise-common-kwonwoo.0dHwjg`에 풀어 현재 checkout을 이동하지 않고 검증했다. 원본 실행 권한 때문에 `./gradlew :common:compileJava :common:test --no-daemon`은 `permission denied`로 실패했다.
- 동일 archive에서 `bash gradlew :common:compileJava :common:test --no-daemon`을 실행했다. Java 21.0.12·Gradle 9.8.2, `BUILD SUCCESSFUL in 16s`, 6개 테스트·실패 0·오류 0·스킵 0을 XML로 확인했다. 로그는 `/tmp/ise-common-kwonwoo-test.log`, 보고서는 archive의 `common/build/reports/tests/test/index.html`이다.
- 위 테스트는 standalone MockMvc의 업무 예외·필드 검증·깨진 JSON·404·405·500이다. 성공 직렬화·실제 Gateway classpath/기동·415·Allow 헤더·JPA·분산 trace·전체 서비스 연동은 이 테스트로 증명하지 않았다. 권우 전체 build는 실행하지 않았다.
- 다른 브랜치의 언급한 테스트는 소스 검토 근거다. 이번 공통 모듈 검증에서 재실행한 결과는 아니다. 기존 Docker 컨테이너 pause/stop, 코드 수정, 병합, commit/push를 수행하지 않았다.
