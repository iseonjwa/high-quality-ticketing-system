## 표 읽는 법

- `테스트 경로`는 `모듈/클래스` 형식이다. 괄호 안의 `S1` 같은 값은 `LotteryScenarioTest` 안의 시나리오 번호다.
- `실행 환경`의 자동 테스트는 Gradle 또는 프론트 테스트, 로컬은 compose 스택, 서버는 공유 배포 서버다.
- 로컬이나 서버에서 실행할 수 있는 행은 각 영역의 "직접 실행할 때" 표에 사전 조건과 절차가 있다. 자동 테스트만 있는 행은 테스트가 곧 절차다.
- `서버 데이터 변경`이 `있음`인 행은 공유 서버 데이터를 바꾼다. 팀에 공지한 뒤 실행한다. `서버 실행 안 함`은 서버에서 돌리지 않는다는 뜻이다.
- 기대 결과 끝에 `(근거: 추정)`이나 `(근거: 설계 문서)`가 있으면 코드로 확인하지 않은 값이다. 표시가 없으면 테스트 메서드 이름이나 코드에서 가져왔다.

## 이 목록의 한계

- 전수 목록이 아니다. 한 행은 테스트 메서드 하나가 아니라 검증할 동작 하나이고, 빠진 시나리오가 있을 수 있다.
- 227건은 테스트 메서드 이름에서 가져왔고 본문은 확인하지 않았다.
- 결제 테스트는 일부 클래스의 이름만, Mock PG는 일부 클래스의 이름만 읽었다. 프론트는 12개 파일의 앞부분만 읽었다.
- `실행 환경`, `서버 데이터 변경`, `우선순위`는 작성자 판단이다. 담당 영역 팀원이 고친다.
- 표의 Java 테스트 클래스 140개와 프론트·스크립트 경로는 작업 트리에 파일이 있는지 스크립트로 확인했다. 테스트를 실행하지는 않았다.

## 고치는 법

1. 시나리오를 더할 때는 해당 파일에 다음 번호로 추가한다. ID는 재사용하지 않는다.
2. 기능이 없어지면 행을 지우지 않고 시나리오 앞에 상태를 적는다.
3. 구현되면 `[미구현]`을 지우고 테스트 경로를 적는다.
4. 실행 결과는 표에 쓰지 않고 [`runs/`](runs/)에 쓴다. 표에 쓰면 리허설마다 수백 행이 바뀌어 PR을 검토할 수 없다.
