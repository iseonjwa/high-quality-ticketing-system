너는 대규모 티켓 예매 서비스의 부하 테스트 데이터를 설계하는 엔지니어다. 아래 시나리오와 시스템 조건을 읽고, 콘서트 티켓 오픈 순간에 몰리는 가상 사용자(Synthetic Data)의 행동 분포를 만들어 줘. 결과는 k6 부하 테스트가 사용자 한 명당 CSV 한 행으로 읽는다.

# 1. 우리가 정한 트래픽 시나리오 (팀 설계)

- 서비스: 콘서트 예매 서버(MSA). 공연장은 KSPO DOME 한 곳, 회차 하나에 15,000석이다.
- 가장 위험한 시간: 평일 오후 8시 티켓 오픈 정각. 오픈 10분 전부터 공연 상세 화면을 새로고침하며 기다리고, 오픈 직후 몇 초 안에 대기열 진입이 몰린다. 오픈 뒤 몇 분 동안은 대기열에서 순번을 확인하다가 입장한 사람부터 좌석을 고른다.
- 사용자 흐름: 공연 상세 조회(새로고침) → 대기열 진입 → 순번 폴링(서버가 알려 준 간격) → 입장 토큰 받기 → 좌석 배치도 조회 → 좌석 선점(한 번에 1~4석) → 결제 → 예매 확정 확인.
  - 이미 다른 사람이 잡은 좌석이면 선점이 409로 실패하고, 대기열로 돌아가지 않고 좌석만 다시 고른다.
  - 선점은 5분 유지된다. 그 안에 결제하지 않으면 좌석이 풀린다.
- 우리가 본 병목(배포 서버 측정): 좌석 배치도 조회(응답 약 830KB), 인기 구역에 몰린 선점 경쟁(409와 재시도), 오픈 직후 대기열 진입 순간 몰림, Gateway 인증 경로.
- 우리가 이미 정한 사용자 상(페르소나 일부): 퇴근 후 PC로 오픈을 기다리는 직장인 팬, 친구와 2매를 잡으려는 사람. 새로고침 연타와 여러 기기 접속도 실제로 일어난다고 본다. 매크로(자동화 프로그램) 사용자는 이번 범위에 넣지 않는다.

# 2. 시스템 조건 (값은 바꾸지 말 것)

- 좌석: 25구역(A~Y) × 20열 × 30번. A~E는 VIP 3,000석, F~O는 R 6,000석, P~Y는 S 6,000석. 무대에 가까운 구역일수록 등급이 높다.
- 1인 최대 4매. 같은 계정은 대기열에 한 자리만 갖는다(진입을 여러 번 눌러도 순번은 하나).
- 대기열 입장 속도는 초당 50명이다. 사용자가 3,000명이면 대기열이 비는 데 약 1분이 걸린다.
- 측정 시간 창: 오픈 10분 전부터 오픈 10분 뒤까지.

# 3. 만들 것

## 3-1. 페르소나 분포 (JSON)

아래 형식을 정확히 지킨 JSON 하나를 ```json 블록으로 줘. 필드 이름과 허용 값을 바꾸지 말 것.

```
{
  "version": 1,
  "personas": [
    {
      "code": "영문 소문자와 밑줄",
      "name_ko": "한국어 이름(짧게)",
      "share": 0.0~1.0 (모든 페르소나의 합이 정확히 1.0),
      "description": "어떤 사람이고 어떻게 움직이는지 한두 문장",
      "fields": {
        "arrive_s": 분포,          // 오픈 시각 기준으로 처음 접속하는 시각(초). 음수는 오픈 전. 범위 -600 ~ 600
        "refresh_s": 분포,         // 오픈 전 상세 새로고침 간격(초). 0은 새로고침하지 않음. 0 또는 3 ~ 60
        "enter_delay_ms": 분포,    // 진입 버튼을 누르기까지 걸린 시간(ms). 오픈 전 접속자는 오픈 시각부터, 오픈 뒤 접속자는 접속 시각부터 잰다. 0 ~ 60000
        "enter_clicks": 분포,      // 진입 요청을 보내는 횟수. 1은 한 번, 2 이상은 연타, 0은 끝내 진입하지 않고 상세만 보다 떠남. 0 ~ 5
        "seats": 분포,             // 한 번에 선점할 좌석 수. 1 ~ 4
        "zone": 분포,              // 노리는 등급. "VIP" | "R" | "S" | "ANY"(아무 곳이나)
        "think_ms": 분포,          // 좌석 배치도를 보고 고르기까지 걸린 시간(ms). 300 ~ 30000
        "max_retry": 분포,         // 409(이미 선택된 좌석) 뒤 좌석을 다시 고르는 최대 횟수. 0 ~ 5
        "on_conflict": 분포,       // 409 뒤 다시 고를 때. "same_zone"(같은 등급에서 다시) | "any_zone"(아무 곳이나) | "give_up"(바로 포기)
        "queue_patience_s": 분포,  // 대기열에서 기다리다 창을 닫고 떠나기까지 참는 시간(초). 0은 끝까지 기다림. 0 또는 30 ~ 900
        "abandon_after_hold": 분포,// 선점에 성공한 뒤 결제하지 않고 떠나는지. 0 또는 1
        "pay_delay_s": 분포        // 선점 성공부터 결제 버튼까지(초). 3 ~ 280
      },
      "basis": "이 페르소나와 비율을 이렇게 잡은 이유. 추정이면 추정이라고 쓴다"
    }
  ],
  "assumptions": ["전체에 걸친 가정. 추정과 근거를 나눠서"]
}
```

분포는 아래 여섯 가지 중 하나로 쓴다.
- `{"dist": "const", "value": 값}`
- `{"dist": "uniform", "min": 하한, "max": 상한}`
- `{"dist": "normal", "mean": 평균, "sd": 표준편차, "min": 하한, "max": 상한}` (범위 밖은 잘라 냄)
- `{"dist": "exponential", "mean": 평균, "min": 하한, "max": 상한}` (min을 더한 지수 분포, max에서 자름)
- `{"dist": "choice", "values": [값, ...], "weights": [가중치, ...]}` (가중치 합은 1.0)
- `{"dist": "bernoulli", "p": 1이 나올 확률}`

정수 필드(`enter_clicks`, `seats`, `max_retry`, `abandon_after_hold`)는 `choice`나 `bernoulli`나 `const`로 준다.

## 3-2. 표본 CSV

위 분포를 따르는 사용자 40명의 CSV를 ```csv 블록으로 줘. 이름·전화번호 같은 개인정보 열은 넣지 않는다. 열 순서는 아래와 같다.

```
user_no,persona,arrive_s,refresh_s,enter_delay_ms,enter_clicks,seats,zone,think_ms,max_retry,on_conflict,queue_patience_s,abandon_after_hold,pay_delay_s
```

- `user_no`는 0부터 39까지.
- 페르소나 비율이 3-1의 share와 대략 맞게(40명 기준 반올림).
- 모든 값이 3-1의 허용 범위 안에 있게.

## 3-3. 확인할 점

마지막에 이 데이터로 부하 테스트를 하면 "모든 사용자가 같은 규칙의 균일 난수로 움직이는 부하"와 비교해 어떤 차이가 드러날 것으로 보는지 3~5줄로 써 줘. 예측이므로 단정하지 말 것.

규칙: 실제 서비스의 공개 통계를 안다고 꾸며 내지 말 것. 근거가 없는 숫자는 추정이라고 밝힐 것. 답은 한국어로.
